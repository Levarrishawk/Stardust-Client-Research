## Observations and findings

Confirmed from actual host source (external historical reference) and actual execution: Configure is accepted once on historical implementation path (omitted) main thread, requires a live exact same-viewport host parent and finite maximumT0..1e9, retains caller references and performs no clock read/query/target admission. The host's parent/viewport are validated by the host; the caller selects the adapter for that viewport, and actual child camera/marker/controller admission occurs on dispatch.

Confirmed by Viewport.PushInput: real pressed-left events hit, retarget, miss while retaining the prior target, and use the caller's10000-microsecond clock after one actual controller/driver tick. Released-left, right and motion events reach a later actual unhandled-input observer without clock/attempt/query/selection changes. Successfully admitted events call actual SetInputAsHandled and suppress that observer. Main scenario counts: five accepted/handled events, four hits and one miss.

Observation: root-window `IsInputHandled()` returned true after PushInput even for ignored events. Interpretation: a post-call root flag is not a suitable event-lifetime propagation assertion in this environment. The final test therefore uses an actual later `_UnhandledInput` observer and verifies its in-callback flag remains clear for ignored/failing events. Confirmed by both headless and GPU executions; no fabricated invocation replaces the viewport route.

Confirmed: duplicate/closed/detached configuration, invalid maximumT, off-thread Dispatch/Close, invalid clock, throwing clock reader, pre-cancellation and caller-callback cancellation reject at their documented boundaries. A clock reader catching nested Dispatch, Configure or Close cannot erase the poison flag; outer routing faults before another child attempt/query. Caller counter/token side effects remain observable external prefixes. Queued parent rejection precedes clock/child effects; actual parent teardown invokes terminal ExitTree closure.

Confirmed by a real marker VisibilityChanged callback: nested host Close is caught after child processing begins. The actual child completes a new pick and new target. The host faults after child return, keeps accepted/handled counts at their prior values and retains the exact completed child result with the actual target. This is a later completed-child prefix, distinct from clock-phase prevention. No adapter disposal, target rollback or marker rollback occurs.

Confirmed: actual event errors produce a bounded LastFailure and disable further unhandled-input processing while remaining unconsumed. Direct selected routing failures propagate. Diagnostics preserve exact existing child failure/result references; they do not invent child failure receipts for admission/clock errors. Close drops callback/borrower/latest-result references only. Adapter/picker/controller target and marker survive. Parent Free and removal inside a clock callback close the host; a closed host cannot reacquire a result reference. Caller Free and subsequent borrower-owner cleanup drain the staged scene.
