# Playback conflict arbitration refinement (block 3 of 3)

`0x0139AD30` is the admission gate after combat playback instance construction. Its true `param_2` route, or a true manager-global flag from `0x0040AA40`, appends directly through `0x00401C90`; null input instead emits a warning and returns false. The meaning of the caller's flag remains partly open.

For normal arbitration, `0x0139AE60` walks the new instance's actor slots (`0x004079E0`: 8-byte slot stride), keeps only slots accepted by `0x00407A70`, and stores their actor pointers (`0x004079F0`). `0x00407A70` accepts mode 1 if actor non-null, and mode 2 only when a further `0x00408080` lookup succeeds with nonnegative result; other modes are false. `0x0139AF80` walks active instances, tests their marked non-null actor pointers against the new set, and gathers conflicting active playback instances. These comparisons are pointer identity in the original x86 process, not network object-ID comparisons.

If there are conflicts, `0x0139B160` finds the **maximum** integer priority at instance offset `+0x68` among them. In `0x0139AD30`, the new instance loses if its priority is lower. Equal priority invokes `FUN_00B59EF0() % 0x65`; values greater than `0x32` reject new, so under a uniform 0..100 result the branch would reject on 50 of 101 outcomes (conditional interpretation, not measured probability). Otherwise all gathered conflicting active instances are removed via `0x00401D90`, and the new one is admitted via `0x00401C90`. The loser is destroyed/freed via `0x00407620`/`0x00407560`.

This resolves priority direction and the source of conflicts. Open: semantic names of actor-slot modes 1/2; who sets the `+0x68` priority; whether `0x00408080`'s mode-2 check represents actor activity, possession, or another state; PRNG distribution; and all caller policies for bypass flag. A replacement can implement this only after those choices are specified by evidence and regression examples. Provisional name `0x0139AD30` `admit_playback_with_actor_conflict_priority`.
