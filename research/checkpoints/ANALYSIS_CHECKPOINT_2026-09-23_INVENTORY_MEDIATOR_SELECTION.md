# Inventory mediator selection and activation (overnight block 23)

`Stardust.exe` read-only Ghidra evidence: primary `SwgCuiInventory` mediator vtable `0x015F03C0`, constructor `0x00C874E0`, functions `0x00C87B30`, `0x00C87D50`, `0x00C87ED0`, `0x00C87FA0`, `0x00C889F0`. The broader class and base-mediator contracts were recorded previously; this checkpoint adds a bounded action path, not a full inventory UI reconstruction.

`0x00C87B30` activates inventory-specific state: it enables the container view, conditionally configures the equipment view and current-player target, creates an `OwnedTransceiver< pair<int,ClientObject*> const&, SwgCuiInventory, CuiContainerSelectionChanged::Type>` listener, stores callback `0x00C889F0`, and registers it. The listener receives a selection pair and, when the owning mediator's `+0xAC` field is nonzero, forwards the selected `ClientObject*` (pair `+4`) to `0x00E72C60`. This is local model/view propagation, not an observed network packet send.

`0x00C87D50` is the paired deactivation path: it disables the container view, optionally emits a message via `game_network_send_VA_00462670` when flag `+0xA8` is set, resets an inventory helper, locates the same owned transceiver by RTTI, mediator pointer, callback address and source, then destroys/erases it. Subsequent block 25 identifies the conditional message as `NewbieTutorialResponse("closeInventory")`; see its dedicated checkpoint.

`0x00C87ED0` handles two bound UI controls at `+0x0C` and `+0x10`, reads a widget bit `0x800` and toggles distinct model/view paths. `0x00C87FA0` takes a target ID and context, checks player/nearby candidate state and target admissibility before calling `0x00E808C0` to update the attached container target. Its special `0x4001` template-type branch installs a range limit of `0x42000000` (32.0f) through the base mediator, tying target selection to the previously documented automatic-distance closure behavior. The exact meaning of `0x4001` is not yet established.

Replacement boundary: authoritative container/equipment data comes from the object model and container-selection events; the mediator owns temporary subscriptions, selection filtering, focus and range closure. It must unsubscribe on deactivation. This block does **not** establish a server-visible inventory action, item transfer packet, or complete drag/drop semantics.

Confidence: **confirmed** for transceiver type, registration/removal, callback forwarding, conditional send call and 32.0f range constant; **strongly inferred** for activation/deactivation roles from paired state changes; **unknown** for special template-type semantics and tutorial-trigger reset policy.
