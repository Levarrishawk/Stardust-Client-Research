# BC6H HDR checkpoint — 2026-09-30

## Question and stop

Can typed signed/unsigned BC6H DDS expose owned HDR values and match an independent decoder without an RGBA8 conversion? Stop after all fourteen modes, reserved modes, clipped edges, mip chains, malformed/budget fixtures and actual GPU upload/readback.

## Inputs and tools

Standards-only synthetic DDS fixtures generated by `generate_bc6h_fixtures.py`, seed 20260930. No original assets or executable addresses are needed. Pinned BCnEncoder.Net 2.3.0 and existing lock files/notices are unchanged. Godot 4.7.2 supplies an independent bcdec implementation through Image.Decompress. Input SHA-256 identities are printed per fixture by producer and verifier. No encoder from either decoder library creates the fixture blocks.

Primary references: [Microsoft BC6H specification](https://learn.microsoft.com/en-us/windows/win32/direct3d11/bc6h-format) defines modes, signedness, interpolation and reserved output; [Godot 4.7.2 bcdec adapter](https://github.com/godotengine/godot/blob/4.7.2-stable/modules/bcdec/image_decompress_bcdec.cpp) selects signed/unsigned BC6H and outputs RGBH. These establish standard extension behavior, not original Stardust acceptance.

## Result and confidence

**Confirmed implementation:** `DdsHdrDecoder` accepts only typed DXGI 95/96 single 2D surfaces. It validates all source/mip/aggregate extents before output allocation and passes exact sixteen-byte blocks to the pinned managed decoder. Output is owned little-endian IEEE binary16 RGB with top-to-bottom rows. There is no alpha channel, tone mapping, gamma conversion or RGBA8 clamping. Valid alpha metadata is retained separately; it does not synthesize an alpha plane. The existing RGBA8 decoder points callers to this separate HDR entry point.

**Confirmed independent agreement:** forty fixtures and 264 mip levels compare bit for bit against Godot's bcdec half output. All fourteen valid modes, 32 partitions for each two-region mode, four reserved modes, unsigned/signed typing, complete nine-mip chains, one-pixel and 3x5 clipping pass. The measured corpus contains 29,832 negative components and 45,349 positive components above one. Reserved blocks are zero RGB by specification. Independent direct endpoint constant fixtures assert half bits 3E0F, 3E1F and 805D, including negative and HDR values.

**Confirmed GPU boundary:** actual OpenGL ImageTexture RGBH upload/readback passes for all forty files, retaining every half byte and mip. Headless independently decodes without a renderer. Native fixtures cover every truncated prefix, wrong dimensions/headers/surface/type/alpha, extra bytes and input/decoded limits. Partial CPU mip chains are allowed; GPU tests require one mip or a complete chain.

## Limits and compatibility consequence

This is a standards extension. No claim is made that the baseline executable consumes DX10 BC6H. The static material bundle remains RGBA8-based and rejects HDR textures until the material's color/data interpretation and HDR cache/upload path are deliberately integrated. Typeless BC6H, arrays, cubes and volumes remain unsupported. Signed negative infinity is representable according to the specification and is not deliberately clamped by the half output; this specific extreme is not covered by the current fixture set. The forty-file measured set has no negative-zero or negative-infinity components. Full HDR scene presentation/tone mapping is a separate contract.
