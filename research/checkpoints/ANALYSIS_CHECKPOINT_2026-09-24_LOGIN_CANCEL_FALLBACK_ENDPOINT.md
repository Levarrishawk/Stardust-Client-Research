# Login Cancel and unindexed endpoint fallback

## Evidence and correction

This extends the [LoginScreen-to-connection checkpoint](ANALYSIS_CHECKPOINT_2026-09-24_LOGIN_SCREEN_UI_TO_CONNECTION.md) using read-only static inspection of the original `C:\Stardust-DEV\Stardust.exe`. It does **not** establish a successful or failed live connection. Decompiled output is pseudocode.

`SwgCuiLoginScreen` button callback `0x00C8D460` has a distinct Cancel branch: hide/deactivate the mediator via `0x009C0BA0`, then invoke `0x00881450`. The latter is a shared CuiManager helper, also called during CuiManager removal and from AvatarSelection. When its manager pointer is present and the active flag is clear, it sets `DAT_01926137=1`, invokes `0x00AB5900`, and passes zero to `0x00411030` and `0x0040F360`. The reciprocal `0x00881420` clears the flag and calls companion helpers. **Correction:** this evidence does not prove process exit or network disconnect from the LoginScreen Cancel button. Earlier wording calling it simply a close/exit path was too broad. Whether the surrounding scene chooses an exit prompt or another screen remains unresolved.

The Finish path `0x00C8D5D0` enumerates indexed `[ClientGame] loginServerAddress%i` / `loginServerPort%i` candidates. If none have a nonzero U16 port, it calls `0x00502E10` (address-string getter) and `0x00502E20` (U16 port getter) before `0x00462290` connection creation. Those getters read globals populated at `config_client_game_install_VA_00503600` from **unindexed** `[ClientGame] loginServerAddress` and `loginServerPort`. The executable's defaults are literal `localhost` and integer `0xADA5` (**44453**). This is a real code fallback, not a guessed endpoint. The installed configuration's indexed live host remains the selected candidate in the ordinary configured case; no live host was contacted in this work.

The original LoginScreen receiver `0x00C8D9E0` already showed opened/closed/token and message-box events. This follow-up confirms that on a close event with pending state it can close the modal and re-enable a bound control, but does not recover transport reason codes or complete localized retry policy. The `LoginClientToken` comparison is present, yet no separate state change is visible in that receiver branch; the login manager may process it elsewhere.

**Confirmed:** Cancel's two direct calls and shared helper flag changes; fallback getters, unindexed config keys and defaults; modal/control changes on connection close. **Strongly inferred:** `0x00881450` switches CuiManager/UI input mode rather than being a process-quit primitive. **Unknown:** post-Cancel screen/exit policy, authentication failure diagnostics, and whether a network connection exists at Cancel time. No new opcode or whole-client percentage is claimed.
