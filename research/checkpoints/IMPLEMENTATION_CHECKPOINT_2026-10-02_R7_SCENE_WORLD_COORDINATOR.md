## Observations, conclusions, consequences

- Confirmed implementation behavior: an externally tagged generation owns staged actual APPLICATION bytes; static message validation occurs before staging. Caller barrier replay applies create/end/contain/opaque baseline/delta in arrival order. Only complete successful replay releases exact CmdSceneReady. Any malformed message, unknown opcode/CRC, conflicting create, missing parent, or exhausted budget retires the world and cancels current jobs. Consequence: callers have a precise atomic readiness boundary and must recover the scene after later load failure.
- Confirmed implementation behavior: no resource load starts for pending-baselines objects or before the barrier. Latest finalized registry revision owns the queued request. Publications require coordinator generation, initializer attempt, registry handle, and finalized phase; queued restart immediately invalidates prior publication. Consequence: consumers must use coordinator.IsCurrent, not just object id or registry handle.
- Confirmed implementation behavior: one persistent initializer bounds cancelled-but-unfinished jobs across scene replacement. A completion frees capacity only after observation. Late stale/destroyed faults are observed and retired without harming the active generation. A mixed current success/fault batch fails without exposing its successful member. Close clears world immediately and DrainCompletion accounts for unfinished cancellation. Consequence: cancellation cannot be used to bypass job limits.
- Confirmed byte boundary, inherited from accepted codecs and independently checked: APPLICATION replication header 23, minimum 25; numeric CREO tag 0x4352454F has LE bytes 4F455243. The proof stores count 99 and opaque 7F00FF only as synthetic bookkeeping, never as valid CREO field schema. Consequence: no replication semantics or coverage increment is claimed.
- Confirmed local proof: existing SoeClientTransport handles reordered peer create/start, duplicate suppression, corrupt CRC rejection, exact select/ready/retry wire, ACK and server-ready. One original creature resource job performs 37 distinct source reads / 4,683,848 bytes, closes archives, publishes once, and is invalidated by destroy. An independent effective-overlay audit checks all hashes/sizes. Consequence: the bounded native integration works with the pinned resource closure; original readiness, terrain and parent scaling remain unknown.
- Modern policy: each create rejects non-CreatureDetail0 recipes before registry mutation/load. The starting catalog rejects invalid enum 1 at construction; the test records that guard without depending on unfinished Assets code. A later catalog accepting StaticAppearance may be mixed; unsupported static create must fail the generation while supported creature create remains accepted. This is a deliberate coordinator restriction, not recovered client behavior.
