# Analysis checkpoint — CKAT time advance and completion boundary

Target: verified `Stardust.exe` compressed-animation runtime vtable; Ghidra pseudocode was checked against the timed-message call's disassembly.

Runtime method `0x00822C40` advances an elapsed-time accumulator by the caller's delta, retains the preceding frame position at `+0x14`, and computes the current frame position at `+0x10` using the template frame rate. It caps the current frame at the INFO-declared end frame (`+0x28`) and returns an overrun/remainder to the caller when elapsed time passes the clip duration (`+0x1C`). The duration fields are established in `0x00822E70` from frame rate and end-frame count. **CKAT does not itself loop the frame counter in this method**; higher-level track/animation ownership handles completion, repeat or replacement. `0x00822D40` asks the template's selected root-motion routine for a delta between previous and current frame positions.

The message virtual `0x00822F30` passes those preceding/current frame positions, converted to integers, into the half-open template collector. This makes start/end delivery a material edge: 1,517 deployed events are authored at the declared end frame, while the ordinary current-frame value is capped at that same end frame. This analysis does **not** claim those events are never delivered, because a higher-level completion call, integer-conversion rounding or a separate endpoint path could intervene. A focused controller-level trace or differential playback fixture is required before specifying exactly-once loop/completion delivery.

Evidence: runtime CKAT vtable `0x015E5DC4`, pseudocode `0x00822C40`, `0x00822E70`, `0x00822D40`, `0x00822F30`; disassembly `0x00822F30`–`0x00822FAB` and collector bound check `0x008245D0`–`0x00824662`; full-corpus endpoint audit. Confidence: confirmed for ordinary advance/clamp/remainder and previous/current-root-motion inputs; unknown for end-frame event fate under outer track control.
