# Quest Journal screen: local-player events to category/tree/description

## Scope

The prior [Quest Journal Manager](ANALYSIS_CHECKPOINT_2026-09-21_QUEST_JOURNAL_MANAGER.md) block established the original `datatables/player/quests.iff` hierarchy, replicated `PlayerObject` state, counter/timer overlays, and a `0x440/0x441/0x444` server/controller mismatch. This block traces the separate `SwgCuiQuestJournal` screen that consumes those sources; it does **not** re-count the manager codec or resolve the mismatch. Source is original `C:\Stardust-DEV\Stardust.exe`, with pseudocode treated as reconstruction.

RTTI gives callback and mediator vtables `0x015F260C` and `0x015F2690`. Constructor `0x00DB3B10` binds `checkShowMission`, `descQuest`, two counter samples, `listCategories`, `treeQuests`, `buttonOK`, and `descriptionComp`. It owns event transceivers for `QuestJournalManager::CountersChanged` and `TimersChanged`; activation `0x00DB4080` also attaches local-player `ActiveQuestsChanged`, `CompletedQuestsChanged`, `QuestsChanged`, and `CreatureObject::PlayerSetup`. Deactivation `0x00DB4150` removes those player subscriptions by RTTI/callback identity and disables the screen-related UI state.

The four player event wrappers at `0x00DB4360/4380/43A0/43C0` compare the event's object to the current local creature/player before calling common refresh `0x00DB43E0`. That refresh rebuilds the model and selected presentation: category/tree work at `0x00DB4A70` obtains definitions through QuestJournalManager helpers and applies the `checkShowMission` state, then `0x00DB4410` updates description and dynamic details for the selected quest/task. Category selection triggers category/tree plus description refresh; tree selection triggers description refresh only, through callback `0x00DB5550`. The OK control closes/hides the mediator through `0x00DB5590`. Counter/timer transceivers also mark the view for refresh; exact presentation order of those overlay lines is not fully reconstructed here.

This is a **view over immutable original-asset definitions plus replicated/local overlays**, not a request/response protocol initiated by the screen. No direct network send was observed in the inspected constructor, activation, selection, or refresh methods. The current server's counter/timer ID mismatch therefore cannot be repaired by just rebuilding the UI; it must be handled in a versioned protocol compatibility profile or server change.

**Confirmed:** RTTI, bound controls, event names/subscription lifetime, local-player identity gates, category/tree/description call order and no direct send in inspected methods. **Strongly inferred:** `checkShowMission` filters quest/mission visibility based on boolean passed into manager queries. **Unknown:** every category formatting rule, precise counter/timer display order and malformed-quest handling in the UI. No new opcode or whole-client percentage is claimed.
