# Analysis checkpoint — inventory container UI navigation and provider boundary

Question A09 / W10+W04. This follows the previously mapped `CuiInventoryManager` open/close protocol and paperdoll transfer path; it does not re-count either. Target is verified original `C:\Stardust-DEV\Stardust.exe`; decompiled text is reconstructed pseudocode.

`SwgCuiInventoryContainer` RTTI has vtables `0x015F3DCC/0x015F3E50`. Constructor `0x00E7EFB0` creates/retains a container provider and child icon/details controls, binds label, `buttonView`, `buttonUp`, capacity bars/text, icons, details and money, plus typed local list-reset/selection events. Activate/deactivate methods `0x00E7FB50/0x00E7FC50` register and suspend the relevant local views and provider. Update `0x00E80C50` obtains provider total/current/limit volume, guards zero/negative totals, computes fill ratios and refreshes capacity presentation; it does not create a separate authoritative inventory count.

The UI callback `0x00E80020` distinguishes two bound buttons. `buttonUp` resolves a valid containing/parent object through `0x00E80190`; if present it calls the already mapped `CuiInventoryManager` open request `0x008D9AF0`, then calls the provider navigation method through `0x00E808C0`. Thus upward navigation is not just a local breadcrumb change: when connected, the open service may enqueue `openContainer` and awaits the server's `OpenedContainerMessage` per the earlier manager checkpoint. `buttonView` switches the icon/detail presentation mode via `0x00E7FF00`, with availability/visibility gates; it does not send a packet. The provider enumerates objects at `0x00E809F0`, and `0x00E803C0` reconciles visible rows/labels when that list changes.

This class is a provider-backed presentation/navigation mediator over authoritative containment, not the owner of equip/unequip command semantics. The complete gesture-level drag/drop path belongs to the separate `CuiWidget3dPaperdoll` and transfer-service checkpoints. Remaining work includes a bounded trace of non-paperdoll item drag/drop gestures and how a failed open/transfer rolls back UI state.

A bounded child-view check confirms the separation: `SwgCuiInventoryContainerIcons` constructor `0x00FECD60` binds a volume display, activation `0x00FECFF0` subscribes to its parent's `ListReset` and container-selection events, and deactivation `0x00FED0A0` removes those exact subscriptions. Its inspected mediator callbacks refresh/localize the icon view; they do not introduce another server message. This is a refinement of the same navigation/presentation block, not a second UI breadth count.
