# Analysis checkpoint — packed-quaternion quantizer table formula

Target: verified `Stardust.exe`, instruction-level trace plus representative original CKAT samples. Ghidra pseudocode was cross-checked against disassembly because the initializer's index register is easy to misread.

`0x00AC0900` clears 255 eight-byte selector records at `0x01945BB8`; the remaining record is in zero-initialized memory. SharedMath install `0x00AB5940` calls `0x00AC0E20`, which iterates seven static range descriptors at `0x018AF640 + 28*i`, `i=0..6`. Their selector starts are `(254,252,248,240,224,192,128)` and counts are `(1,2,4,8,16,32,64)`. For range `i`, define `n=2^i` and `width=2/(n+1)`. For `j=0..n-1`, the initialized selector is `start[i] | j`, with eight-byte record `{base=(j+1)*width-1, rangeIndex=i}`. This fills exactly **128..254** (127 selectors); the default records **0..127 and 255** remain `{base=0, rangeIndex=0}`. The range descriptors and float constants are present in the executable; the initializer also computes 11-bit encode/decode scales `1023/width` and `width/1023`, and 10-bit scales `511/width` and `width/511`.

For each packed U32, the first and second components use 11-bit sign/magnitude fields and their selectors' bases plus/minus `magnitude * width/1023`; the third uses a 10-bit field and `width/511`. The fourth component is `sqrt(1-sum(firstThree²))`. The animated evaluator interpolates the decoded quaternions along a dot-product-selected path. A first sample of all **127,315** SROT records plus the first key of each of **171,000** AROT channels found six component sums above `1.00001`; the later exhaustive audit found **248** such values among all **12,059,807** AROT keys and the SROT values, with a maximum near `1.0002971`. This warns against inventing a silent clamp policy: the original decoder executes a square root without a visible clamp in the traced path, and exact x87/float behavior for these rare inputs requires a differential fixture.

Important audit correction: SROT disk order is three selector bytes *before* the packed U32, while its expanded runtime record places U32 first. A first-pass audit that read the bytes from the wrong side of the word falsely reported all-256 selector coverage; the corrected deployed coverage is 128..254 for AROT and 75 distinct values from that range for SROT.

Evidence: disassembly `0x00AC0900`–`0x00AC093F`, `0x00AC0D90`–`0x00AC0E12`, `0x00AC0E20`–`0x00AC0ED5`; pseudocode `0x00AC0B30`, `0x00AC0AD0`, `0x00AC0BA0`, `0x00AC0B90`; static range bytes/constants extracted read-only from `Stardust.exe`; ignored scratch audit `probe_ckat.py`. Confidence: confirmed for table generation and decode formula; uncertain only at numeric overshoot handling and exact float-rounding fidelity.
