# Analysis checkpoint — second skeletal animation-message listener

Question A04 / W08. Target: verified original `Stardust.exe`; decompiled text is reconstructed pseudocode. Earlier work established CKAT `MSGS` disk parsing and the `GameAnimationMessageCallback` prefixes. This block examines a **distinct subscriber**, not the already-mapped prefix handler.

`0x007D79F0` appends a `(callback, context)` pair to a SkeletalAppearance2/controller listener vector. A raw `E8 rel32` executable scan finds two direct call sites: `0x0062355E` in the known `GameAnimationMessageCallback` attachment `0x00623530`, and `0x0139E1C5` in `0x0139E040`. The latter passes callback `0x0139C870` with its owning object as context. `0x00830170` invokes registered listeners synchronously for each emitted animation message, so this is a real second dispatch edge, not merely a similar string.

The second callback `0x0139C870` obtains the message name through the message interface, scans to the first underscore, constructs a temporary CRC string from the bytes **after** that underscore, and passes it to `0x0139D5E0`. That function calls a function pointer at the owner's `+0x1C` target `+0x10` with the stripped suffix. Unlike the known client-event listener, there is no six-prefix check in this callback. The exact owner type, valid-name precondition, semantics of the target callback, and affected game/presentation state have not been resolved. In particular, a name such as the deployed `fire1` (801 CKAT groups in the earlier corpus audit) **cannot yet be assigned an effect** merely because it lacks one of the six client-event prefixes; the underscore scanner's behavior for underscore-free names needs an actual caller/asset fixture.

This proves that “six recognized prefixes” is not the complete animation-message consumption model. It does **not** prove that all 3,823 non-prefix groups are used, nor close A04's group-to-effect criterion. The next bounded step is to identify the owner created/updated through `0x0139E040`, resolve its `+0x1C` target's function pointer, then exercise an installed clip message with a matching name. Search for other indirect registrations separately; the two-call raw scan is only direct-call evidence.

Evidence: executable call sites `0x0062355E`, `0x0139E1C5`; read-only pseudocode/instructions `0x007D79F0`, `0x00830170`, `0x0139E040`, `0x0139C870`, `0x0139D5E0`; prior [MSGS corpus](ANALYSIS_CHECKPOINT_2026-09-23_CKAT_MSGS_DISK_CORPUS.md) and [event integration](ANALYSIS_CHECKPOINT_2026-09-23_CKAT_MSGS_TO_CLIENT_EVENT_INTEGRATION.md). Confidence: **confirmed by code** for second registration, synchronous invocation, delimiter scan and forwarding; **unknown** final semantics and ordinary reachability. No whole-client percentage change.
