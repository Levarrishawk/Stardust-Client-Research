# CLEF `CPAP` runtime fields and literal-path correction

Date: 2026-09-22. Original target `C:\Stardust-DEV\Stardust.exe`, SHA-256 `E782BF1C49B3DA730F66B54BC558947C46493F7133F672EED1D8E0C56A6B6150`.

## Confirmed code path

The `CPAP` leaf has a NUL-terminated appearance path; `CLEF/0001` adds one F32, `0002` adds one byte, and `0003` adds four more F32 values. The loader stores a 40-byte runtime record with appearance-template handle at `+0x0C`, base F32 at `+0x10`, byte at `+0x14`, and the four version-3 floats at `+0x18..+0x24`. Older versions initialize the four floats to 1.0. This is a legacy 32-bit in-process layout, not a portable file or network structure.

Both world and attached execution methods (`0x005F05B0`, `0x005F0B70`) create a particle appearance and effect object from that template. The F32 at `+0x10` is forwarded to the managed-particle record at its `+0x20`; the manager's `0x005235A0` update subtracts frame delta from this value and retires the record when the lifetime expires. The byte at `+0x14` reaches the manager's termination-policy byte at `+0x54`, which controls whether an expired particle is allowed to finish naturally before removal. These are **confirmed by code and the prior manager lifecycle trace**.

The version-3 pair at `+0x18/+0x1C` is sampled as a bounded random **uniform appearance scale**, unless the effect instance carries a positive explicit scale override at its `+0x08`. The resulting value is passed as XYZ=(s,s,s) to appearance virtual slot `+0x48`. The pair at `+0x20/+0x24` is sampled separately and stored through `0x007A9040` at particle-effect appearance `+0x64`; prior particle runtime analysis shows this factor multiplies effective time scale. Both pairs are ordered in all installed records. Thus geometry scale and animation/time scale are separate authored controls. **Confirmed path; inferred name of the appearance's virtual scale setter from its three-float input and effect.**

## Full-overlay corpus

The corrected parser sees **815** `CPAP` leaves: 418 in `CLEF/0001`, 15 in `/0002`, and 382 in `/0003`, with 464 distinct normalized literal paths. The lifetime F32 is finite in all records, ranges **0..200**, and is most commonly 1.0 (384 records). The version-2/3 flag is 0 in 78 and 1 in 319 records. All four version-3 floats are finite and positive; the scale pair ranges **0.1..10**, and the time-scale pair **0.66..5**. Neither pair is reversed in any installed record. These ranges describe the installed assets, not safe parser limits.

An exact-path audit exposed one correction to the earlier direct-reference inventory: `clienteffect/droid_effect_fog_machine.cef` literally names `appearance/pt_partydroid_fogmachine.prt ` with a trailing ASCII space. The archive contains the otherwise identical path **without** that space. `TreeFile` normalization at `0x00A930D0` lowercases and canonicalizes slash runs but does **not** trim whitespace. `0x00B260F0` checks that path with `TreeFile::exists` and substitutes the default appearance if absent. Therefore this reference is unresolved under the configured archive overlay, even though a whitespace-trimming research scanner previously called it live. A loose override under an unusual matching name is not ruled out; none was established. Do not silently trim source paths in a compatibility parser merely to make the asset appear valid.

The direct CLEF reference total remains **1,889**, but the corrected split is **1,876 live / 13 absent**: ten `.snd`, two genuinely absent `.prt`, and the one trailing-space `.prt` typo. Recomputed CEF→particle closure reaches **576** live particle nodes, **253** attachment edges, **1,891** PTEX shader slots, and **278** distinct nonempty shaders. Previous values 577 and 1,892 included the particle reachable only after incorrect whitespace trimming. Shader NAME closure is unchanged: 278 DDS occurrences (270 distinct), 270 EFT occurrences (11 distinct), with seven shaders naming one missing EFT.
