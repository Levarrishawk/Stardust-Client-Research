# Analysis checkpoint — CKAT/0001 counted channels and QCHN

Target: verified `C:\Stardust-DEV\Stardust.exe` and effective configured original assets. Ghidra output is reconstructed pseudocode. This refines the older broad animation-format checkpoint without claiming all interpolation semantics.

The effective overlay contains **7,771** `CKAT/0001` `.ans` assets. All have a 16-byte `INFO` payload: one F32 frame rate followed by six signed-16 values. The executable loader at `0x00825B30` uses the second signed-16 as transform-record count, the third as animated-rotation count, fourth as static-rotation count, fifth as animated-translation count, and sixth as static-translation count. The first signed-16 is the declared clip end frame, retained at template `+0x1C`; its label was resolved by a later full-corpus timing audit. All 7,771 `INFO` records have the expected width.

Each `XFRM/XFIN` record is one NUL-terminated transform name followed by exactly ten bytes: U8, U16, U8, U16, U16, U16. The loader retains the name and five scalar/flag/index values. Across the corpus the number of `XFIN` records exactly equals the transform count for every clip (range 2..79). `SROT` stores seven bytes per declared static-rotation entry (**three U8 quantizer selectors, then one U32 packed quaternion**), and `STRN` stores four bytes per static translation entry. Every effective clip matches those count-derived widths. Subsequent evaluator and corpus traces resolved XFIN's rotation flag/index and three translation-axis mask/index pairs.

An optional top-level `QCHN` appears in **32** effective clips. The loader detects it after the main compressed-channel/message/locomotion forms and calls `0x00824870`. Its file payload is U16 key count, three U8 quantizer selectors, then exactly `keyCount` entries of U16 plus packed U32 (six bytes each). All 32 deployed QCHN chunks match `5 + 6*keyCount` bytes. The reader expands entries into 12-byte runtime records and performs a post-load pass `0x008251D0`; later analysis confirms this channel supplies relative root rotation. This is separate from the 171,000 QCHNs nested in AROT.

These are confirmed executable/corpus contracts; they do not prove all possible CKAT versions. Interpolation and quantizer-table details are addressed by later 2026-09-23 CKAT checkpoints.
