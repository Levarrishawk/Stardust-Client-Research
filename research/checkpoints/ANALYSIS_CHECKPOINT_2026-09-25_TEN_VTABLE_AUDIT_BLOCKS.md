# One R05 methodology audit: ten executable-backed vtable findings

Date: 2026-09-25. Scope: original `C:\Stardust-DEV\Stardust.exe`, SHA-256 `E782BF1C49B3DA730F66B54BC558947C46493F7133F672EED1D8E0C56A6B6150`, existing Ghidra inventory, curated names and historical vtable exports. This is **one function-denominator methodology audit with ten findings**, not ten independent analysis blocks, workflows, or evidence for any additional percentage. Original assets and server were not changed; no executable was run.

Reproduce the common byte-level audit with:

```text
python tools/python/verify_vtable_exports.py C:\Stardust-DEV\Stardust.exe local-private/generated-evidence/stardust_function_inventory.tsv data/curated/provisional_names.csv local-private/generated-evidence
```

The script uses only Python standard-library modules. It parses PE32 sections, checks each historical export row's first-column VA actually contains its second-column pointer, requires executable PE-section membership for target classification, validates MSVC RTTI via the complete-object locator at table VA minus four, and walks contiguous executable pointers from each RTTI-validated start. `TABLE` rows are **static table-membership evidence**, not proof of live object construction. `CANDIDATE_REFS` are raw byte scans and remain heuristic. Full Ghidra pseudocode was not regenerated in these blocks.

## Audit findings

1. **Image identity and bounds — closed for this audit.** PE32 image base is `0x00400000`; executable `.text` begins `0x00401000`; `.rdata` begins `0x015DC000`. The SHA-256 matches the pinned original binary. These are provenance checks, not newly recovered behavior.

2. **Historical TSV integrity — narrowed and corrected.** Among 1,837 rows in 24 `*vtable*.tsv` exports, 729 contain the stated pointer in the original image; 1,096 are pointer mismatches and 12 slot addresses are unmapped. The earlier exact-join sample counted 68 uncurated generic functions over 64 bytes, but byte verification of its exported rows reduces that to **66**. A filename or second-column match alone is insufficient. Residual: determine which mismatches are intentionally from another image/module versus stale/raw-scanner errors before using those files for UI coverage.

3. **RTTI/table segmentation — narrowed.** Recovering the actual table start from the preceding MSVC locator changes class attribution. For example, `client_global_water_manager_vtable.tsv` runs into flora and celestial tables, `flora_static_vtable.tsv` runs into `CelestialObject` and skybox primitive tables, and `world_singleton_vtable.tsv` starts with non-vtable scalar words before `TerrainObject` at `0x015ECCC4` and `ProceduralTerrainAppearance::Chunk` at `0x015ECD34`. The original file labels are *window labels*, not ownership labels for every row. New table walks include entries beyond truncated exports, yielding **69** distinct uncurated generic >64-byte exact entries. Residual: independently prove each recovered table end, particularly where contiguous executable pointers could extend through an unusual layout.

4. **Procedural terrain/chunk/worker — previously behaviorally mapped; inventory refined.** RTTI validates `ClientProceduralTerrainAppearance` at `0x015E66B4` (101 contiguous executable slots, 54 exact Ghidra entries, 22 uncurated generic >64-byte entries), `ClientChunk` at `0x015E731C` (48/21/6), and the terrain worker wrapper at `0x015E66A8` (2/1/0). Prior [terrain submission analysis](ANALYSIS_CHECKPOINT_2026-09-12_PROCEDURAL_TERRAIN_SUBMISSION.md) already proves the constructor and camera callback route, so those functions are **not** counted as fresh behavioral discoveries. Static code has two raw occurrences of the terrain table address; one lies in the already described constructor `0x00849350`. Residual: individual table-slot roles and 47 executable terrain targets absent from exact Ghidra entries need classification.

5. **Flora/celestial attribution — narrowed.** RTTI-backed `ClientStaticRadialFloraManager` at `0x015E64C8` has 9 executable slots, 8 exact Ghidra entries and 7 uncurated large entries. Dynamic/radial manager roots are `0x015E6FFC` and `0x015E704C`; their respective large-entry counts are 1 and 2. But the wide raw slices also contain celestial/skybox classes, so the previous per-file count of 16 large “static flora” entries was over-attributed. The already documented terrain auxiliary dispatch identifies actual flora instances and the no-op `+8` method; see [dispatch checkpoint](ANALYSIS_CHECKPOINT_2026-09-21_TERRAIN_RENDERABLE_DISPATCH.md). Residual: slot-specific method behavior beyond that established dispatch.

6. **Water family — bounded class ownership, no new render semantics.** RTTI validates `ClientGlobalWaterManager2` at `0x015E6F6C` and `ClientLocalWaterManager` at `0x015E7434`, each with three contiguous executable slots and three exact Ghidra entries; neither contributes an uncurated generic >64-byte exact entry. Their static/dynamic/local shader-primitive tables are separate classes at `0x015E6E44`, `0x015E6EA4`, `0x015E6EF4`, plus local primitive `0x015E73E4`. Earlier [water rendering analysis](ANALYSIS_CHECKPOINT_2026-09-12_WATER_RENDERING.md) already established the broad pipeline. Residual: individual primitive virtual methods and source-level names; no inference about final light/shader scalars.

7. **Audio family — table identity verified, prior behavior retained.** `Sound2d` at `0x015DC79C` has 26 executable slots, 16 exact Ghidra entries and 8 uncurated generic >64-byte entries. `Sound2dTemplate` at `0x015DC9DC` has 41/9/3. Raw code contains two possible occurrences of the `Sound2d` table address, one in the previously documented constructor `0x00418F40`. The [audio bridge checkpoint](ANALYSIS_CHECKPOINT_2026-09-12_AUDIO_PLAYBACK_BRIDGE.md) already covers the Miles adapter and per-frame parameter path. Residual: distinguish uncurated slot semantics and Ghidra-omitted short targets; do not count revalidation as fresh functional coverage.

8. **Scene/cockpit class split — corrected attribution.** The `scene_render_driver_vtables.tsv` slice contains distinct RTTI-backed `CockpitStage` (`0x015DE768`, eight slots), `CockpitLeaveStage` (`0x015DE79C`, eight), and `ThirdPersonStage` (`0x015DE7C0`, six), as well as two one-slot watcher tables. The `GroundScene` root is `0x015DD988`, only four contiguous executable slots before adjacent message tables. Existing [game-loop documentation](../../docs/GAME_LOOP_ARCHITECTURE.md) identifies its render slot; this audit does not establish any new scene state transition. Residual: check stage construction/selection paths if they become a decision blocker.

9. **UI export is not a function denominator — contradicted prior naive join.** The `cui_vtable_inventory.tsv` has 1,104 rows, but only 23 first-column/second-column pointers byte-match this PE and none of those 23 target an exact executable Ghidra entry. This is consistent with the export being a heterogeneous scanner product; it does **not** imply UI lacks virtual methods. The [UI inventory](ANALYSIS_CHECKPOINT_2026-09-21_UI_MEDIATOR_CLASS_INVENTORY.md) already warned that its raw scanner output needs RTTI validation. Residual: rebuild UI vtable candidates from actual PE RTTI and executable target checks; do not assign UI function-completion from this TSV.

10. **Missing analyzer entries and denominator — material finding, still open.** Across the RTTI-validated table walks, 196 unique executable targets exactly match a Ghidra function entry, including 69 uncurated generic >64-byte entries. Another **161 unique executable pointer targets** fall *outside every exported Ghidra function interval*, not merely at interior labels. For those 161, 123 have a raw `RET` opcode somewhere in the first 16 bytes, seven begin with `RET`, five begin with a jump form, and 26 have another first-16-byte shape. These opcode scans are not instruction decoding, but spot-checked targets include `0x004195C0` (`fld`/`ret`) and `0x0041CE00` (`fld`/`ret`) and strongly suggest real small callable entries omitted by the export. This corrects the assumption that 93,287 non-`Unwind@` Ghidra entries are even an exhaustive **candidate** denominator. Before any percentage, recover and classify these raw targets, then expand beyond the small set of known vtables. No current whole-client percentage is defensible.

## Accounting and confidence

Findings 1, 4, 6, 7 and 8 mostly **validated or refined existing evidence**; they are not independent behavioral completions. Findings 2, 3, 9 and 10 corrected measurement/attribution errors. Finding 5 narrowed a specific class misattribution. The audit did not close the R05 exit criterion. Confirmed: image hash, PE pointer comparisons, RTTI names for validated table starts, exact Ghidra-address joins. Strongly inferred: many of the 161 outside-interval executable targets are callable original methods. Tentative: raw code-address occurrences indicate constructor/registration references. Unknown: full reachable application-function set, exact UI callback inventory, which table slots execute in ordinary gameplay, and remaining per-method semantics.

Next R05 work should build a *new* exact-PE RTTI/vtable corpus rather than trust old filename slices; recover the 161 omitted entries into a separate stable-address queue; validate a sample by instruction-aware decoding or Ghidra; then classify CRT/library and actual runtime roots. Keep “identified class table,” “candidate callable entry,” “reachable in scenario,” and “behavior understood” as separate states.
