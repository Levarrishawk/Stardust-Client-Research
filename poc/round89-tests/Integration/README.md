# Original-installation application verification

The offline join constructs the engine-neutral ReplacementClientApplication from an explicit original installation profile, pinned injected peers and a bounded minimum-resource provider. The application owns preparation, session, pump, world, motions and run. Godot borrows those services and owns presentation.

Run the documented consolidated command in [the regression runbook](../../../docs/CLIENT_REGRESSION_RUNBOOK.md). The Round89 native entry is the default; --gpu adds actual renderer verification. Explicit local root, configuration, tools, cache and fresh private output are required. No sockets or DNS are constructed.

Five headless cases exercise the original selected player through success, pre-ready cancellation, minimum-provider failure, disconnect send error and send timeout. The optional GPU case presents the same actor through local movements and authoritative corrections. Independent authored protected peers verify authentication, selection, readiness, movement, deferred bytes and disconnect. Independent archive readers verify original preparation, publication resources and terrain identities. Synthetic peers remain offline inputs, not interoperability proof.

Close retires application work and caller presentation without blocking. Owner-thread finalization waits for actual drain and presentation completion, observes failures separately and releases original installation resources. Normal cleanup requires successful drains. Faulted completion permits safe owner finalization without claiming cleanup success.

The bounded provider decodes original PTAT; full procedural terrain, general CREO1/PLAY gameplay, nearby actors, avatar customization, original movement timing and live server receipt/release remain unproved.

In the provider-failure case, ApplicationDrainSucceeded remains false and the exact observed InvalidDataException is retained. Clean records safely finalized ownership for that expected case; it does not claim successful provider task completion. Success and cancellation require successful application drains and no cleanup failures.
