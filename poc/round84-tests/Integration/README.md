# Selected-player offline session verification

This composition uses the reusable session, injected datagram pump, scene bridge,
original-installation creature preparation and selected-player Godot adapter.
The peer is authored Python data delivered through in-memory ports. It creates no
sockets, resolves no hostname and does not execute the original client.

Supply explicit original installation/configuration, cached packages and native
runtimes. Choose a fresh output beneath this repository's ignored `local-private`.

```powershell

```

The public bounded preparation policy selects
`object/creature/player/shared_human_male.iff`, its declared
`appearance/lat/all_m.lat`, exact idle `emt_standing_idle_ambient_1_ag`, and
`loop_standing` routes `[0,1]`/`[0,2]` for walk/run clips. These are explicit
inspection choices, not recovered avatar animation selection. CRC and all pins
are discovered from input bytes; no historical argument vector or private
hand-built catalog is needed. General avatar selection/customization remains open.

The synthetic peer supplies one matching selected identity, original object and
terrain logical paths, an independently authored typed CREO3 baseline and a nonworld sentinel.
Its replies follow actual session requests, authentication, selection and ready.
The typed baseline uses the accepted independent Round15 author. It does not
represent a complete server baseline set or prove live compatibility. The pump's
standalone component still tests an opaque count-zero envelope; that is separate
from this presentation proof, whose factory requires typed replicated state.

The minimum service deliberately waits, then decodes original
`terrain/tatooine.trn` PTAT and confirms the caller has established its modern scene
owner. It does not evaluate the procedural surface or recover the original
minimum-readiness policy. Tests reject early ready/publication, require ordered
staging, one scene-ready and explicit sentinel ownership, and check the selected
identity and independent Godot position conversion. Success-headless,
cancel-before-ready and minimum-service-failure run by default; `--gpu` adds the
visible case and private screenshot. Modern camera/light settings serve inspection.

Source-only private staging includes SHA-256 identities. Builds use local package
sources with audit disabled; per-command 180-second bounds use the regression
runner's descendant cleanup. Native receipts and independently compared
authentication/select/ready datagrams stay private. Python checks preparation,
loaded closure and terrain hashes against installation bytes separately from
native decoding. Controlled close joins ports, minimum work, resource jobs and
presentation; it is **local teardown**, not a protocol disconnect/server-release
claim. Movement is not performed by this test.
