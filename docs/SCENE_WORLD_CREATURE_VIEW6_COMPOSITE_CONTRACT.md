# Optional composite CREO6 world publication

Round36, 2026-10-03. The [world coordinator](../poc/Stardust.Core/Session/SceneWorldCoordinator.cs) optionally owns the accepted [composite store](SCENE_CREATURE_VIEW6_COMPOSITE_STORE_CONTRACT.md), using the frozen [ordered scalar/HAM kernel](CREATURE_VIEW6_COMPOSITE_CONTRACT.md). The [router and wrappers](../poc/Stardust.Core/Session/SceneWorldCreatureView6CompositeApplicationRouter.cs) provide an independent ingress/publication partition. This is engine-neutral modern publication, with no original owner callbacks, gameplay effects, defender/wearable delta composition, or live interoperability claim.

## API and configuration

Both public constructors append `SceneWorldCreatureView6CompositePolicy? creatureView6CompositePolicy = null` after the accepted scalar CREO6 policy. Configuring both scalar and composite CREO6 throws `ArgumentException`; one complete baseline is consumed and charged by exactly one CREO6 partition. Default and scalar-only behavior remain available.

The policy accepts `CreatureView6Limits BaselineLimits`, `CreatureView6CompositeLimits DeltaLimits`, `CreatureView6CompositeStateLimits StateLimits`, `SceneCreatureView6CompositeStoreLimits StoreLimits`, and optional `ulong RevisionSeed = 0`. Baseline and delta payload ceilings must each fit the world payload ceiling. For a 65536-byte world, explicitly select corresponding payload limits; defaults are 1 MiB. Limits are validated and copied, including nested model/message limits. Ingress delta limits and the state kernel's message/model limits remain independently enforced; direct already-owned plans receive kernel/store policy checks but are not decoded again at ingress.

Public APIs are `CreatureView6CompositeEnabled`, `RetainedCreatureView6CompositeBytes`, `FindCreatureView6Composite(generation, id)`, `IsCurrent(SceneWorldCreatureView6CompositeSnapshot)`, and `ApplyCreatureView6CompositeDelta(generation, exactExpected, plan)`. `SceneWorldObjectSnapshot.CreatureView6Composite` carries the partition into snapshots and world change batches without changing existing scalar/TANO properties. The immutable wrapper exposes Generation, Incarnation, global store Revision, composite State, and complete eighteen-field Model.

Journal APIs are `DrainCreatureView6CompositeEvents(generation)`, `AcknowledgeCreatureView6CompositeEvents(batch)`, and `IsCurrentCreatureView6CompositeEvent(batch, index)`. A wrapper exposes Generation, StoreRevision and the immutable ordered metadata-only store records. Distinct wrappers can refer to the same issued underlying batch. Successful exact acknowledgement invalidates all such wrappers once; foreign world/generation, stale issued batch, repeated acknowledgement, and closed world reject.

## Family, lifecycle, and delivery

Only CreatureDetail0 recipients accept typed CREO6. The full eighteen-field baseline must precede creature end-baselines when this partition is enabled. Matching pending or finalized creatures can be seeded; deltas require finalized seeded recipients. Static recipients keep their own TANO3/TANO6 barriers and do not require CREO6. Accepted assignments are fields 0, 2-12 and 16-17; HAM/max-HAM fields 13/14 use the frozen ordered kernel. Defender field 1, wearable field 15 and unknown delta indices reject. Complete baseline defender/wearable data and counters remain retained.

Generation, world owner, current incarnation, and exact stored publication bind snapshot currentness. Stale generation/receipt returns false before plan access. A current receipt with mismatching plan ID throws. Same-incarnation registry handle changes preserve state and world currentness; the next update uses the latest handle with the exact stored snapshot. Destroy/recreate invalidates old receipts, starts recreated state revision one, and preserves the store's global revision progression. Valid no-op HAM plans still advance one outer state/store publication and world mutation revision, with zero mutation events.

Historical journal events survive recipient destruction/recreation within a generation. A current journal may be acknowledged even though its historical events cannot be delivered. The event guard checks owner, generation, exact current underlying batch, bounds, current registry incarnation, and finalized recipient. Call it immediately before delivery while remaining serialized. No callback dispatch is provided. Generation replacement clears mapped state and journal; coordinator close clears owned resources/state and drains/cancels owned asynchronous work. Router disposal/failure clears only its ingress callback/world/downstream references and never closes the borrowed world or downstream.

## Preparation, failure, and resources

The coordinator validates family, phase, exact receipt, checked world mutation revision and world journal capacity, and allocates the complete replacement world journal before store preparation. The frozen store prepares all candidate model/map/event arrays, charges and checked revision/epoch under its owner gate. `CheckPrepared` revalidates active exact candidate and handle/incarnation. Commit then consists of prebuilt store and world assignments; finally releases the gate. No parsing, user callback, allocation, or checked arithmetic occurs between the first assignment and release. The internal seam is trusted: check and commit cannot have intervening callbacks or registry mutation.

RetainedCreatureView6CompositeBytes is all mapped current model logical bytes plus 24 per pending composite event. Other actors and earlier events reserve global state/output/queue capacity. Every intermediate model must fit, so growth followed by shrink does not evade limits. Kernel and message work remain separate counters, each narrowed by the store ceiling; map/journal copying and frozen validation overhead have separate hard bounds. These are logical resource policies, not CLR heap or elapsed CPU measurements. Prior CREO3/TANO3/TANO6, opaque envelope, and resource-job partitions retain separate charges.

Rejected direct plans and exact active CREO6 attempts preserve preceding valid publication, earlier journal, active phase and resource/presentation ownership. Tests explicitly reject a later malformed/unsupported wire and a later HAM intermediate overflow after prior valid scalar work. Failed preparation exposes no scalar/vector prefix. Wrong-family/noncandidate envelopes and staged/barrier failures keep the prior generation-fatal behavior. External callback mutations themselves cannot be rolled back; their returned candidate is rejected.

## Router callback boundary

`SceneWorldCreatureView6CompositeApplicationRouter(world, decoder = null, downstream = null, maximumPayloadBytes = 65536)` borrows an enabled world and copies each accepted message. Exact CREO6 deltas are decoded by the frozen grammar before any custom decoder. Baselines and lifecycle/control messages pass downstream, defaulting to world.Accept. The input copy is cleared after handling.

Callbacks run before preparation. The whole-world ingress stamp includes generation/phase, world mutation revision and callback-attempt epoch, registry object references, world change membership, and every typed partition's publication revision including composite CREO6. Generation changes, world/journal mutation, even rejected mutation attempts, event drain/ack attempts, caught router reentry/disposal, stale expected publication, or mismatching plan object/raw declared count reject the candidate. Pure read-only inspection is permitted. All world/router/store operations require their constructing managed thread. The router closes its own references on failure; no callback executes during commit.
