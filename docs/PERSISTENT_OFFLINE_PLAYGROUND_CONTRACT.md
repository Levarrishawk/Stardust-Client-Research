# Persistent configured offline playground

Date: 2026-10-06. This is an authored Godot replacement-host lifecycle boundary over frozen accepted80 Version13. It is not original movement, UI, sender or live-client parity.

## Public entry and hooks

[PersistentOfflinePlayground](../poc/Stardust.Godot/PersistentOfflinePlayground.cs) is a Node. Configure it before AddChild with `Configure(Func<int,string[]> arguments, Func<int,ScenePumpedWorldPreview> factory, int maximumRuns, Action<ScenePumpedWorldPreview>? beforeRetirement=null)`. Run numbers start at1; maximumRuns is1..32. The arguments factory supplies each independent full Version13 argument array; the preview factory returns a fresh unattached live ScenePumpedWorldPreview. A rejected pre-AddChild factory/candidate returns false and retains the preceding outcome. An unreturned factory allocation remains factory-owned; an attached returned node is borrowed/rejected, never freed by the shell.

The shell exposes CurrentPreview, CurrentReady, StartedRuns, RetiredPreviews, CompletedReports (copied array of primitive records), LastCompletedReport, IsTerminal, IsClosing, LastFailureType, LastFactoryFailureType, OutcomeCaption and RestartHud. `RequestRestart()` enters the actual frozen80 HUD RequestRestart callback; it returns false for a current child, terminal/closing shell or exhausted run budget. It does not emit a button signal. `RequestClose()` sets a shutdown request; _Process performs controlled child shutdown and quits after drain/terminal reporting. `RunReady(int run)` and `RunCompleted(int run, OfflinePreviewCompletionReport report)` are invoked in shell _Process, after readiness or retirement/report handling, never in child completion/native exit callbacks. RunCompleted can carry a terminal attempt: inspect ValidOutcome, CleanupSucceeded and Restartable before interpreting it as a successful session.

[Child bridge](../poc/Stardust.Godot/ScenePumpedOfflineRestartBridge.cs) adds `ConfigureOfflineRestart(string[] args, Action<OfflinePreviewCompletionReport> onCompleted, Action<ScenePumpedWorldPreview>? beforeRetirement=null)` before AddChild, plus OfflineRestartReady, OfflineRestartCompletion, OfflineRestartCleanupFinished and RequestOfflineShutdown. It clones bounded arguments (2..256 strings, each<=4096) and admits exactly one bounded Version13 SuppliedConfiguredOfflinePlayground profile. All existing full profile/asset/input checks still run in _Ready. Default children continue using OS arguments and ordinary tree quit behavior. The frozen ordinary failure body is preserved exactly as FailDefault, mechanically checked against the incoming archive.

The optional retirement hook runs at most once after valid actual completion/root snapshots are captured, before point/input/resource cleanup, on normal or actual terrain-fault retirement. It receives the live child for a caller-scoped test partial, allowing actual viewport W/Shift/orbit/wheel teardown stress without an additional update. It never runs for a missing/invalid outcome. A thrown hook is a cleanup error and blocks restart; callback effects are not rolled back.

## Readiness and persistent display

Readiness is actual configured Version13 pointStarted/phase72 with configured session, point driver, controller, root/transport/queue, session/manual/run/camera/point input, focus/limits/live HUD, terrain query, world/pump/host and two visual objects prepared. World ScheduleFinish latches it immediately after BeginPointTarget returns, before the next update; the property remains historical through cleanup. This avoids relying on outer polling for tiny runs completed within one host frame. It imports no unfinished Round81 Runtime/Networking API.

Only one child is admitted. Completed normal or actual terrain-fault cleanup delivers a valid primitive callback exactly once; the receiver stores it with exact child/generation identity and does not Free or admit another factory. Shell _Process frees that successfully drained child, then owns the frozen [restart HUD](TERRAIN_OFFLINE_RESTART_HUD_CONTRACT.md) on the outer shell. The next candidate's prior outcome remains visible during loading until actual readiness is observed, then the prior facade is explicitly disposed. The old child is fully freed before the next factory. Duplicate or stale completion callbacks cannot affect a successor. A candidate rejected before AddChild is freed in a later _Process, preserving the old outcome and avoiding native deletion in the GUI callback. Admission reentry is sticky for admission but does not prevent terminal polling/controlled shutdown of an already published child.

Factory/admission failure after child publication becomes terminal. Missing completion, failed root drain, unsupported reason or any cleanup error cannot restart. Child terminal attempts are exposed via primitive polling, not successful completion callback. If cleanup failed, the shell retains that child, records the terminal report once and creates no successor; it does not claim Free after unsuccessful cleanup. Controlled window close exits1 for that terminal condition. A successfully drained window-close cancellation terminates without treating close itself as a restart fault.

## Primitive report and cleanup evidence

OfflinePreviewCompletionReport is a flat record with Reason, MaximumUpdates, CompletedUpdates, AttemptedUpdates, RootFrames, QueueCount, PendingMessages, RetainedPackets, ValidOutcome, ReadyReached, CleanupSucceeded, Actors, QueuedPublications, PendingPublications, OutstandingArchiveJobs, ArchiveCalls, ArchiveClosed, FailureType, CleanupFailureTypes and WindowClosing. Its derived Restartable and Outcome contain only primitive state. Counts/reason/root buffers come from actual frozen controller/root capture in [ScenePumpedOfflineOutcome](../poc/Stardust.Godot/ScenePumpedOfflineOutcome.cs); actor/publication/archive values come from the actual cleanup frontier. No node, session, worker, transport, resource or controller reference is retained in a report.

ValidOutcome requires supported BudgetCompleted/FinishRequested/Faulted controller completion and clean historical root completion, not clean roots alone. CleanupSucceeded additionally requires no cleanup failures, actors/queued/pending/outstanding jobs0, matching archive calls/closed and all archive tasks completed. Normal cleanup performs existing checks and disposal; failures attempt each input/terrain/resource cleanup and preserve caught error types. A Finish cleanup exception stays terminal even if subsequent recovery cleanup drains.

A failed presentation host Completion can carry its original frame failure. The bridge observes that exact non-aggregate original failure only if host.Failure is identical and both actual presentation/world drain tasks completed successfully. Distinct, aggregate or failed-drain exceptions enter the cleanup error collector and block restart. This distinction is a source-backed implementation rule; the worker did not execute an original-terrain fault run. Concurrent ObserveHost/Finish/Fail share one task installed before starting cleanup, one capture and one hook/notification. After native child exit, pending continuations suppress scene/engine work; new _ExitTree/receive/supervisor notification callbacks never Free.
