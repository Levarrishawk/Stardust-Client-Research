# Selected-zone outbound disconnect

Round87 implements the bounded transport/session/pump boundary using the existing [SOE schema](SOE_TRANSPORT_PROTOCOL.md), [Round71 byte vector and ownership](SCENE_WORLD_PEER_DISCONNECT_CONTRACT.md), and [Round72 completion prefix](SCENE_WORLD_MULTIPACKET_DISCONNECT_CONTRACT.md). No application codec, engine owner, original executable execution or live contact is added. These are modern owner policies around the recovered eight-byte transport shape.

## Preparation and local closure

`SoeClientTransport.CreateDisconnectDatagram(ushort reasonWord = 0x0006)` requires Established and returns a fresh owned protected array. Decoded bytes are opcode `00 05`, the negotiated connection ID as big-endian U32, and the raw reason word as big-endian U16. The default preserves `00 06`; reason semantics remain Unknown. Existing negotiated seed, CRC width and datagram limit protect the frame. It consumes no reliable sequence and does not close transport or change pending/retained counts. Caller arrays survive subsequent transport closure. The accepted71 vector remains decoded `00 05 12 34 56 78 00 06`, protected `00 05 C6 F7 E4 D9 C6 C0 C6 D2 7E` with seed A1B2C3D4/CRC2.

`ReplacementClientSession.CloseWithDisconnect(long nowMilliseconds, ushort reasonWord = 0x0006)` requires Selected and an established zone. It prepares one owned Zone datagram, releases credentials, pending/reliable state and selected endpoint/ID, and changes Phase to Closed. Preparation errors follow existing fault policy. Duplicate calls reject without another datagram; Dispose remains idempotent. Closed means no further local protocol work. It does not mean the datagram was sent or the server released the player. Clock/thread guards run before preparation. A returned wire remains caller-owned after Dispose.

## Pump submission and deadline

`ReplacementDatagramPump.BeginDisconnect(long now, long timeoutMilliseconds = 3000, ushort reasonWord = 0x0006)` requires the creating thread, no reentry, a monotonic clock, an active selected Zone lane and completed successful login retirement. Timeout must be positive and at most30000ms; checked deadline addition and all admission checks precede session/queue mutation. A second BeginDisconnect rejects and preserves the in-progress prefix. Invalid admission leaves session/pump active. Preparation failure retires the pump through its normal failure path.

The pump takes the prepared wire, clears queued unsent wires and its owned notices, and preserves the current in-flight send buffer/task. Caller-transferred application notices are outside its ownership. Special disconnect Tick never polls session, retries reliability, dispatches an incoming application or closes session again. Completed receive bytes are cleared without decode; outstanding or late receive ownership passes to the existing retirement helper. No new receive is started in this state. New Submit/login/zone work rejects; supplied rejected wire arrays clear, while an aliased pending send buffer remains protected by existing ownership checks.

After the prior send completes successfully, its bytes clear and exactly one final disconnect is submitted through the same admitted port and pinned peer. DisconnectRequested records preparation. DisconnectSubmitted becomes true when the actual SendAsync call is made, including a synchronous throw. DisconnectSendCompleted becomes true only when an owner-thread Tick observes successful final task completion before the deadline. No peer ACK or server release is inferred. Success retires the active lane, cancels receive, disposes the port and initiates drain; the pump is then disposed and further Tick rejects. Explicit abort/Dispose remains idempotent and never promotes a later task completion into a send-success flag.

The deadline is checked at the beginning of special Tick; observation at or after the deadline fails even if a task has completed since the previous Tick. Timeout, send exception/cancellation, or an observed receive fault/cancellation records FailureType and retires/drains with no send-success flag. An uncooperative in-flight borrower can outlast that deadline: retirement keeps its buffer until actual task completion. Timeout bounds the attempt, not an injected port's willingness to cancel.

DrainCompletion remains the existing retirement aggregate. It can already be complete while the final attempt is in progress, so caller must first observe DisconnectSendCompleted or FailureType and then await drain. Returned-task send/receive I/O failures are observed once in Tick and again by DrainLane, making drain faulted with a redacted aggregate; this is re-observation of the same I/O failure, not a new cleanup failure. A synchronous SendAsync throw leaves no returned send task and drains successfully if cleanup succeeds. A new DisposeAsync failure after a successful send also faults drain, while DisconnectSendCompleted remains true and FailureType remains null. Callers must handle that cleanup failure separately. No successful-drain claim follows from completion alone.
