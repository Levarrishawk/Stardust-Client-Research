# Supplied manual terrain intent

The [point controller](../../SWG-Godot-Client/poc/Stardust.Core/Session/SceneWorldTerrainPointTargetDriver.cs) adds `SetManualInput(System.Numerics.Vector2 nativeXZDirection, long exactCurrentClock, CancellationToken token = default)` and owner-guarded `ManualInput`. Vector2.X is native X and Vector2.Y is native Z. Manual7 appends prior enum values0..6 unchanged. Existing constructor, point target, pause/admission and clear signatures remain unchanged; no host/input adapter, terrain builder, pathfinder, gameplay cadence or original manual gait/control/units parity is introduced.

Each direction component must be finite in[-1,1]. The setter requires owner/non-reentry, open healthy current world/store/incarnation, exact current driver-result clock, pre-cancellation and remaining update capacity. It prepares owned diagnostics, then rechecks token/reentry before committing. Only direction intent and target ownership change: existing target is released and its receipt becomes non-current; paused intent, successful-target revision/count/cap, update counts, actual driver/result/clock and last borrowed motion are preserved. The setter performs no driver call, geometry query, input submission or motion publication. Zero direction becomes Idle or Paused. It does not refund point capacity or consume another successful target.

`ManualInput` retains the admitted raw binary32 direction. Analog magnitude inside the unit disk is preserved. For each ordinary active manual tick, compute double length, use configured speed unchanged when length<=1 or speed/length when length>1, then cast scaled X/Z once to binary32. If the actual binary32 Vector3 magnitude exceeds configured speed, move each nonzero component one representable float toward zero, at most four times. These ULP adjustments involve no repeated double-to-float cast. If magnitude still exceeds the cap, admission throws before Submit. Thus the actual published float speed is bounded by configured speed (at most10), including maximum-speed diagonals. This is explicit modern rounding policy, not original input behavior.

Ordinary consecutive ticks submit manual velocity to the actual owned terrain driver and ground through its retained supplied surface. Manual mode continues until replaced or cleared; no target-plane/no-overshoot rule applies when there is no point target. Paused ticks submit zero while retaining raw manual intent. Resume recomputes that same intent during the next normal update. Eligible authoritative correction is adopted by the actual driver before its tick; manual axes remain the supplied axes rather than steering toward a target. Sole serialized local writer remains required. Another local writer is unsupported and not silently adopted.

Successful `SubmitTarget` clears manual intent only after its actual admission and receipt preparation succeed. Invalid/stale/foreign/capped target submission leaves manual intent unchanged. Point target then resumes its existing radius/travel/arrival/final-stop rules. `ClearTarget` now clears both movement intents, retaining its exact clock/currentness/pause/budget/driver/publication invariants; clearing an already empty controller is idempotent. `Dispose` drops both intents and owns only the existing actual driver. Historical caller receipts and borrowed world/store/query/surface/motion survive.

Invalid range/nonfinite direction, wrong clock/token, stale/closed/faulted/disposed context, wrong thread and exhausted updates reject before new intent or driver/publication effects. Inherited post-Submit failures/cancellation retain honest motion prefixes and latch terminal fault; outside-terrain manual travel is not clamped or teleported. A focused real outside tick faults with the exact prior local publication preserved and its manual intent retained until disposal. Reentry poison/post-check cancellation and rare allocation branches remain source-inspected/inherited; no callback hook is added. Missing exact historical ray-emitter provenance is unchanged.
