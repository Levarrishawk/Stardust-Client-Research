# Supplied human face inspection

Round 19 adds a standalone [preview](../../SWG-Godot-Client/poc/Stardust.Godot/SceneCreatureFaceInspectionPreview.cs) using the baseline descriptor loader, face builder, and owned creature visual. It does not depend on the same-round production resource-reader work. See the [evidence checkpoint](../research/checkpoints/IMPLEMENTATION_CHECKPOINT_2026-10-02_R19_FACE_INSPECTION.md) and existing [composition contract](BLUEPRINT_FACE_COMPOSITION_CONTRACT.md).

The explicit six zero-valued entries in [human-face-zero.json](../../SWG-Godot-Client/poc/preview-profiles/human-face-zero.json) are supplied inspection values, not recovered character defaults. Its SHA-256 is `C4F7CF06AB8C4083A2510556550C047DC0ADD5A5A0040829A81CBB047CCCBD9B`. The configured overlay is pinned by the existing configuration pin. Loading uses at most 128 resources and 32 MiB encoded source bytes. Before publication, a separate 64 MiB decoded policy checks unique material/face-source mip storage plus generated output mips. This is a post-decode acceptance check, not a peak-memory bound during decoding.

The baseline human catalog entry, idle selection, and supplied walk/run bank are loaded on an owned worker. Default loading consumes 39 unique reads / 4,686,371 encoded bytes; generated loading consumes 76 / 5,940,390. Generated output must have exactly one destination: `appearance/mesh/hum_m_head_l0.mgn`, shader slot 0, MAIN (`0x4D41494E`), `shader/hum_m_face.sht`, renderer `texturerenderer/hum_m_face.trt`. Body, mouth, and head factor records must equal the default descriptor records. Missing and additional profile keys and a non-MAIN destination are rejected by the baseline builder before GPU allocation.

Both views use idle frame 0, a fixed camera at `(0,1.05,-4.2)` looking at `(0,1.05,0)`, FOV 32, and the same background. `SceneCreatureVisual.Verify(true)` checks generated texture upload bytes and the actual shader albedo resource. The preview records the identities of all five mesh material surfaces, including their shader and texture resources. Eight walk/run frame selections with Height 1.4, followed by idle/Height reset, must retain those identities and pass visual verification. Clip switches use the existing 0.25-second presentation blend completion convention.

The [independent verifier](../../SWG-Godot-Client/poc/round19-tests/Rendering/Verify.py) reuses the Python original-byte composition oracle and parses raw head TRTS bindings. Five layer hashes and the final 256×256 RGBA image agree; the final SHA-256 is `A41EE8925C695A8BC2DA0CAC1FA17864D471270507DF3900472F0655A5A42808`. At 1280×720, the default/generated comparison changes 1,967 pixels with half-open bounds `(614,148)-(662,203)`. Every changed pixel lies inside the face rectangle `(610,135)-(665,220)`. The body rectangle `(550,225)-(725,700)` and sampled upper-cap rectangle `(610,135)-(665,148)` are identical. This establishes the bounded inspection result, not parity with the legacy renderer or arbitrary customization profiles.

Normal teardown disposes two owned roots and closes two archives after all worker jobs complete. The cancellation probe waits until the archive lookup is entered, cancels, drains the worker, and requires zero visual allocations and one archive close. Forced process termination is not a demonstrated drain guarantee. Original bytes, detailed exports, and PNGs remain ignored/private.

Run the [launcher](../../SWG-Godot-Client/poc/round19-tests/Rendering/Launch.ps1) with explicit existing Godot path, archive root, and configuration. Omit `CapturePath` for headless mode; supply a fresh absolute PNG path under the checkout's ignored private directory for a GPU capture pair. `CancelLoad` is a separate mode. Run `Verify.py EXPORT DEFAULT_PNG GENERATED_PNG` with the bundled Python runtime. The launcher prints the private evidence and log paths; the second capture appends `-generated` to the first stem.
