# Explicit bounded offline terrain session budget

[TerrainOfflineSessionBudget](../poc/Stardust.Core/Session/TerrainOfflineSessionBudget.cs) is sealed, immutable and validates constructor integers: `TerrainOfflineSessionBudget(int maximumUpdates, int maximumTargets)`. Readonly properties `MaximumUpdates` and `MaximumTargets` are bounded1..6000 and1..128.6000 updates represent60 seconds only at a10ms step; other already admitted step durations remain caller policy. This is explicit modern offline capacity, not original movement/session duration or live authorization.

The [point driver](../poc/Stardust.Core/Session/SceneWorldTerrainPointTargetDriver.cs), [locomotion observer](../poc/Stardust.Core/Session/SceneWorldTerrainLocomotionObserver.cs) and [pivot-follow clock](../poc/Stardust.Core/Session/TerrainCameraPivotFollowClock.cs) append `TerrainOfflineSessionBudget? budget = null` after their existing cancellation-token constructor parameter. No existing positional parameter/default changes. With null, point update/target ceilings stay128/16 and observer/follow update ceilings stay256; their default requested counts remain128. With a budget, requested maximumUpdates/maximumObservations must be positive and no greater than its MaximumUpdates; requested point maximumTargets must fit MaximumTargets. **A budget does not change requested counts:** passing a6000 budget with default arguments still grants128 updates. A smaller budget may reject otherwise valid default requested counts; callers must request the smaller counts explicitly.

Rebase counters/caps, per-step terrain reservations/triangle tests, single-step scheduler, input, speed, point-admission/provenance, clock, event/cycle/phase, byte and object-row limits remain unchanged. No persistent motion/event history is added to production. Budgets never reset, rearm or refund successful target/update/observation counters. Point and follow constructors retain complete configured signed64 end-clock preflight; opt-in observer also checks its actual initial driver timestamp plus requested observation interval fits signed64 before clock construction. The null observer path retains its prior admission semantics. Owner/current-incarnation/token/failure prefixes and borrowed disposal rules remain unchanged.
