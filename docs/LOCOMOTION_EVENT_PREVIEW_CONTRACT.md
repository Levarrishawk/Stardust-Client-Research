# Accepted-displacement locomotion event preview

Round 4 adds an engine-neutral modern preview policy. It does not establish the original client's event scheduling. Moving clips advance from accepted planar displacement after collision resolution; elapsed time advances idle. The wrapper produces owned diagnostics, with no audio, effects, root-motion application, animation graph, or Godot integration.

LocomotionEventPreviewClock takes idle/walk/run PreviewLocomotionClip descriptors, an explicit run threshold, and the corresponding CompressedLocomotion event sources. Source and descriptor EndFrame must match. Callers must pair descriptors derived from the same prepared clips; event sources do not carry frame-rate metadata. Tick(seconds, acceptedWorldDelta, active) returns a LocomotionEventPreviewBatch containing State, Generation, UnwrappedPhase, Advanced, and ordered occurrences. Reset(heading) returns to idle and starts a new generation.

The existing [locomotion clock](MOVEMENT_SKELETAL_PREVIEW_CONTRACT.md) remains authoritative for classification, normalized phase, heading, accepted distance, and switch counts. The wrapper forks that clock and uses its internal LastPhaseIncrement rather than duplicating its arithmetic. Successful wrapper states equal the existing clock exactly. There is no phase compensation or boundary snapping. Moving phase depends on accepted X/Z distance; Y does not contribute to locomotion distance.

For each accepted tick, completed cycles increase by floor(previous normalized phase + authoritative increment). Unwrapped phase is completed cycles times the selected EndFrame plus the new authoritative frame. A mode switch starts a new generation and cycle epoch, preserving the previous normalized phase in the destination clip. The destination cursor is seeded at that entry frame: occurrences at or before entry are skipped, and only that tick's traversal is emitted. The previous clip receives no catch-up traversal.

Traversal follows the [event cursor contract](ANIMATION_EVENT_CURSOR_CONTRACT.md): (previous, target], duplicate identities retained, terminal occurrences before the next cycle's frame-zero occurrences. Initial idle frame zero is eligible on the first positive tick; Reset rearms it. Inactive and zero-duration ticks return empty unchanged snapshots. A positive active tick with blocked planar movement selects idle and emits only idle events.

Batch ownership is private to the clock. IsCurrent checks owner identity and generation; equal generation numbers from different clocks do not match. Old snapshots remain immutable after switches or reset. IsCurrent does not establish whether a batch has already been delivered; consumers remain responsible for delivery discipline. The wrapper stores no batch history.

Preflight runs on candidate clock/cursor state and commits only after event generation and batch construction succeed. Validation, phase, cycle, event-budget, or generation failures leave locomotion state, cursor time, cycles, and generation unchanged. Default per-tick budgets are 64 cycles and 4096 occurrences; configured maxima are 1024 and 262144. The cursor phase ceiling is 2^40. Existing finite-vector, maximum 100-unit displacement, and maximum .25-second tick guards remain authoritative. A phase whose cycle association cannot be represented is rejected instead of modifying the legacy clock's arithmetic.

Synthetic fixtures verify transitions, blocked movement, reset, duplicate ordering, terminal/zero ordering, atomic rejection and retry, owned snapshots, and 512 independent-oracle/partition cases. Partition comparisons use binary-exact subdivisions. Arbitrary float displacement partitions inherit the existing clock's rounding and are not promised exact boundary equivalence.

The original-data probe resolves idle through the pinned human object/SAT/LAT selection chain, then walk/run through the accepted [animation bank](SKELETAL_ANIMATION_BANK_CONTRACT.md). Idle resolves to appearance/animation/all_b_idl_ambient_01.ans with scale 1; it is not guessed from a filename. Walk and run use displacement AuthoredSpeed/FrameRate on Z and time 1/FrameRate. Respectively 100 and 67 ticks cross three wraps and emit six ordered footsteps (walk frames 7/23; run 6/17). The extra tick accommodates float displacement rounding without introducing a snap. A subsequent blocked tick emits no movement footsteps.

These results confirm this modern implementation against synthetic fixtures and original decoded event records. Original scheduling, long-duration precision limits, generation exhaustion, and renderer integration remain separate questions. No research/function/protocol coverage denominator changes.
