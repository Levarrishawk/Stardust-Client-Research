# CREO4 ordered scalar and encumbrance composition

CreatureView4ScalarEncumbranceCodec (external historical reference) owns an ordered delta union of eleven accepted scalar fields and field2 encumbrances. CreatureView4ScalarEncumbranceState (external historical reference) applies that union atomically while retaining the complete fourteen-field [accepted baseline](CREATURE_VIEW4_BASELINE_AND_SCALARS_CONTRACT.md). Fields3/13 and unknown fields reject. This is a supported subset, not full CREO4 delta/world/gameplay support.

## Public API and immutable lifetime

CreatureView4ScalarEncumbranceUpdate has overloads taking the frozen CreatureView4Update or CreatureEncumbrancesView4Update, and exposes Index, nullable Scalar and nullable Encumbrance. Constructors preserve the frozen children's immutable values and hard shape limits. CreatureView4ScalarEncumbranceDelta takes ulong objectId, ushort declaredCount and an enumerable of union updates; it copies at most4096 nonnull updates in order. Neither source buffers nor update-array mutations can alter an owned plan.

Codec Decode accepts wire spans or a ReplicationEnvelope and explicit CreatureView4ScalarEncumbranceLimits; Encode/EncodeEnvelope accept the owned plan and limits. Baseline decode/encode remains the frozen CreatureView4Codec API. State.FromBaseline takes the complete frozen baseline, optional CreatureView4ScalarEncumbranceStateLimits and revisionSeed=0; Reseed requires the exact ulong recipient. Apply accepts a union plan and optional operation limits, returning Current, DeclaredCount, Events, WorkUsed and DecodedOutputBytes. State exposes complete Model, ObjectId, Revision and DecodedBytes. Nested limits are copied, and an operation override governs its returned state, matching the frozen child pattern.

The model keeps ten raw F32 words, full U64 listen ID, baseline header metadata, field2 vector/counter, ordered skill entries/counter with raw command/string bytes and prefix spelling, and ordered mission pairs/counter. No float arithmetic, finite eligibility, nine-stat clamp, key coalescing or map/set normalization occurs. Untouched skill/mission collection objects are retained by identity; scalar-only paths also retain the encumbrance object. All values remain immutable and successful/failed branches can be evaluated concurrently. There is no registry, owner callback, thread affinity, world publication, engine adapter or mutable store in this slice.

## Wire boundary

Use the frozen little-endian delta envelope: CREO tag4352454F, view4, U64 recipient, raw U16 declared metadata, followed by source-ordered fields. Supported scalar indices0/1/4/5/7/8/9/10/11/12 consume raw U32, and6 consumes raw U64. Field2 consumes U32 extent/counter and the [frozen encumbrance command grammar](CREATURE_ENCUMBRANCES_VIEW4_CONTRACT.md): opcode0 U16 index;1/2 U16 index+S32 value;3 U16 replacement count+that many S32 values;4 has no payload. Its cursor counts one per command plus replacement values, preserving final replacement overshoot. Declared metadata does not bound actual fields.

The entire bounded body is scanned before allocating update/command/value DTO collections. A bounded envelope field copy and small reader/meter objects are separate from this DTO preflight. Unsupported3/13, unknown opcode/field, truncated command/value or empty body rejects without returning a partial plan. Encode and Apply first measure every owned field/command/value, including extra/incomplete extent validation, before candidate mutation or output-buffer construction. Thus an already owned plan cannot bypass message budgets. Exact EOF is a modern strict boundary, consistent with the accepted codecs.

## Ordered mutation and publication

Apply validates full recipient/update count and complete message shape, checks the next ulong revision before candidate construction, and validates the starting complete baseline under the operation model policy. It then processes source order:

- A scalar uses the frozen complete scalar state to apply one assignment, preserving raw old/new bits and duplicate/equal assignment descriptions.
- At each field2 record, calculate the frozen wrapped skip once from that record's extent/incoming counter and the current vector counter. Every command is consumed and metered; a command whose original start cursor is below skip is ignored in full, including replacement payloads. Each admitted command delegates to the frozen kernel using a synthetic one-command record with local extent and incoming counter=`currentCounter+localExtent` modulo2^32, forcing skip zero there. This changes no original command/counter behavior; it prevents recalculating the original record skip at each child call.
- Before delegation, predict only count, summary cardinality and logical work from the frozen operation rule, check all complete-model capacities and reserve child work. The frozen kernel performs the actual list/equality/counter mutation. Its event count and WorkUsed must match prediction. An unexpected mismatch throws before returning a complete result.

Remove invalid index, equal set and empty clear are no-ops; sparse insert/set zero-fill; replacement increments1+replacementCount even for equal/empty replacement; mutation counters wrap exactly. Source field order and duplicate/interleaved writes remain observable through the resulting raw model and event order. All-skipped/zero-extent/no-op messages still advance the complete modern revision once. Child temporary revisions do not become public full revisions.

Only the completed full model/event array is returned. A late failure cannot leak earlier scalar/child candidates or mutate the previous full state. Earlier successful returned states likewise survive later failing Apply/Reseed calls. Reseed advances checked full revision, requires matching recipient and replaces the full baseline under retained policy. Revision overflow rejects; no wrap or implicit recovery is allowed. Baseline Model.DeclaredCount and change.DeclaredCount remain distinct raw metadata.

Scalar candidates retain the full baseline cost. No aggregate capacity is deferred until the final model.

## Events, construction output and exact work graph

CreatureView4ScalarEncumbranceEvent is a modern48-logical-byte description: Kind Assignment/EncumbranceMutation, Field, UpdateOrdinal, nullable Opcode/Index, nullable OldBits/NewBits and nullable OldValue/NewValue. Assignments carry raw bits; vector summaries carry the frozen opcode/index/S32 metadata. Replace/clear summaries omit index and scalar values. List order preserves all emitted summaries; UpdateOrdinal identifies the original mixed field. These are not legacy callbacks, clear per-item notifications or gameplay effects.

Returned output bytes=`fullStateBytes +48*eventCount`. Before each child call, the post-command complete state plus prior/all new48-byte descriptions must fit output/events. Separately, construction reserves the child's frozen24-byte summary against complete state and prior mapped48-byte descriptions. Remove/clear construction uses the pre-removal vector count; other commands use the predicted resulting count. The maximum of these phases is the fixture peak output. Frozen child capacity checks remain in force. Child/mapped phase charges do not sum all simultaneously live CLR objects; logical output is not heap/allocator accounting.

Apply work is reproducible from this operation graph:

1. Initial full seed work plus aggregate message work.
2. Each scalar: full seed work for its child seed, then the frozen one-assignment child work=`2*currentFullSeedWork+1`.
3. Each field2 record: current vector count for child seed. Skipped commands add no child work beyond aggregate message consumption.
4. Each admitted vector command: frozen single-command work=`oldCount+2+payloadValueCount+mutationWork+finalCount+emittedSummaryCount`. Mutation work is remove `oldCount-index`; insert `newCount-oldCount+max(0,oldCount-index)`; set `newCount-oldCount+1`; replace `oldCount+newCount`; clear `oldCount`; suppressed no-ops use0. Even admitted no-ops pay the frozen single-command scan/copy/finish charges.
5. Final complete seed work plus mapped event count before publishing full state/event-array output.

Child seed and predicted child Apply work are charged before child candidate allocation; the child independently enforces the reserved exact value. The final charge precedes final full-state/event-array construction. These are explicit modern logical charges, including repeated complete-baseline work for scalar children; they do not measure CPU, temporary wrapper count or allocator copying. Consequently, a baseline eligible to seed under a policy may require more work allowance for a composed operation.
