# Primitive offline completion snapshot

[TerrainOfflineSessionCompletion](../poc/Stardust.Core/Session/TerrainOfflineSessionCompletion.cs) exposes `Capture(TerrainOfflineSessionController controller, int maximumUpdates, bool finishRequested = false)`. It reads one actual controller State and that state's contained point/terrain result. Capture should occur before [configured owner](TERRAIN_CONFIGURED_OFFLINE_SESSION_CONTRACT.md) teardown. It changes no controller, driver, intent, row or clock and retains no controller/actor/world/query/terrain references. The private-constructor immutable result contains only an enum, integers, booleans, a string and one float.

Exact get-only fields: `Reason:TerrainOfflineCompletionReason`, `MaximumUpdates:int`, `CompletedUpdates:int`, `AttemptedUpdates:int`, `Stopped:bool`, `Faulted:bool`, `Mode:string`, `Speed:float`, `TargetActive:bool`, `FinishRequested:bool`. Reason enum values are BudgetCompleted0, FinishRequested1, Faulted2, Incomplete3. Ordinary System.Text.Json serialization writes the enum as its numeric value; callers may choose an enum converter. Mode is the actual defined point-mode name. Speed preserves the actual binary32 value. TargetActive derives from the contained point target reference, then becomes a primitive bool. FinishRequested records the supplied caller flag; it does not itself request or prove a stop.

| Actual snapshot | Reason |
| --- | --- |
| Actual controller/point/terrain fault, inactive terrain or unavailable/disposed point mode | Faulted |
| Nonfaulted, Stopped false, including pending finish intent | Incomplete |
| Valid actual stop, completed at supplied maximum, explicit finish flag false | BudgetCompleted |
| Valid actual stop below supplied maximum, or explicit finish flag true | FinishRequested |

Fault classification takes precedence over the caller finish flag and completion count. A stopped report requires at least one completed tick, actual Idle mode, exactly zero speed, no target and matching attempted/completed counts. Capture rejects an inconsistent stopped state rather than inventing a zero publication. It does not claim zero motion just because an incomplete snapshot has speed0. Completed and attempted values remain actual prefixes; a real edge fault may preserve completed1/attempted2 and nonzero prior speed.

Null controller rejects; supplied maximum must be1..6000. Controller-State owner/reentry guarding is inherited. Counts must agree between controller and contained point state, be nonnegative/bounded by the supplied maximum, have attempted>=completed and at most one unfinished attempt. Healthy attempted/completed counts must match. Mode must be a defined enum member, and speed must be finite in0..10. Invalid snapshots reject with InvalidDataException; invalid maximum rejects with ArgumentOutOfRangeException. The caller must supply the actual configured maximum: this API cannot prove hidden controller configuration, and a larger wrong maximum can change classification. It does not query an independently advanced exposed point driver; it captures the controller's last contained snapshot.

Captured results remain independent and freely readable/serializable after child/owner disposal. The controller's historical State also remains owner-readable after Dispose, so recapture returns the same historical values; it does not assert that disposed children are currently active. No borrowed diagnostic object is embedded. Original input/gameplay/lifecycle parity is unclaimed; this is modern offline reporting only.

[Native scenarios](../poc/Stardust.Core.SmokeTests/TerrainOfflineSessionCompletionScenarios.cs) and [independent before-native reference](../poc/round79-tests/Runtime/verify_completion.py) compare ten reports across five bounded cases: initial/incomplete, maximum3 normal stop, requested stop below maximum, real missing-destination fault with hold disabled, and a moving active target. Both explicit finish overrides and pending stop are covered. Independent Fraction-grounded binary32 speed and actual attempted/completed prefixes feed separate classification expectations. Native92 checks/23 negatives verify owner/null/bounds/too-small maximum, no capture side effects, primitive-only direct serialization, private/get-only shape and historical/borrower retention after owner disposal. All four enum reasons pass; fault remains1 completed/2 attempted. Undefined modes, nonfinite speed, negative/inconsistent synthetic internal counts and contradictory stopped internals are source-inspected guards; no reflection/injection corrupts frozen controller state. Final two focused builds have zero warnings/errors; no unrelated long corpus/default suite or host/GPU run is claimed. All frozen source/default profiles remain hash-identical.
