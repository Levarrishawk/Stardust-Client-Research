# Scene creature face completion and logical accounting

Round19 Runtime, 2026-10-02. Validation (external historical reference) extends the existing completion gate with the frozen `SceneCreatureResourceOptions.FaceInspection` policy. Accounting (external historical reference) measures owned inputs and synthetic outputs separately. These are modern consistency and queue-budget rules. They make no new claim about original client execution or physical memory consumption.

A null policy rejects any FaceBlueprints, FaceResources or GeneratedFaces. A non-null policy requires all three. Global CustomizationValues, blend/shape selection and material texture/normal/lighting extensions remain rejected. Authored palette and albedo checks remain unchanged: face inspection values do not globally recolor the body. Existing authored creature texture limit remains 32MiB.

Opt-in validation requires exact blueprint, renderer output and mesh-slot-MAIN binding closure from owned detail0 geometry. Slot indices and shader paths must agree; conflicting destinations reject. Generated.Values must contain exactly the blueprint's required variable-name/Boolean keys and equal every supplied policy value. Dependency maps contain exactly referenced face shaders, effects by shader, input DDS paths, palette paths and pixel programs. Each dependency has common source metadata; inline effects use their owning shader source. Common/nested source rules and existing root/appearance/animation pins still apply. Metadata trees are source-size bounded, with depth16/node16,384/child4,096 limits. This is closure over the supplied descriptors, not independent reconstruction of every encoded dependency.

Face limits are 16 blueprints, 64 shaders/effects/textures/palettes/programs, 256 slots/vertex arrays/render sets/prepare lists, 4,096 operations across blueprints and 4,096 binding traversal entries. Dimensions are at most1,024; the accepted compositor's per-blueprint1,024-triangle and33,554,432 bounding-box-test limits apply without pixel raster loops. Preparation reselects explicit texture/palette values using the existing pure helper. Programmable candidate/pass, blend/depth/stencil/factor tags, inherited sampler, MAIN/UV0, exact PSHP instruction tokens and register declarations must match the supported [composition policy](BLUEPRINT_FACE_COMPOSITION_CONTRACT.md). Face inputs retain valid declared mip shapes and supported color/alpha policies. Invalid index, malformed metadata or checked overflow rejects as InvalidDataException through the existing gate.

Generated outputs are RGBA32, unspecified color space, straight alpha, exactly one mip and exactly the corresponding blueprint dimensions/byte extent. Ordered layers match render shader/array, prepared source path and analytically derived triangle LOD choices. Write counts must be nonnegative and within triangle bounding-box work; each cumulative hash has SHA256 syntax. The last layer hash must equal the actual final RGBA bytes. Validation performs no I/O, decoder call, original program execution or full pixel recomposition. Intermediate cumulative hashes, exact write coverage and factor-to-pixel derivation cannot be attested from these DTOs alone; accepted readers/builders remain the provenance boundary. Internally consistent forged pixels or changed values accompanied by correspondingly forged metadata are outside this consistency gate. The independent original-byte oracle verifies actual composition separately.

`MaximumDecodedBytes` charges the checked sum of unique authored/face DDS bytes and generated face bytes. Authored and face inputs deduplicate by ordinal source path. Existing default/static repeated-path rules still require the exact same owned reference. A face input repeating an authored path may instead be a separate decode only if format, color space, alpha mode, every mip extent and every RGBA byte agree. Contradictory clones reject; this special case scans those repeated pixels. The original fixture has one such separately owned input. Distinct source paths retain the existing distinct charge even when references are shared. Thus the receipt is logical consumption; multiple equivalent allocations can exist.

Receipt fields `Sources`, `SourceBytes`, `DecodedTextures`, `Mips` and `DecodedTextureBytes` retain their source/input meanings. Appended get-only scalars `GeneratedFaces` and `GeneratedFaceBytes` default to zero. Generated outputs have no invented source paths and do not inflate input texture/mip counts. Output images deduplicate by exact image reference; aliases require identical ordered layer metadata and reject contradictory descriptions. Any generated image reference aliasing either authored or face input rejects, including a separate face decode suppressed by path dedup. Generated mip dimensions/byte lengths and all sums use checked arithmetic. `PendingWeight = SourceBytes + DecodedTextureBytes + GeneratedFaceBytes`. Geometry, animations, CLR/container overhead, heap, GPU and transient work are excluded. Accounting does not validate full face compatibility, freshness or source hashes.

Native scenario (external historical reference) uses the frozen descriptor reader with face flags and existing builder, then test-only reflection around the existing internal typed completion constructor. It depends on no unfinished reader/initializer changes. All archives close and borrowed source arrays clear before validation/accounting; owner and worker validation agree, source reads remain unchanged and descriptor fingerprints remain stable. The fixture tests exact decoded budget and one-byte-below rejection, default isolation, missing modules/keys/dependencies, bindings, output metadata/pixels/layers/LOD/hashes, aliases, overflow and cancellation-independent validation. Cancelled builder output is not published.
