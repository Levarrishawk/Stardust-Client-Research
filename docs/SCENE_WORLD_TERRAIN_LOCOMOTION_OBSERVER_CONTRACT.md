# Actual terrain displacement locomotion observer

[SceneWorldTerrainLocomotionObserver](../poc/Stardust.Core/Session/SceneWorldTerrainLocomotionObserver.cs) borrows an actual concrete terrain driver, current world and exact bound motion store. It owns a `LocomotionEventPreviewClock` built from caller-supplied idle/walk/run descriptors and `CompressedLocomotion` message sources. Caller must pair each descriptor/source from the same clip and supply a modern run threshold. It does not select original gameplay gait, advance the driver, publish motion, resolve assets or dispatch audio/effects.

Construct immediately after the actual driver exists, with configured step1,000..100,000 microseconds and maximum observations1..256 (default128). Initial actual healthy driver state and current issued local row must agree exactly in transform/speed, object identity and finalized typed uncontained incarnation. The store/world binding is proved through the frozen store API. **Driver association is an explicit caller construction contract:** public driver state does not expose exact bound world/store or step configuration. Matching public pose/object fields cannot prove those hidden identities; no reflection or new driver API is used.

Call `Advance(long exactDriverClock, CancellationToken token = default)` immediately after each actual configured single step. Owner/non-reentry/open/token/cap/current world/generation/root/incarnation checks precede owned-clock mutation. Actual driver must be active without fault/dropped/suspended time, speed in0..10, finite position components within±1,000,000, exactly one step and current clock exactly prior observer clock plus configured step. Current store row must be the actual issued local identity matching driver transform/speed, with null authoritative movement counter and revision exactly baseline+1. Native planar delta is binary32 subtraction of actual pose minus baseline, with Y ignored; elapsed is the exact integer clock difference divided by1,000,000. The frozen clock then classifies displacement/elapsed and advances phase/events atomically under its existing policy.

The motion-store revision counter is global. **Revision+1 is conservative serialized whole-store publication policy**, not proof of a hidden authoritative counter. Unrelated actor publication, extra local publication, reset or omitted correction creates a gap and rejects. No inference identifies the cause of that gap. Another motion-store writer is unsupported. Caller must serialize publication or explicitly reconstruct the observer at a valid local baseline when this bounded policy cannot continue.

Call `Rebase(SceneWorldObjectMotionSnapshot authoritative, long exactDriverClock, CancellationToken token = default)` after correction pump publication and before driver Advance. Require actual issued current authoritative identity for the same incarnation, movement counter present, revision newer than baseline, healthy unchanged driver clock equal observer/current supplied clock, finite bounded pose/speed and remaining observation capacity. A copied, stale, foreign, local or repeated row rejects. Rebase changes only baseline pose/revision; phase, events, observation budget, elapsed clock and generation remain unchanged. The next actual driver step adopts correction and observer counts only its physical planar displacement. Rebase after stepping cannot repair an omitted rebase; no teleport footsteps or phase rollback are fabricated.

`State` exposes immutable observation count, actual timestamp, baseline pose/revision, locomotion state, generation, unwrapped phase, generation seconds and completed cycles. `Advance` returns an immutable receipt with that state, actual driver/local-row references and actual owned event batch. `IsCurrent` checks observer identity and gait generation/current world, rather than latest-row identity or health; historical same-generation receipts may remain current. Gait switches advance generation under the frozen policy; historical batches remain owned and unchanged.

Active paused/idle zero ticks count observation/time and select idle, contributing zero accepted distance and no walking/run footsteps; supplied idle messages may still emit. Height changes do not enter planar distance. Run classification uses actual rounded accepted displacement/elapsed, not stored speed or a recovered run/walk getter. All checks precede clock Tick. Tick's preflight failure is atomic and can leave the already completed borrowed driver publication intact. No cancellation check or borrowed call follows successful Tick. Rare allocation failure after clock commit latches terminal observer fault, preserving the committed prefix without retry/rollback; this branch is source-inspected, without injection hooks. `Dispose` drops only observer references; borrowed driver/world/store survive and historical State/receipts remain readable.
