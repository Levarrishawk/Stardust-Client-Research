# Configured offline session owner

[TerrainConfiguredOfflineSession](../poc/Stardust.Core/Session/TerrainConfiguredOfflineSession.cs) owns one actual frozen point driver and its actual borrowed-driver session controller, initialized from an existing immutable [TerrainOfflinePlaygroundSettings](TERRAIN_OFFLINE_PLAYGROUND_SETTINGS_CONTRACT.md). It borrows world, motion store and ray query. It adds no movement, JSON, camera, engine or transport algorithm.

Constructor: `TerrainConfiguredOfflineSession(SceneWorldCoordinator world, SceneWorldObjectMotionStore motions, ulong objectId, TerrainModernPatchSetRayQuery rayQuery, TerrainOfflinePlaygroundSettings settings, long initialTimestampMicroseconds, float footOffset = 0, SceneWorldTerrainMotionLimits? terrainLimits = null, CancellationToken token = default)`.

Null world/store/query/settings and pre-cancellation reject before budget/driver creation. Settings have already passed their private-constructor validation. CreateBudget supplies exact settings update and successful-target capacities. The actual point constructor receives settings WalkSpeed, ArrivalRadius, StepMicroseconds, MaximumUpdates, MaximumClickAttempts, HoldMissingDestination, that actual budget, and caller initial timestamp/foot offset/terrain limits/token. The actual controller receives that same returned point driver, maximum updates and step. RunSpeed remains a caller-selected movement option; initialization starts at WalkSpeed. Click-attempt counting remains the input caller's responsibility, separate from successful-target capacity.

Owner-guarded `PointDriver`, `Controller`, `Settings`, `Budget` and `IsDisposed` getters return exact retained references/values. Callers can set point/manual/speed intent and advance the controller through their existing contracts. Their strict clocks, cancellation, world/incarnation, currentness, target provenance, foreign-progress and final-zero behavior are inherited. Sole serialized local-writer ownership still applies; independently advancing the point driver is detected by the controller and is unsupported ordinary use. This parent adds no intent forwarding or extra tick.

Dispose is owner-thread guarded, non-reentrant and idempotent. It marks the parent disposed, disposes controller first and point driver second, and attempts point disposal in a finally even if controller disposal throws. Historical getters remain owner-readable after disposal: the exact children are now disposed; immutable settings/budget, controller historical state and point destination receipt remain inspectable. It closes no borrowed world/store/query and removes no borrowed motion row. Disposal does not fabricate a final zero tick; callers should finish through Controller before disposal when a zero-speed row is required.

Constructor retains local ownership until both actual children and final cancellation checks succeed. On later failure it disposes the returned controller prefix before the returned point prefix. This cleanup never claims to reverse an initial publication or authoritative row. A throw inside an unreturned frozen child constructor retains its inherited cleanup/publication limitations. Cancellation after initial publication and allocation/late-construction failure are source-inspected branches without artificial injection hooks; pre-cancellation, actual initial grounding failure and admission failure are executed. Parent cleanup ordering is directly established by source; executed tests verify both children retire and histories/borrowers survive.

[Native tests](../poc/Stardust.Core.SmokeTests/TerrainConfiguredOfflineSessionScenarios.cs) and [independent before-native fixtures](../poc/round78-tests/Runtime/verify_configured.py) verify parsed maximum3/click32 settings, exact actual budgets,32 successful targets and unchanged rejection of the33rd, then two manual grounded steps and the actual final zero Idle stop. Fraction terrain and independent binary32 positions/speed plus integer clocks/counts compare exactly. Native94 checks/28 negatives cover pre-cancel, all null dependencies, invalid timestamp/object/foot/limits, owner constructor/getters/dispose, mismatched/stale world/store, actual missing initial ground retaining the existing row, external point progress/fault prefix, terminal/disposed children, repeated parent disposal and externally disposed-child cleanup. World/store/query and historical rows remain alive. One offline build has zero warnings/errors, with no native/numeric failures. All frozen production/default profiles stay hash-identical; no repeated114-case movement corpus, cadence or host/GPU run is claimed.
