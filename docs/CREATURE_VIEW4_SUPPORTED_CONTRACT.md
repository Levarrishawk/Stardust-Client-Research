# CREO4 supported ordered composition

[CreatureView4SupportedCodec](../../SWG-Godot-Client/poc/Stardust.Core/Protocol/CreatureView4SupportedCodec.cs) composes the eleven [scalar fields and encumbrances](CREATURE_VIEW4_SCALAR_ENCUMBRANCE_CONTRACT.md) with the reviewed [field3 skill map](CREATURE_SKILL_MODS_VIEW4_CONTRACT.md). [CreatureView4SupportedState](../../SWG-Godot-Client/poc/Stardust.Core/Protocol/CreatureView4SupportedState.cs) returns one immutable fourteen-field baseline model and ordered events. Field13 mission deltas remain unsupported. This is a modern bounded compatibility implementation, not evidence of original client callbacks, full CREO4 coverage or live interoperability.

## Public boundary

CreatureView4SupportedUpdate wraps a CreatureView4Update, CreatureEncumbrancesView4Update or CreatureSkillModsView4Update; Index and nullable Scalar, Encumbrance and Skill identify its branch. CreatureView4SupportedDelta owns an ordered collection of at most4096 updates, a full U64 ObjectId and raw U16 DeclaredCount. Decode accepts a wire span or ReplicationEnvelope; Encode and EncodeEnvelope accept that plan. CreatureView4SupportedLimits governs payload, fields, aggregate commands, vector values, per-key and total key bytes, decoded bytes and work.

CreatureView4SupportedStateLimits combines frozen CreatureView4StateLimits model policy with supported message policy. FromBaseline accepts the complete raw baseline and an optional revision seed; Reseed requires the same recipient. Apply accepts a supported delta and optional operation policy. The returned CreatureView4SupportedChange exposes Current, DeclaredCount, ordered Events, WorkUsed and DecodedOutputBytes. Current exposes Model, ObjectId, Revision and DecodedBytes. Policies and public collections are immutable copies. Each successful seed, reseed or whole Apply advances a checked U64 modern revision once, including no-op and counter-only messages. Overflow rejects before publication.

## Raw baseline versus runtime model

The frozen raw baseline decoder remains unchanged. It preserves ordered skill records, duplicate keys, raw command bytes and short/extended prefix spelling. Supported FromBaseline intentionally normalizes field3 into the frozen skill kernel's runtime map: unsigned byte-lexicographic key order, last duplicate pair wins, raw command0 and shortest legal name prefix. Binary names remain bytes, without decoding or case folding. Projected Model.SkillMods therefore represents runtime state; it is not a lossless copy of raw baseline records. Encumbrances, mission pair order/counter, full U64 listen ID, ten raw F32 words and baseline header metadata retain their frozen meanings. Mission pairs are not coalesced.

Raw input counts, all raw key bytes, per-key sizes and raw semantic allocation are bounded before map normalization. Duplicate collapse cannot evade seed limits. Scalar operations and skill changes preserve unrelated immutable collections; retained previous states and failing branches never mutate.

## Wire and complete-message preflight

The frozen little-endian CREO/view4 delta envelope contains U64 recipient and U16 declared metadata. Actual fields follow source order; declared metadata does not bound their count. Scalars consume the frozen U32 raw float words or field6 U64. Field2 retains the exact frozen extent cursor grammar, replacement overshoot and wrapped skip. Field3 consumes U32 extent/counter and exactly extent commands: opcode0/1/2, a U16 length or FFFF+U32 extended length, raw key bytes, S32 base and S32 bonus. Remove still consumes both pair words. Unknown fields, field13, map opcodes above2, truncation, invalid shape or trailing partial fields reject.

Decode scans the entire body before allocating update/command/value collections, then copies owned bytes. Encode measures the entire plan before its output buffer; Apply measures it before candidate mutation. Message counters are shared across both command families. Vector values count only field2 values; map keys have separate per-key and aggregate byte limits. For field bytes F, total commands C, vector values V, map commands M, key bytes K and fields N: payload=F+2, decoded=F+10+24*M, work=N+C+V+K. These are deterministic logical costs, not CLR heap measurements.

## Ordered application and capacity

Apply validates recipient, next revision, message shape and starting full model under the operation policy. Scalar/encumbrance records delegate to the frozen scalar/encumbrance state. Skill records delegate as whole records to the frozen skill kernel, preserving original wrapped skip calculation, skipped command consumption, mutation counter increments, unsigned final counter repair, equal upsert/missing remove no-ops and binary-key matching. Extent0 still permits final counter repair. Source update ordinals and event order survive interleaving. Child temporary revisions never become the public full revision.

Before child execution a bounded shadow predicts skill lookup/mutation work and full intermediate capacity, including pre-removal peaks. Actual mutation belongs to the frozen child kernel; predicted work, event cardinality and counter are checked against its result. Full model, event count, output and work limits include all retained encumbrance and mission values. No scalar candidate or earlier map mutation escapes a late failure. Only a completed model and event array are returned; no store, owner callbacks, engine state or world publication is added.

Supported DecodedBytes is semantic runtime storage: 72+4*encumbranceCount+16*missionCount+16*skillCount+skillKeyBytes. This differs from the frozen raw-wire skill entry accounting, which includes9 bytes plus the2/6-byte name prefix and key. Delegated scalar/encumbrance capacity adjusts that difference explicitly. Initial raw seed capacity uses the same semantic formula with every raw skill entry, before duplicate collapse.

Assignment and EncumbranceMutation descriptions cost48 logical bytes each. SkillMutation descriptions cost64+keyLength and expose opcode, immutable Name, old/new base/bonus as applicable. Events expose Kind, Field and UpdateOrdinal, plus nullable scalar/vector/map members. DecodedOutputBytes is final semantic state plus all mapped descriptions. Capacity separately admits child map command ownership (24 per command in decoded message accounting), child construction summaries (32+keyLength), and full mapped descriptions (64+keyLength). The modern full mapped pre-removal peak is intentionally stricter than a final-state-only check.

Let S(model)=14+all three collection counts+skill key bytes. Seed work is S(raw)+exact frozen child map seed work+S(normalized). Apply charges S(initial)+complete message work; each scalar/encumbrance child charges S(current) plus its frozen whole Apply work; each map child charges its exact frozen Apply work; completion charges S(final)+mapped event count. Lookup work, skipped/no-op records and final map projection remain metered. These reproducible logical costs bound accepted work; they do not claim exact instruction or allocation counts.
