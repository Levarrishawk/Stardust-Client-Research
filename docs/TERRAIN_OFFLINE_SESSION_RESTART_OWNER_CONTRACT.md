# Bounded serialized offline restart ownership

[TerrainOfflineSessionRestartOwner](../poc/Stardust.Core/Session/TerrainOfflineSessionRestartOwner.cs) owns at most one actual [configured session](TERRAIN_CONFIGURED_OFFLINE_SESSION_CONTRACT.md) at a time and retains the last accepted immutable [completion](TERRAIN_OFFLINE_SESSION_COMPLETION_CONTRACT.md). It adds no movement, terrain, engine, transport or automatic retry algorithm.

Exact API:

- `TerrainOfflineSessionRestartOwner(int maximumRuns = 8)`; range1..32 successful factory admissions.
- `TerrainConfiguredOfflineSession Start(Func<TerrainConfiguredOfflineSession> factory)`.
- `TerrainOfflineSessionCompletion Complete(bool finishRequested = false)`.
- `TerrainConfiguredOfflineSession Restart(Func<TerrainConfiguredOfflineSession> factory)`.
- `Dispose()`.
- Owner-guarded get-only `Active:TerrainConfiguredOfflineSession?`, `Generation:int`, `LastCompletion:TerrainOfflineSessionCompletion?`, `IsDisposed:bool`, `CleanupFaultType:string?`.

Start is allowed only before any successful admission and without an active run. A failed first factory can be retried explicitly through Start. Restart requires a prior accepted completion and no active owner; it is allowed after ordinary completion or actual fault. Successful admission increments Generation once; failures consume no successful-run slot and preserve previous Generation/LastCompletion. The limit is checked before invoking the factory. Repeating Start after a successful run, restarting while active, completing without active and exhausting the limit reject before factory/mutation. Getters remain owner-readable after disposal for historical inspection.

Factory results must be non-null, non-disposed, unadvanced, healthy owners on the calling owner thread. Point/controller counts must start at0, with no stopped/faulted/pending-stop controller state and matching actual initial clock. Pure actual target-admission validation checks current world/incarnation; an idempotent same-value controller SetPaused checks its open/healthy guard without intent or row mutation. Factory-provided initial point/manual/pause intent is not silently replaced. Factory association with world/store/query and responsibility for unreturned objects are caller contracts; this owner does not construct those borrowed dependencies or prove hidden associations.

Complete captures the actual controller report using active.Settings.MaximumUpdates and the supplied finish flag before teardown. Incomplete rejects without changing Active, Generation, LastCompletion or borrowed motion. A stopped/faulted accepted result becomes LastCompletion, Active becomes null, then the configured owner retires controller before point through its frozen Dispose. Generation counts admitted runs, including a run that subsequently faults; it never rewinds. A captured report survives teardown with honest attempted/completed prefix. The next factory begins only on a later explicit Restart after retirement; old children are never reset or revived.

Thrown/null/disposed/advanced/stale factory results leave Active null and retain prior history/counts. A returned rejected candidate is disposed; its initial publication is not rolled back. A factory that throws before returning remains responsible for any object it created but did not return. Each invocation performs one factory call, with no automatic retry. Cancellation can be expressed by a factory throwing or by the frozen configured constructor token; no extra cancellation API is introduced.

All methods and getters enforce thread affinity and non-reentry. A same-thread nested call, including a getter or Dispose, poisons the outer invocation even if the factory catches its rejection. A returned candidate is then retired without treating that already known poison as a new cleanup failure. No active owner or generation is published. Cleanly failed admission remains explicitly retryable.

If actual retirement throws, the returned prefix is privately retained and CleanupFaultType records the exception type. Active stays null; a previously captured completion and Generation stay visible. All later Start/Restart/Complete calls reject before another factory. Dispose marks the restart owner disposed and retires an active owner if any, but never silently retries or claims to repair a failed retirement. The caller must arrange cleanup of incorrectly associated thread-owned resources on their proper thread. Disposal of an incomplete active run produces no fabricated completion or zero tick. No borrowed world/store/query is disposed by this owner.

[Native scenarios](../poc/Stardust.Core.SmokeTests/TerrainOfflineSessionRestartOwnerScenarios.cs) and [independent before-native verifier](../poc/round80-tests/Runtime/verify_restart.py) pass129 checks/37 negatives. Three successive admissions with fresh actual incarnations and initial clocks0/100000/200000 yield two maximum3 budget stops separated by a real strict missing-ground fault (completed1/attempted2), then healthy third-run recovery. Seven exact successful binary32 grounded updates, integer clocks/generations and four primitive completion reports compare independently. Tests prove old children retire before the next factory, histories/borrowers survive, phase/cap rejection precedes factory, failed/null/stale/advanced/disposed-controller factories retire without publication rollback, caught getter/Dispose reentry poisons admission, and incomplete Complete/Dispose remain honest. An actual foreign-thread returned owner exercises retirement failure; the parent remains terminal and the fixture retires that owner on its original creator thread. Two focused builds have zero warnings/errors. No repeated whole-terrain/host/GPU/default suite is claimed; all frozen sources/profiles remain hash-identical. Rare allocation failure and same-thread child-disposal failure without hooks remain source-inspected.
