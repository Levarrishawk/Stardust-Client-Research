# Scene CREO6 full prepared store

[SceneCreatureView6FullReplicationStore](../../SWG-Godot-Client/poc/Stardust.Core/Session/SceneCreatureView6FullReplicationStore.cs) owns current complete CREO6 models and ordered metadata-only journals over a borrowed, serialized SceneObjectRegistry. It delegates to the frozen [complete kernel](CREATURE_VIEW6_FULL_CONTRACT.md), preserving all eighteen baseline fields and the complete ordered delta union. It is independent of the accepted [scalar/HAM store](SCENE_CREATURE_VIEW6_COMPOSITE_STORE_CONTRACT.md) and [world partition](SCENE_WORLD_CREATURE_VIEW6_COMPOSITE_CONTRACT.md). No world, networking, engine, target/resource resolver, original callback or gameplay integration is added here.

## Public API and identity

Constructor: `SceneCreatureView6FullReplicationStore(SceneObjectRegistry registry, SceneCreatureView6FullStoreLimits? limits = null, CreatureView6FullStateLimits? stateLimits = null, ulong revisionSeed = 0)`. Limits are validated and copied, including nested model/message records. Store limits bound actor count, retained logical state, pending events, events per apply, logical output and work. Defaults are 64 objects, 1MiB state, 4096 pending/per-apply events, 2MiB output and 1048576 work. Hard ceilings are4096 objects,128MiB state,262144 pending/per-apply events,256MiB output and16777216 work. State/output limits must be at least8 (complete empty models actually need108 bytes); event/work limits may be zero.

Public operations: Seed(handle, baseline), Apply(handle, exactExpectedSnapshot, plan), Find(handle), IsCurrent(snapshot), Revision, RetainedStateBytes, PendingEventCount, DrainEvents(), Acknowledge(batch), IsCurrentEvent(batch,index), Close()/Dispose(). Every operation requires the constructing managed thread; reentry throws. The host must serialize all borrowed registry mutations with these operations. No store method invokes a callback.

A snapshot exposes Handle, Incarnation, global store Revision, and immutable CreatureView6FullState State. Full baseline raw declared metadata, strings and prefix spelling, scalar bits, signed HAM values, full-width IDs, vectors, element ordering and counters remain represented in State.Model. Delta declared metadata belongs to the plan/kernel change and does not overwrite baseline metadata or add a second snapshot field. One valid whole plan advances one global store revision and one outer full-state revision, including valid skipped/no-op plans. Same-incarnation reseed advances the prior state revision; recreation starts state revision one while global store revision continues.

Seed requires an exact current registry handle and matching baseline ID. Apply additionally requires the exact stored snapshot reference issued by this store for the same current incarnation. Stale handles and foreign/superseded expected snapshots return null before plan access. Current identity plus wrong plan recipient throws. Same-incarnation handle changes preserve stored state: Find(newCurrentHandle) can return its historical-handle snapshot, whose store IsCurrent is false; Apply through the new current handle with that exact stored snapshot is allowed. World wrappers may separately use incarnation and exact underlying publication currentness, as in the accepted world pattern.

Find, IsCurrent, RetainedStateBytes and DrainEvents retire stale incarnations, preserving same-incarnation handle changes. Retirement prebuilds its map/totals and checked next epoch before assignments, invalidates issued batches and leaves global store revision and historical journal unchanged. Revision and PendingEventCount do not retire. Writes do not prune stale other actors, including on failure: actor capacity can remain occupied until explicit read-side retirement. Close clears owned map/journal/issued references, retains the last store revision, and leaves the borrowed registry open. Old caller-held snapshots and batches remain immutable values outside store retention.

## Genuine prepared publication seam

Internal APIs are Prepared, PrepareSeed, PrepareApply, CheckPrepared, CommitPrepared, ReleasePrepared, and IsCurrentBatch. Preparation owns the store gate until release. It constructs the complete immutable kernel result, replacement snapshot/map/journal, all logical totals and checked global revision/epoch before publishing anything. The candidate binds store, exact handle/incarnation, proposed revision/epoch and its active slot identity.

CheckPrepared requires owner thread, held gate, open store, exact candidate owner and active slot, unconsumed candidate, expected next revision/epoch and current registry handle/incarnation. CommitPrepared is prebuilt assignments only: entries, bytes, pending events, revision, epoch, issued invalidation and consumed marker. It is a trusted internal seam: the caller must successfully check immediately before commit, allow no intervening callback or registry mutation, and release in finally. Commit does not revalidate or allocate. These internal APIs are not exposed publicly for testing.

Release without commit cancels publication. Foreign, released, superseded or consumed candidates cannot pass a later check. Foreign/released release attempts do not clear another active slot. Reads, close or reentrant preparation while the gate is held reject. Stale/recreated/reset registry recipients fail check; cancellation publishes no prefix. Failed preparation, checked overflow, output/work/event exhaustion and late kernel rejection preserve prior published state, charge, global revision, queue and issued receipt. External registry mutation itself is not rolled back; later read retirement handles its stale map.

## Global accounting and frozen construction peaks

Each full event costs48 logical output bytes. Effective state capacity subtracts every other actor's retained model bytes. Effective output capacity subtracts those bytes plus48 times every already pending event. Remaining journal capacity and per-apply event capacity narrow the full kernel event limit. Candidate current/intermediate/final models and predicted mapped events must all fit before map/journal allocation and commit.

The frozen kernel also retains its exact narrower construction reservations: old child state plus24 per HAM event or32 per defender/wearable event, with untouched partitions and earlier full48 events reserved. The store neither widens those child limits nor invents an old-state-plus-new48 reservation. Exact generated output peaks include both final/full events and narrow child construction; long wearable removal/clear fixtures distinguish them.

Full kernel work includes initial full validation, whole message consumption, per-vector seed/copy, per-command child work and scalar seed/apply overhead. Store MaximumWork narrows both the model full-work ceiling and the separate message-consumption ceiling; the full work already includes message consumption and is not charged again by the store. Seed has its frozen baseline validation charge. Bounded map/journal copies, validation scans and wrapper overhead remain separate hard-bounded costs. State/output/work units are explicit logical policy, not total CLR heap, elapsed CPU, or lifetime accounting. Prior caller-held values and unrelated world partitions are not included.

## Journal ownership and delivery

SceneCreatureView6FullEventRecord contains Handle, Incarnation, StoreRevision and the complete full event value: Kind, Field, UpdateOrdinal, optional Opcode/Index, optional U64 OldId/NewId and optional S32 OldValue/NewValue. It retains no historical model, wearable customization, plan, resolver or callback reference.

Drain returns the same immutable issued SceneCreatureView6FullEventBatch until publication, retirement or acknowledgement invalidates it. The batch exposes StoreRevision and readonly Events. Acknowledge requires exact store owner/issued reference plus revision/epoch, clears the entire journal once, and rejects stale/foreign/repeated/closed receipts. Historical events survive destruction/recreation/reset until acknowledgement or close. Acknowledgement authorizes journal ownership only; it does not require a live recipient. Before explicit retirement, an issued historical receipt can still acknowledge even when registry currentness has changed.

IsCurrentEvent additionally requires an in-range index and current registry incarnation. It rejects old-incarnation delivery even when a historical batch can acknowledge. It does not require finalized phase or bind a separate world generation. A future world must add its owner/generation/phase guard and perform immediate delivery while remaining serialized. Same-incarnation handle changes do not alone make historical event recipients stale. No delivery occurs inside the store.
