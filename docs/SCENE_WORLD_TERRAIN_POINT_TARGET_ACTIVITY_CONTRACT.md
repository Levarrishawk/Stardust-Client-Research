# Point-target active pause intent

The [point-target driver](../poc/Stardust.Core/Session/SceneWorldTerrainPointTargetDriver.cs) adds explicit modern active zero-velocity ticking to the accepted [point-target contract](SCENE_WORLD_TERRAIN_POINT_TARGET_CONTRACT.md). Existing enum values Idle0, Moving1, Arrived2, Unavailable3, Faulted4 and Disposed5 are unchanged; Paused6 is appended. Default intent is unpaused and all unpaused APIs/numerical rules remain unchanged.

`SetPaused(bool value, long exactCurrentTimestampMicroseconds, CancellationToken token = default)` and owner-guarded `IsPaused` expose owned intent. Setter admission requires open/current world/store/incarnation, healthy operational mode, pre-cancellation, exact cached current driver-result clock and remaining update capacity. It checks cancellation again before changing intent. Stale, Unavailable, Faulted, disposed, wrong-thread, invalid-clock, pre-cancelled and exhausted-update cases leave intent/state unchanged. No target is admitted, so target count/cap is unchanged. Repeating a valid intent is allowed and does not consume updates.

The setter changes only the paused flag and owned Mode diagnostic. It never calls the owned driver, submits input, advances a clock, queries geometry or publishes/clears a motion row. Its frozen world/store currentness checks are read-only. On resume, Mode reflects the last actual driver-result pose: Idle for no target, otherwise Arrived/Moving by radius. Pending authoritative correction is adopted on the next actual update, according to the accepted policy.

Each next normal consecutive `AdvanceNext` while paused submits exactly zero velocity, runs one active grounded driver tick and publishes zero stored speed. Clocks and attempted/completed update budgets continue normally. This is not scheduler suspension, time freezing, backlog replay, prediction or an original gameplay pause. The first paused tick stops a previously moving row; the setter alone preserves its previous speed. Paused authoritative correction is admitted under existing finite/bounded rules, adopted by the actual driver and grounded during that zero-velocity tick. Its X/Z remains the authoritative X/Z.

Actual target receipt, hit/query identity, target revision and currency remain retained through pause/resume. Retargeting while paused replaces the target normally and keeps Mode Paused. Idle/no-target and already-arrived controllers also report Paused while intent is true and execute zero-velocity grounded ticks. Resume steers from the current eligible owned/authoritative pose during the next normal step. Sole local writer, immutable-selection retirement, constructor/publication-prefix limitations, final arrival stop and unproved frozen ray-emitter provenance are unchanged.

Inherited failures remain terminal: a bounded authoritative correction outside retained terrain may pass pose admission then fault actual grounding even while paused. That externally published correction row is not rolled back. Faulted/Unavailable setter calls do not clear retained intent; Dispose does clear it, retires only the owned driver, releases target/borrowed references and preserves borrowed dependencies/history. `IsPaused` is false after disposal, while attempts to set it reject.

[Focused native scenarios](../poc/Stardust.Core.SmokeTests/SceneWorldTerrainPointTargetPauseScenarios.cs) and an [independent reference](../poc/round66-tests/Runtime/verify_pause.py) compare71 exact binary32 pose/speed/orientation and integer-clock updates in five traces with15 paused ticks: moving pause for three steps, pause/correction/resume, paused retarget, idle and arrived. Native checks prove exact target retention, setter zero driver/store effects, first-tick zero speed, active grounding, owner thread, wrong clock/token, update cap, stale generation, closed store, faulted lifecycle and cleanup. Geometry height is independently Fraction-derived; expectations are not seeded from native output. Reentry and post-effect cancellation branches remain source-inspected/inherited because no production callback hook is added.

`ValidateTargetAdmission(long timestampMicroseconds, CancellationToken cancellation = default)` is the lead-authorized pre-pick admission API. It checks the actual owner/reentry/open/current incarnation, healthy mode, exact current clock, cancellation and remaining successful-target capacity before any surface query or target/store effects. A fresh healthy controller with no target passes. It shares the same private admission used by SubmitTarget; it does not reserve a target or consume a budget, so the adapter must keep selection/use serialized and revalidate at actual submission. Target-cap exhaustion is rejected before picking. Native tests prove read-only fresh admission, invalid clock/token, reduced cap and retired incarnation behavior.

Caught reentry sets an operation-local poison flag; guards check it before owned mutation commits and after attempted driver effects. This prevents a caught nested guard exception from allowing the active operation to finish successfully. No production driver callback exists, so poison control flow is source-inspected rather than dynamically forged. Focused final tests pass362 native checks including37 negatives; both the71-update pause reference and unchanged111-update Round65 regression pass. No unrelated large suite or Godot integration is claimed. Next probe: lead consumes pre-pick admission and pause/resume intent in the joined host with explicit selection retirement and final stop.
