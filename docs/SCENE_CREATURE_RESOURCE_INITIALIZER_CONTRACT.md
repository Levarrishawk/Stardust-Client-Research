# Bounded scene creature resource initialization

R6-RUNTIME-01 composes the accepted [scene registry](SCENE_OBJECT_REGISTRY_CONTRACT.md) and [creature resource reader](SCENE_CREATURE_RESOURCE_CONTRACT.md). This is a modern object-resource preparation barrier. It does not recover terrain, minimum-scene readiness, baseline field completeness, original asynchronous scheduling, or world/render publication predicates.

## Request and injected loader

SceneCreatureResourceRequest owns an immutable registry snapshot/create DTO, the already immutable ObjectTemplateCatalog, idle selection, exact walk/run bank, and resource limits. Construction copies dictionary entries and explicit route arrays into read-only containers, validates selection paths/pins/routes, and validates the create/catalog lookup. Mutation of supplied bank/routes after construction cannot affect a job. Construct requests under serialized access; concurrent mutation during copying is unsupported.

SceneCreatureResourceInitializer takes a registry, an injected Func(request, cancellationToken, Task<SceneCreatureResources>), maximumOutstandingJobs (default 8), and maximumObjects (default 64). Both limits are 1..4096. The loader is invoked on the owner thread and must promptly return its asynchronous task; use Task.Run for synchronous CPU/archive preparation. Loader closures must independently snapshot exposed mutable configuration such as roots, configuration bytes, resolver state and limits not carried by the request. Loader implementations must not access/mutate the registry or return prototype host objects. They own archive/resolver lifetime and must close it before completing the task. No publication callbacks are invoked.

## Owner, attempts and capacity

Start, Poll, Cancel, Find, IsCurrent, TrackedObjects and Dispose require the construction thread and reject reentrancy. Registry mutation remains the caller's responsibility on the same serialized owner. Loader completion/cleanup never accesses the registry. OutstandingJobs is a thread-safe observation of workers still retained by this initializer. The initializer introduces no locks around registry operations and does not mutate the registry.

Start(request, restart=false) verifies the exact current registry handle, snapshot phase/container/arrangement, and byte-identical create identity through the accepted codec, including signed zero. Foreign/stale/altered snapshots reject. A same-handle duplicate returns the existing ticket and does not invoke the loader, even after success, failure or cancellation. Changed configuration requires explicit restart. Completed tickets remain tracked as metadata; results are not cached or transferred twice.

Each real start creates a SceneCreatureResourceTicket with initializer GUID, registry handle and monotonically increasing attempt number. Explicit restart creates a distinct attempt even with the same handle. A new registry revision requires a new request and new attempt; old work is never retagged. Starting a revision/restart cancels prior jobs for that object only after capacity and allocation preflight. Capacity rejection leaves tickets, jobs and cancellation state unchanged. Synchronous loader exceptions or null tasks become tracked faulted tasks, consumed by Poll.

The outstanding budget includes running, completed-but-unpolled, cancelled and cancellation-ignoring workers. Restart/reset cannot move unfinished work into an unbounded retired collection. Capacity remains consumed until Poll observes completion or disposal cleanup completes. Current ticket metadata has a separate bounded object capacity. Stale metadata is pruned by Poll; no capacity recovery is hidden inside a failed Start. Find returns last-maintained metadata, not a freshness guarantee; IsCurrent(ticket) combines exact initializer attempt identity with registry.IsCurrent; it rejects superseded attempts even when their registry handle is unchanged.

## Poll, validation and transfer

Poll first prunes invalid handles and requests cancellation for stale/replaced attempts. Registry replace, changed containment, first end-baselines finalization, destroy, reset and close invalidate the old work through the accepted revision/generation rules. Idempotent registry operations retain their handle. Poll processes only completed tasks, without awaiting incomplete workers or depending on time/sleeps.

Every completed task yields one bounded owned completion record: ticket, Prepared/Faulted/Canceled/Stale, optional resources and optional error. Faulted task AggregateExceptions are observed, including cancelled/stale jobs. Stale status takes precedence; its error can still report a late fault. A successful cancelled job produces no resource transfer. Once consumed, the initializer drops task/result references, disposes cancellation state and releases its job slot. Subsequent Poll cannot repeat that completion. Retaining completion/results is the consumer's ownership choice.

Prepared requires an exact current handle/attempt, matching create bytes and recipe, plus a compact retained-descriptor check. Required checks include root and SAT source pins, bounded source accounting, skeleton/detail0 geometry/skin/LAT references, selected prepared idle, exactly walk/run with positive locomotion speeds and matching clip pins, and authored material/effect/texture/palette closure. Missing/null/inconsistent public result records produce Faulted with no resources. This check does not reparse bytes or independently prove every scalar/mesh/image invariant; the unchanged reader is responsible for decoded correctness. Caller-provided loaders must return owned data rather than borrowed mutable records.

Prepared establishes only that one object resource request passed this barrier. It does not set registry Finalized, modify SceneReady state, create engine instances or apply transforms. Before later publication, the consumer must recheck initializer.IsCurrent(ticket), since a revision can change after Poll transfers ownership.

## Cancellation and disposal

Cancel(ticket) only targets the matching tracked attempt with an outstanding job; foreign/missing/completed tickets return false. Cancellation does not release capacity early. Token callbacks should be prompt, avoid registry/initializer mutation and not block the owner; callback exceptions are caught and can appear on completion. Cancellation is cooperative, so a loader ignoring its token can remain outstanding indefinitely.

Dispose is owner-thread, idempotent and nonblocking. It closes future operations, clears ticket metadata, cancels all jobs and attaches at most the existing bounded job count of cleanup continuations. These continuations observe late faults, dispose cancellation sources and release references/counts without touching registry state or transferring results. DrainCompletion, meaningful after Dispose, completes when those cleanup continuations finish. It never makes an ignoring worker finish sooner. The caller must dispose when abandoning polling; there is no finalizer or global worker pool.

## Evidence and reproduction

Native tests use controllable TaskCompletionSource barriers and direct task waits, with no sleeps or race-based polling assumptions. They cover snapshot/bank/route ownership, exact signed-zero identity, foreign handles, duplicate/restart and one-shot transfer, outstanding/object capacity rollback, cancellation-ignoring late success, new-revision success before old-revision fault, all registry invalidations, malformed/null tasks/results and forged closure records, owner-thread/reentrancy rejection, and late success/fault/cancellation after disposal. Synthetic positive results use an independently authored tiny CKAT and managed descriptor closure, with no copied original bytes or rendering claim.

One real worker uses the accepted pinned human recipe and configured effective overlay through SceneCreatureResourceReader.Load. The actual injected task is the synchronization barrier; archives close before it completes. Owner Poll transfers 37 read-once sources / 4,683,848 source bytes and prepared idle/walk/run, preserving the synthetic create's raw identity. An independent Python source audit verifies all 37 effective hashes/sizes; a tampered export rejects. This static corpus evidence is separate from the synthetic packet and modern asynchronous policy.
