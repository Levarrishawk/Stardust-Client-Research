# Current-speed retained-terrain playback

SceneWorldCurrentSpeedTerrainPlayback (external historical reference) binds an actual [supplied current-speed composition](SCENE_WORLD_SUPPLIED_CURRENT_SPEED_PLAN_CONTRACT.md), its actual receipt, an actual world/motion store, and an actual immutable [retained terrain-set query](TERRAIN_MODERN_PATCH_SET_SURFACE_QUERY_CONTRACT.md). It constructs and owns one [terrain motion driver](SCENE_WORLD_TERRAIN_MOTION_CONTRACT.md) and one frozen [plan playback](SCENE_WORLD_CURRENT_SPEED_PLAN_PLAYBACK_CONTRACT.md). All behavior here is modern supplied-local policy; original movement units, floor/collision, physics, gameplay and full locomotion parity remain Unknown.

## Binding and admission

`Bind(world, motions, composition, source, surface, policy, initialTimestampMicroseconds, stepMicroseconds, footOffset = 0, terrainLimits = null, playbackLimits = null, cancellationToken = default)` returns null for an unavailable source or world/store binding. Policy must explicitly be `SuppliedLocalOnlyStoredSpeedOnWorldZ`. It never recalculates target/transition results, reloads readers, copies a plan, generates terrain, or builds another surface query. Supplied stored speeds may be signed: negative values move along negative native Z; driver state speed remains nonnegative planar magnitude.

Before constructing the owned driver it checks cancellation, policy, nonnegative initial time, step 1,000..100,000 microseconds, and the entire plan end time against signed-long overflow. It checks all frozen playback limits and full step/three-operation/output reservations, all terrain limits, complete retained-set patch/triangle reservations and query admission, and every stored speed for finite absolute value at most 10. Limits preserve the frozen hard ranges; playback output charge remains 512 bytes. Terrain foot offset must be finite within its supplied cap. The owned driver permits one step per update.

The approved internal `SceneWorldObjectMotionStore.IsBoundTo(candidate)` checks owner thread/reentry and the exact borrowed world reference while open. It neither prunes nor publishes nor alters rows. Closed and foreign empty stores therefore reject before initial publication; a valid empty same-world store is accepted. Numeric object ID, generation or incarnation equality alone is insufficient.

Binding also requires composition currency, matching generation, an active world, finalized current typed replication, the actual source target's exact Object and Placement references, and matching incarnation. An existing selected motion is read through the frozen store and must have finite nonnegative speed at most 10 before driver construction. This read may prune obsolete rows according to the existing store contract; it creates no local motion publication. The driver then adopts existing motion or create placement, validates finite bounded pose and grounded height/offset using the retained query, and performs its existing initial publication. These pose/height checks remain driver constructor preflight, rather than duplicate wrapper interpolation.

## Initial publication and failures

The actual driver constructor publishes initial grounded motion once. The wrapper then constructs playback, rechecks cancellation and source currency, and exposes the binding. A failure after initial publication preserves that row: there is no rollback. The catch path disposes every owned child that returned successfully and releases borrowed references. If the driver constructor throws before returning its reference, the wrapper cannot explicitly dispose that unreturned instance; it owns managed state and borrows external dependencies, and initial-publication effects are not reversed. Memory allocation failures are not claimed atomic. Stale-source null before construction and admission failures are distinct from this post-publication prefix.

## Playback, identities and retirement

World, Motions, Composition, Source, Surface, Driver and Playback expose the actual objects with owner-thread guards. The exposed owned children are for inspection; callers must serialize access and use the wrapper as the sole consumer. `AdvanceNext(submit, advance, token)` directly delegates exact one-step consumption to frozen playback. Receipts retain the actual source, actual plan step and actual driver result references. `IsCurrent` delegates source/receipt identity currency; it does not assert that a historical motion row is still latest. Motion-only authoritative corrections preserve composition currency and are adopted by the actual terrain driver at its next advance. Source replacement/retirement makes playback unavailable before submission; errors after attempted submission preserve the successful prefix and latch the frozen terminal fault.

`Retire` and `Dispose` dispose the owned playback and driver, release every wrapper dependency reference, and leave world, store, composition, source and retained terrain borrowed. Repeated disposal is harmless. A caller retaining a historical receipt retains its result. Immutable retained terrain has no retirement API: changing a caller variable does not invalidate the old query. A host retiring or replacing a terrain selection must explicitly retire this wrapper. Disposal does not clear motion rows. All wrapper operations reject a foreign thread and reentry; no external callbacks exist in wrapper control flow, so reentry prevention is source-inspected rather than exercised through a forged callback.

## Evidence and verification

Confirmed implementation observations: direct constructors/delegation and reference checks in the linked source; native separate-assembly scenarios (external historical reference); an independent reference runner (external historical reference) using sealed frozen62 input hashes before output. Synthetic authored profiles/received frames and four supplied terrain chunk recipes remain private fixture inputs. The independent rational plan, binary32 displacement/speed/pose and Fraction triangle-height calculations compare all 3,630 steps across 63 traces, including 60 sixty-step traces, negative motion, patch/chunk seams and authoritative correction. Height tolerance is absolute 1e-9/relative 2e-11; published binary32 position, speed, orientation and time compare exactly. Actual child/source/row/result identities are checked natively.

Admission tests include exact and one-less caps, pre-cancellation, invalid clock and overflow, speed above 10 preserving the prior row, owner thread, closed/foreign empty stores, foreign world with equal numeric identifiers, valid empty store, source replacement/retirement, motion-only updates, borrowed survival, and late outside-terrain terminal failure preserving the accepted result/publication prefix. Existing frozen playback/driver tests supply their own deeper scheduler/reentry/error coverage; no injected callback or original-client execution is claimed here.

Compatibility consequence: a host can consume an already-current supplied plan against one proven native world/store incarnation and retained terrain without recomputation.
