Round34, 2026-10-03. This is an engine-neutral composition of the accepted [complete baseline/scalar codec](CREATURE_VIEW6_CODEC_CONTRACT.md), [scalar state/store contract](SCENE_CREATURE_VIEW6_STORE_CONTRACT.md), and [HAM specialization](CREATURE_HAM_VIEW6_CONTRACT.md). ## Accepted boundary

CreatureView6CompositeCodec (external historical reference) accepts a nonempty Delta CREO/view6 ordered union: scalar/string/pair indices0,2–12,16–17 and HAM/max-HAM13–14. Defender1, wearable15, unknown fields/opcodes, incomplete bodies and impossible typed command extents reject. The baseline decoder remains the frozen complete decoder. All integer wire fields are little endian; index12 retains raw U32 bits and projects to S32 in the model. String content is owned opaque bytes, preserving short versus extended length spelling. Pair7 preserves both U64 words. Raw U16 declared count is metadata, independent of actual parsed field count; repeated fields and their order remain exact.

Each HAM field retains its own extent/counter and accepted command grammar. An assignment consumes its complete U16-length S32 sequence, even when its cursor overshoots extent or crosses a skipped interval. Unsigned skip and counter wrap, duplicate/equal/invalid-index/empty-clear behavior, zero growth and repeated-field reconciliation are exactly delegated to the frozen HAM kernel. No union regrouping or fabricated counter resynchronization occurs.

Decode first scans the complete message without allocating field/command/value/string models, then constructs owned immutable models under the same caps. The generic bounded envelope owns its field copy before that scan. Encode and Apply measure the complete typed message before stream/candidate allocation. Constructors independently bound/freeze caller collections; those already-existing DTO allocations are outside Apply preflight.

## Full model and publication

CreatureView6CompositeState (external historical reference) owns one immutable complete `CreatureView6Baseline Model`, checked U64 branch revision and logical `DecodedBytes`. Seed/reseed use the accepted full-model validator. Seed advances revision seed by one; reseed requires the same ObjectId and advances once. Apply requires the matching recipient, processes each union update in order and advances the outer revision exactly once, including wholly skipped/no-op HAM plans. Independent immutable branches can be used across threads; this API supplies no current-incarnation identity or world transaction.

The scalar adapter delegates each assignment to `CreatureView6State.Apply`. The HAM adapter creates one private two-vector seed per plan and reuses its current state across interleaved scalar updates. After each HAM update, a fresh full model combines the resulting vectors/counters with the current scalar fields and untouched defender/wearable references. Baseline declared metadata remains the baseline value. Neither state nor receipt retains an original seed-model property or an overwritten scalar-string root. Immutable untouched objects can be safely shared. The receipt contains only Current, raw delta metadata, ordered events and WorkUsed. Temporary child receipts and candidates are not published. Any late rejection leaves the input state and earlier successful results unchanged.

Modern events are descriptions, with fields Kind, Field, UpdateOrdinal, nullable Opcode/ElementIndex/OldValue/NewValue. Each scalar assignment emits one Assignment, even if equal. Each actual HAM mutation maps one frozen kernel event to HamMutation at its containing union ordinal; ignored commands emit none. These events neither execute nor claim to reproduce original callbacks, owner accumulators, presentation or gameplay effects.

## Global budgets and adapters

Message limits apply to the entire union, including overwritten strings and skipped command values. Payload is opaque field bytes plus two metadata bytes; decoded logical bytes are field bytes plus ten for ObjectId and metadata. Fields, actual HAM commands, aggregate S32 values, per-string content and aggregate string content all have independent caps. Message work is fields + commands + values + string content bytes. Defaults are 1MiB payload,256 fields,65536 per-string bytes,262144 aggregate string bytes,4096 commands,65536 values,2MiB decoded bytes and1048576 work units. Corresponding hard ceilings are8MiB,4096,1MiB,4MiB,65536,1048576,16MiB and16777216. Two-pass scans use the same logical budget each pass; work is not elapsed CPU or allocation accounting.

Full-model limits reuse `CreatureView6StateLimits`: update count, per/aggregate strings, per-vector and all-four-vector elements, state bytes, event count, output bytes and work. The complete initial model and every intermediate candidate must fit. State bytes are102 +8*defenders +4*HAM +4*maxHAM +16*wearables + encoded length prefixes/content for all three scalar strings and every wearable customization. Output adds24 per composite event. Untouched defenders, wearables, their counters and customization bytes are included. Current state uses only current string roots; replaced content is not accumulated in state charge. The message budget still counts all string assignments.

For HAM calls, the adapter reserves all non-HAM state bytes/elements and already-produced composite events from the child caps. The combined HAM ceiling is the remaining full-model element allowance, capped at131072. The child receives remaining work and event allowance. This checks growth before later shrink and retains the accepted conservative pre-remove/pre-clear prospective-event capacity. For scalar calls, the adapter reserves prior events and subtracts sixteen additional output bytes to translate the frozen eight-byte scalar event to the composite twenty-four-byte event. Each child result is checked again against the full publication limits.

State WorkUsed is one initial HAM seed-copy charge (old HAM + maxHAM elements, only when the plan contains HAM), plus the sum of frozen scalar Apply work and frozen HAM Apply WorkUsed for each ordered update. Scalar work is19 + resulting full-model element count + resulting string content bytes per assignment. Frozen HAM work already charges its initial/final two-vector copies, field/command/value consumption and mutation costs; these are not charged a second time by the adapter. Full-model validation scans, wrapper objects, event mapping and defensive copies have additional bounded overhead under existing hard ceilings. This is an explicit logical policy, not a measured heap/CPU ceiling. Whole-message work and state work are separately enforced and never presented as one denominator.

Operation policies replace retained policies and become the successful result's policy. FromBaseline has its own accepted seed-work charge18 + full elements + string content. Apply initial validation uses the fixed hard validation-work ceiling rather than mistakenly charging that seed-work amount again to the operation's logical work. Checked arithmetic and revision overflow reject.
