Namespace `Stardust.Core.Session`; source ReplacementClientApplication (external historical reference). Minimum provider signature is `Func<CmdStartSceneMessage,ProceduralTerrainInput,Func<string,TreLookupResult>,CancellationToken,Task>`.

The owner exposes borrowed Session, World, Motions and Run until finalization. Profile and Creature are historical preparation metadata. StartLogin, Authenticate, SelectCharacter, Tick and BeginDisconnect delegate to accepted owners. Selection takes object ID, zone connection ID and caller time; the application obtains the explicit zone port from its factory. No selection or credentials are inferred. ToString contains only closing/finalized flags. All observations and mutations require the creating thread; mutation reentry rejects.

Installation preparation completes before a factory port is requested. The application creates the creature-only world and original-overlay resource loader, motion store, session, pump and run. Existing run validation admits root policy; therefore an invalid root policy can fail after a factory port has returned. Startup exposes no application services, starts no selection, resource jobs or minimum provider, and never invokes a world Poll. These invariants allow thread-affine owners and original inputs to roll back on the construction thread while port disposal finishes asynchronously.

Each successfully returned factory port becomes application-owned immediately, wrapped with idempotent disposal. An admitted wrapper is borrowed/retired by the pump; an unadmitted returned zone wrapper is still retired by the application. Reusing the underlying login port as zone rejects without a second underlying DisposeAsync. The factory owns any resource it creates but does not return when it throws. Null factory results reject. Pinned login port must match options.Port; with an explicit endpointApproval, login correspondence rejects before preparation/acquisition and selected galaxy/advertised zone correspondence rejects before the zone factory. Read-only selection preflight shares the existing session grammar; mismatch preserves the active login prefix. See [endpoint approval](REPLACEMENT_ENDPOINT_APPROVAL_CONTRACT.md). Without the optional policy, existing injected callers retain their prior admission behavior.

Argument/null peer preflight errors precede acquisition. Failures inside prepared startup throw nested `StartupFailure` exposing a redacted FailureType and `RollbackCompletion`. The caller must await that task: pending/faulted returned-port rollback is observable and never silently claimed successful. No continuation disposes thread-affine owners. Default tests prove invalid-policy post-acquisition rollback with delayed/faulted port disposal and exclusive archive reopening; no test-only failure seam exists.

Decoder retains TGEN without evaluation. The explicit minimum provider receives that decoded owned PTAT and a guarded resolver, not global paths or credentials. Every resolver call checks cancellation and a retirement flag under the archive lookup gate. Retained resolvers reject after close; a lookup already in progress must finish before finalization acquires the gate. BeginClose never waits for that gate, and TryFinalizeClose uses TryEnter so owner-thread polling does not block on an outstanding lookup. Provider/resource tasks are also tracked directly, retaining late faults even when an underlying retirement helper observes and suppresses them. Provider callbacks must obey existing owner constraints; caught Tick/close reentry leaves the healthy outer prefix unchanged.

## Close, drain and finalization

BeginClose(Task presentationCompletion) binds the exact caller-supplied presentation task, sets retirement, cancels owned run/minimum work, retires pump/all acquired ports, and closes world/session. Dispose starts that same nonblocking retirement without inventing a presentation-completion claim. Motion/preparation remain retained. Duplicate retirement is idempotent; a different presentation task rejects once one is bound.

TryFinalizeClose(Task presentationCompletion) binds that exact observation, starts retirement if needed and returns false while any run/world/port/resource/minimum/presentation task is incomplete or the lookup gate is busy. Provider/resource task cancellation after retirement is expected completion and does not fault the drain. Their genuine faults remain observable. Port/presentation cancellation and completed faults remain cleanup observations. After all borrowers complete, finalization records aggregate inner failure types once under the gate and attempts motion/session/preparation disposal on the owner thread. It returns true/IsFinalized even after faulted retirement, allowing safe installation release rather than waiting forever for success. CleanupFailures records failures separately; IsFinalized means finalization was attempted, not that every cleanup action succeeded. Repeated finalization never duplicates the same completed drain observation.

DrainCompletion aggregates current drains plus direct minimum/resource tasks, wrapper disposal, supplied presentation and synchronous cleanup failures. It can be complete before presentation is supplied; that does not authorize finalization. Caller must stop presentation, provide its real completion task, continue owner-thread TryFinalizeClose polling, and observe failures. Runtime run failure starts retirement; existing argument/clock/disconnect preflight rejection without a failed run preserves the active flow. Endpoint policy preflight rejects before acquisition and preserves the healthy application. A failed zone factory/admission retires the whole application and every returned wrapper.
