# Explicit controlled launch and one attempt

Round92 supplies [ReplacementControlledLaunch](../../SWG-Godot-Client/poc/Stardust.Core/Configuration/ReplacementControlledLaunch.cs) and [ReplacementControlledAttempt](../../SWG-Godot-Client/poc/Stardust.Core/Session/ReplacementControlledAttempt.cs). They prepare inputs and report bounded typed observations; they perform no DNS/socket construction, server contact, resource loading or cleanup. Configuration assertions do not authorize contact or establish scenario truth. The [endpoint approval](REPLACEMENT_ENDPOINT_APPROVAL_CONTRACT.md), [controlled plan](CONTROLLED_SERVER_VALIDATION_PLAN.md) and actual [application drain](REPLACEMENT_CLIENT_APPLICATION_CONTRACT.md) remain separate boundaries.

## Strict Version1 configuration

`ReplacementControlledLaunchCodec.Decode(ReadOnlySpan<byte>)` is the only public construction path. Total input is1..131072 bytes of strict UTF8 JSON with depth<=12, no comments/trailing commas. Root requires exactly Version1, Profile, ClientVersion, Login, Zone, GalaxyId, ApprovedCharacterId, LoginConnectionId, ZoneConnectionId, PhaseBudgetMilliseconds, OverallBudgetMilliseconds, DisconnectTimeoutMilliseconds and MinimumReadinessApproved. Only MovementPrerequisites is optional. Duplicate, unknown or missing properties reject at every supported object, including the nested original profile. No credential/password/token/character-name fields exist; unknown additions reject. Codec errors are redacted, without raw parser payloads.

Profile is the nested existing [strict original launch profile](REPLACEMENT_LAUNCH_PROFILE_CONTRACT.md), retaining its65,536-byte/depth8/path/route validation. Codec reads no file and invents no installation defaults or historical fixture arguments. ClientVersion is explicit nonempty ASCII, <=256 characters. Login and Zone each require exact Hostname:string, Ipv4Address:U32, Port:nonzero U16, validated by immutable approved mapping. Numeric IDs are JSON unsigned integer values; ApprovedCharacterId is nonzero U64; connection IDs are distinct U32. GalaxyId is explicit U32. The produced endpoint policy always includes the same approved character before zone acquisition.

PhaseBudgetMilliseconds is1..30000; OverallBudgetMilliseconds is1..120000 and at least the phase budget; DisconnectTimeoutMilliseconds is1..30000. Values are required, not hidden defaults. Existing transport deadlines can reject earlier; these whole-attempt/phase limits supplement them, including credential and character-selection waits. MinimumReadinessApproved must explicitly be true for a future controlled bootstrap. It is an operator-approved bounded minimum scenario, not proof that PTAT/full terrain, local floor, server validated position or a particular character is ready.

Optional MovementPrerequisites requires exactly boolean FreshStampZero, MatchingValidatedPosition, MovementPrerequisitesValidated. All true yields the accepted three-root MovementScenario for the approved character. Absence or any false disables movement. A null/partial/incorrectly typed object rejects. No received readiness can silently enable movement. Getters expose Profile, Options, LoginPeer, ZonePeer, EndpointApproval, approved character/connection IDs, budgets, minimum approval and optional movement scenario. Launch has no public unvalidated constructor; ToString says only configured. Endpoint/character configuration should not be included in saved diagnostics.

## Typed observation budget

Construct `ReplacementControlledAttempt(long phaseBudgetMilliseconds,long overallBudgetMilliseconds)` with the same explicit bounds. Call Start once at the actual user StartLogin timestamp. The guard cannot restart after completion/stop. It neither starts login nor rebases overall origin on a phase change. Observe takes nonnegative monotonic caller time, `ReplacementControlledAttemptObservation(Phase,ClientReadySubmitted,ServerReadyReceived,VisiblePlayer,Faulted=false,Closing=false)` and optional cancellation token. Owner-thread/no-reentry guards apply; invalid clock rejects before consuming time or state. It does not read an implicit wall clock or accept names/traffic/raw exceptions.

State contains Started, typed Stage, typed StopReason, elapsed overall and phase milliseconds. Stages are NotStarted, LoginHandshake, Credentials, LoginResponses, CharacterSelection, ZoneHandshake, ZonePermissions, SceneReadiness, PlayerPublication, Active. Typed transitions contain only stage/elapsed time and are bounded by strictly increasing stage progression (at most nine records). Observations before Start reject. Selected phase stays SceneReadiness until both client-ready and received server-ready; client-ready alone does not reset that timer. Server-ready advances to PlayerPublication; actual visible player advances to Active. The adapter supplies true observations; the guard cannot establish or manufacture those states. Readiness booleans outside Selected, server-ready without client-ready, visible without server-ready, Offline/unsupported phase or backward stage stop InvalidObservation. Skipped forward observations are allowed because adapters may miss intermediate ticks; they are not independent proof of the skipped work.

Exact elapsed>=budget stops, checked **before** a same-tick transition can reset a phase deadline. OverallTimeout takes priority over PhaseTimeout when both expire. Cancellation, Faulted and Closing observations take priority before deadline evaluation. Other reasons are None and InvalidObservation. Active remains within both budgets; there is no automatic successful attempt outcome from local visibility or movement. A stopped State freezes its historical elapsed/phase prefix; later valid observations preserve it. Transitions and State are owner-thread observations; copies cannot mutate the guard.

## Retirement and evidence

Timeout/other stop reports a typed reason for the engine adapter to request bounded disconnect when legal, then retire presentation/application. The guard never releases owners or decides async work has drained. Cleanup must retain actual borrowers and be observed separately even after budgets expire; a deadline cannot force resource free or falsely imply successful local/server cleanup. Actual-session tests leave a stalled CharacterList/login/credential intact after guard timeout until the caller explicitly closes and drains it.
