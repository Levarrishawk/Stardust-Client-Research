# Independent configured playground transport generations

transport_fixtures.py (external historical reference) is an importable Python fixture producer and verifier for frozen configured Version13. It reuses the isolated Round14 independent encoder (external historical reference); it does not import production codecs, sibling Round81 work, or run a socket. These are authored synthetic identities, not live authentication or server session semantics.

## Producer API

`reseed(profile: dict, connection_id: int, seed: int) -> dict` deep-copies the profile. Both numbers require exact Python integers in0..4294967295; Boolean, floating, negative and oversized values reject. Admission requires Version13/`SuppliedConfiguredOfflinePlayground`, bounded16384-byte JSON, exact frozen SOE field set, CRC2/max496, explicit Boolean offline flags, bounded explicit settings and matching adapter bits. This is transport-fixture admission; the host still validates its complete behavior policy.

Every inherited protected field is authenticated with the source seed before regeneration: two correction reliable-data frames (sequence0/1), their ACKs, disconnect, outer Multi and outer ACK. Correction/root application bytes and object identity are preserved. The outer Multi retains reliable prefix sequence2/application, disconnect reason6 and reliable suffix sequence3/same prefix application; only its disconnect connection identity and protection change. `InvalidDisconnectConnection` preserves its explicit XOR1 negative policy. Incorrect CRC, marker, packet structure, ACK sequence, correction counter or outer children reject. No inherited protected field remains under the old seed. An unknown added SOE field rejects rather than silently remaining stale.

Version13 has no profile handshake or outbound ACK arrays: its existing native owner creates these at runtime. `handshakes(profile) -> {RequestHex, ResponseHex}` independently returns request14 bytes (opcode1, protocol2, connection U32BE, max496) and response17 bytes (opcode2, connection, seed U32BE, CRC2/selectors1+4/max496). Adding obsolete `SoeRequestHex`/`SoeResponseHex` fields rejects. Each `encoder(seed)` loads isolated globals, so generation does not alter another imported oracle's seed. `verify_runs` requires distinct connection IDs and seeds across its supplied generations; reseed itself permits round-trip regeneration to an earlier configuration.

## Before-native motion and log verification

`expect_motion(profile, samples) -> {Cadence, Frames, Completion}` takes independently authored rows `{Native: [x,y,z], Quaternion: [x,y,z,w], Speed: number}`. Samples are finite, bounded by configured updates, converted to binary32 and spaced exactly10000us. It independently computes100000us changed-pose/speed admission, immediate moving-to-stopped admission and1000000us stationary heartbeat, modular counter/timestamp, canonical62-byte C2S root, reliable channel0 sequence0 onward and protected ACKs. The fixed dedicated healthy drain has no backlog. Supply a verified independent movement/orientation oracle for full moving runs; do not populate these samples from native logs.

`verify_runs(segments, profiles, expectations) -> receipt` accepts1..32 full per-child log strings and matching profiles. Each expectation is `{Transport: expect_motion(...), Runtime: exact independently authored offline_completion_summary dict}`. Author/save expectations before launching native code. It checks exactly one actual bootstrap record, every cadence row, exact application/protected-data/ACK bytes, sequence, per-drain empty buffers, exact primitive completion, strict runtime completed/attempted prefix, and closed empty transport cleanup. The actual frozen record is named `soe_root_transport_ready`; there is no frozen `soe_root_bootstrap` record. Receipt `Generation` is the supplied segment ordinal, not a claimed native world incarnation.

Runtime terrain failure remains distinct from root failure: a failure after N completed updates requires runtime Reason Faulted, Faulted true and AttemptedUpdates N+1, while the root summary may remain healthy/CleanDrain with N samples and empty buffers. This verifier supports that actual strict failure boundary. It deliberately rejects root-session failure/nonempty FIFO, interleaved segments, missing/duplicate bootstrap and unverified extra roots. It verifies transport evidence, not GPU/input/reset behavior or whole-log diagnostic admission; the lead retains its independent full behavior verifier and diagnostic policy.

`verify_transport_only(segments, profiles, expected_runtime, expected_queue_steps)` supports the lead's existing independent movement model, whose quaternion/position comparisons have bounded float tolerances. Supply pre-native exact runtime dictionaries and zero-based sorted unique queue-step lists (one per child). This API validates root header/object/flags/counter/timestamp/finite fields and uses each actual62-byte application as **borrowed serialization input** to the independent encoder. It checks exact protected frame/ACK, handshake, sequence0/counts, independently scheduled cadence, healthy root completion and cleanup. It does not generate expected movement from native output: the lead must separately validate every application against its independent trajectory/heading and issued row. Receipt explicitly records `NativeApplicationBorrowedSerializationInput=true`, `ExpectedMovementGenerated=false`, and `RequiresSeparateMovementOracle=true`. The existing exact `expect_motion`/`verify_runs` oracle stays separate.
