# Interior accepted-movement event diagnostics

R5-RUNTIME-01 adds optional modern diagnostics to the existing original full interior route. Launcher SceneCharacterEvents emits --scene-character-events. It requires the pinned interior specification, actor/character, geometry, idle selection and owned walk/run locomotion profile. Cancellation and other inspector routes cannot combine with it. Launcher rejection happens before path resolution or engine launch; raw interior validation happens before specification/asset reads. Default flags, existing locomotion classification/state, pose/crossfade, actor owner, camera and lighting policy remain unchanged.

The existing scene TickScene first resolves collision, then passes next.WorldPosition minus previous.WorldPosition and that accepted tick's seconds to the [Round 4 event clock](LOCOMOTION_EVENT_PREVIEW_CONTRACT.md). The existing LocomotionPreviewClock still drives presentation. Every opt-in event tick compares its state with that authoritative clock. Neither render delta nor intended input advances the event cursor. Automatic host pause/focus boundaries discard elapsed movement; inactive animation ticks return no events. The opt-in manual controls also hold while simulation is paused. Blocked planar movement selects idle and clears moving history. Gait changes, actor reset and building-owner changes start new event generations; no prior-generation history is published.

LocomotionEventDiagnosticLog binds to one clock owner and allocates a fixed ring (default 128, permitted 1..4096; interior uses 16). It follows the tested [R3 diagnostic policy](ANIMATION_EVENT_DIAGNOSTIC_PREVIEW_CONTRACT.md), reusing the immutable record type while leaving the elapsed-playback log unchanged. Strict ordering is (Cycle, Frame, GroupIndex, OccurrenceIndex). A single frontier rejects replay/backward delivery; there is no growing identity set. Deliver preflights the entire batch and counter capacity before changing ring/frontier/totals. Foreign, stale, empty and repeated batches reject atomically, including when a new generation is pending.

Recent returns an owned read-only oldest-to-newest snapshot. ClearRecent removes display history while retaining the delivery frontier and counts. SynchronizeGeneration clears current history/frontier and per-generation count only when the bound clock's generation changes; lifetime DeliveredTotal persists. Valid nonempty delivery also synchronizes automatically. The adapter explicitly synchronizes on empty switch/reset ticks and skips empty delivery. Disabled diagnostics continue to track the accepted locomotion clock and synchronize epochs, but discard delivery; enabling does not catch up discarded events. These totals count diagnostic delivery, not all generated events.

The scroll panel shows mode, frame, generation, current-generation total, lifetime total, and the last 16 authored names/frames/cycles. Controls enable delivery and clear display history. Names cause no audio/effect dispatch. No root movement, new physics, graph execution, mesh/shader policy, or crossfade event weighting is introduced. Events follow the selected modern target gait; original scheduling and crossfade event timing remain Unknown.

The helper consumes already-owned prepared idle/walk/run data. It introduces no resolver/file reads, texture creation or mesh recreation. Main's existing exit hook disposes the helper before scene resources: ring history clears and clock/log/UI references drop. Repeated disposal is harmless; subsequent owner access rejects. Serialized main-thread ownership is required.

Native tests cover capacities 1/3/4096, duplicate authored identities, 2000 ticks per capacity, immutable snapshots, clear/reset/switch lifetime counts, automatic synchronization, and atomic foreign/stale/empty/replay/backward rejection. Original headless tests resolve the existing pinned object/SAT/LAT/bank chain once: 123 sources / 15,389,461 source bytes. Both owner poses exercise all gaits. Alternating accepted manual steps keep the actor within the corridor: walk/run each cross three wraps and deliver six occurrences at walk frames 7/23 and run frames 6/17. Every tick's event state equals the existing locomotion state. Blocked/pause/focus/reset/clear/disable, retained topology and texture counts/bytes, and teardown assertions pass. Existing door/input/camera routes and the default route regression also pass.

Prototype host/Core/shared native builds report zero warnings/errors; the existing native suite passes. Headless checks establish source loading, CPU/mesh publication and control assertions; they do not verify GPU pixels or label visibility. The existing certificate-store startup diagnostic remains in passing offline logs. Capture-only behavior waits for layout and scrolls the diagnostic label into view before rendered-frame waits; default framing/scroll is untouched. Worker GPU execution remains unrun, and lead must inspect a fresh capture.

Use the owned reproduction script (external historical reference) with prototype hostPath and the existing pinned SceneSpecification. Default mode is headless; DefaultRoute omits diagnostics for regression. For lead GPU inspection, explicitly select Gpu and use CapturePath with a fresh ignored PNG. The script preserves all original route pins and passes the existing CapturePath spelling.
