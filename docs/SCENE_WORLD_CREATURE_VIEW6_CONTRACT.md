# Optional CREO6 world publication

Round34, 2026-10-03. The [coordinator](../poc/Stardust.Core/Session/SceneWorldCoordinator.cs) optionally composes the accepted [supported CREO6 codec](CREATURE_VIEW6_CODEC_CONTRACT.md) and [full current model/store](SCENE_CREATURE_VIEW6_STORE_CONTRACT.md) with serialized world publication. No store or codec changes were required. Unsupported vector deltas and live/gameplay semantics remain excluded.

Types and ingress: [SceneWorldCreatureView6ApplicationRouter](../poc/Stardust.Core/Session/SceneWorldCreatureView6ApplicationRouter.cs). Verification: [native scenarios](../poc/Stardust.Core.SmokeTests/SceneWorldCreatureView6Scenarios.cs), [isolated runner](../poc/round34-tests/Runtime/Program.cs), [synthetic fixtures](../poc/round34-tests/Runtime/ordered-fixtures.json), [independent full-model peer](../poc/round34-tests/Runtime/peer.py).

## Frozen API

Both existing public constructors append `SceneWorldCreatureView6Policy? creatureView6Policy = null`, after the optional TANO6 policy. Both the generic object and creature-only constructors support CREO6. The record accepts `CreatureView6Limits CodecLimits`, `CreatureView6StateLimits StateLimits`, `SceneCreatureView6StoreLimits StoreLimits`, and optional `ulong RevisionSeed = 0`. Limits are validated and copied. Codec payload limits must fit the configured world payload limit: for a default 65536-byte world, explicitly choose `new CreatureView6Limits(MaximumPayloadBytes:65536)`. The codec's default 1 MiB limit requires a correspondingly configured world. There are no world-policy CREO6 decoder callbacks.

Public state API: `CreatureView6Enabled`, `RetainedCreatureView6Bytes`, `FindCreatureView6(long generation, ulong id)`, `IsCurrent(SceneWorldCreatureView6Snapshot)`, and `ApplyCreatureView6Delta(long generation, SceneWorldCreatureView6Snapshot expected, CreatureView6Delta plan)`. `SceneWorldObjectSnapshot.CreatureView6` propagates through snapshots and world change batches. The immutable wrapper exposes Generation, Incarnation, global store Revision, accepted State and Model; `wrapper.State.Model` is the complete current eighteen-field value.

Public journal API: `DrainCreatureView6Events(generation)`, `AcknowledgeCreatureView6Events(batch)` and `IsCurrentCreatureView6Event(batch, index)`. World batches expose Generation, StoreRevision and ordered immutable store records. Drain may return distinct wrappers for the same exact underlying issued store batch. Acknowledgment requires this world owner/generation and that exact current underlying batch; successful acknowledgment invalidates all wrappers once. It is journal ownership, not authorization to deliver.

The delivery guard checks owner, generation, current underlying batch, index bounds, registry incarnation and finalized recipient. Callers must use it immediately before eventual delivery and remain serialized. Historical events can belong to an acknowledged-current journal while referring to a removed/recreated recipient; delivery guard then returns false. No callback dispatch or weak target resolver is provided.

## Family, barriers and currentness

Only configured CreatureDetail0 recipients accept typed CREO6. A complete exact 18-field baseline is required before a creature's end-baselines barrier when the optional policy is enabled. Pending or finalized matching-family recipients may be seeded; deltas require a finalized recipient with a complete seed. Static objects do not require CREO6. The full supported union remains 0,2-12,16-17; defender/HAM/wearable delta indices 1,13-15 reject. Baseline vectors/counters are retained untouched by supported assignments.

Typed packets do not append opaque history. Default/opaque mode remains unchanged when the policy is absent. Existing CREO3, TANO3 and TANO6 policies remain independent. Their existing fields, names, customization and scalar/motion state are preserved. Native tests exercise both constructor forms and all four typed partitions together, including exact reference preservation of prior creature names/scalars after CREO6 updates.

Generation and exact stored publication identity bind world currentness. A stale generation or stale/foreign receipt returns false before plan access. Current receipt plus a mismatching plan ID throws. Manually supplied plans are already-owned decoded models; wire codec limits apply at ingress and kernel limits independently apply to every plan.

World currentness uses current incarnation and exact stored state, allowing registry handle revisions from end-baselines/containment to carry state forward. The store publication may retain its historical handle; the next update uses the latest exact registry handle plus the exact stored snapshot. Destroy/recreate invalidates old world tokens. A recreated seed starts state revision one while global store revision continues. Generation replacement retires mapped state and discards that world's historical journal; close clears owned state/resource work. The coordinator owns its private registry, the store borrows it, and router disposal never closes the borrowed world/downstream.

## Atomic preparation and accounting

The coordinator checks active finalized family/current receipt, checked world mutation revision and pending-world-journal capacity, then allocates the complete replacement world journal. It prepares the accepted store candidate under the store owner gate: full immutable current model, replacement map, old plus new journal, logical totals and checked revision/epoch. CheckPrepared revalidates exact active candidate ownership/current handle/incarnation. Only then does commit assign store fields and prebuilt world journal/revision. There is no parsing, decoder callback, allocation or checked arithmetic after the first assignment. Finally releases preparation. No consumed publication is followed by a rollback claim.

RetainedCreatureView6Bytes charges all mapped current model DecodedBytes plus 8 logical bytes per pending assignment event, matching the accepted33 store policy. Store limits apply globally across its creature actors, including other retained models and earlier events. Every intermediate model growth/output/work check precedes a later shrink. CREO3, TANO3, TANO6, opaque envelopes and resource-job budgets remain separate partitions; no total-world CLR heap cap is claimed. Kernel work excludes separately bounded map/journal copying. Caller-held old models/batches are outside store retention.

Rejected direct plans and active exact CREO6 baseline/delta attempts preserve current state, charges, world phase and earlier valid journal entries. Later malformed/unsupported exact deltas do not destroy an otherwise valid active generation. Router failure closes its own ingress references only. Wrong-family/noncandidate envelope failures and staged/barrier failures retain existing generation-fatal drain behavior. Overflow rejects before publication. External decoder/downstream mutations cannot roll back.

## Router purity and ownership

`SceneWorldCreatureView6ApplicationRouter(world, decoder = null, downstream = null, maximumPayloadBytes = 65536)` borrows an enabled world, owns callback references and a message copy, and recognizes exact CREO6 delta envelopes. Noncandidate baseline/lifecycle/control messages pass downstream; default downstream calls world.Accept. Exact supported grammar is checked before any custom decoder.

Callbacks run before preparation against the whole-world ingress stamp, now including CREO6 state revisions alongside prior typed partitions, registry identities, generation/phase, checked mutation/callback-attempt epochs and world journal membership. Event drain/ack attempts advance the callback-attempt epoch. Decoder results must match object ID/raw declared count; generation changes, world/journal mutations, caught router reentry/disposal or stale receipts reject the returned plan. Pure read-only inspection is allowed. All world/router/store operations require the creating managed thread. No callback runs during commit.
