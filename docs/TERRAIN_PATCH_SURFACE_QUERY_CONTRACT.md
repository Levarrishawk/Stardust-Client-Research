# Supplied terrain patch surface query

[TerrainPatchSurfaceQuery](../poc/Stardust.Core/Geometry/TerrainPatchSurfaceQuery.cs) chooses a projected triangle from the frozen [owned geometry](TERRAIN_PATCH_GEOMETRY_CONTRACT.md) and interpolates its supplied height and normal. It also consumes [assembled geometry](TERRAIN_PATCH_ASSEMBLY_CONTRACT.md) with its accepted seam topology unchanged. This is an explicit modern native-space policy: X is the supplied first coordinate, Y is height, Z is the supplied second coordinate. It establishes no original collision query, original world-axis mapping, procedural height generation, terrain sampling, or original arithmetic parity.

## API and lifetime

`new TerrainPatchSurfaceQuery(TerrainPatchGeometry geometry, TerrainPatchSurfaceQueryLimits? limits = null)` copies the nine positions, nine raw normals and active topology indices, and stores each triangle's projected signed double area. It retains no geometry, grid, caller array, engine object, callback, disposable resource or mutable global. The query is immutable and concurrently readable. CopyPositions, CopyNormals and CopyIndices return independent arrays. Mutating caller source or any inspection copy cannot change an old query.

`Query(double x, double z)` returns nullable `TerrainPatchSurfaceHit`: null means outside all eligible projected triangles. Nonfinite or over-cap locations throw rather than being classified outside. A hit contains PatternIndex, TriangleIndex (zero-based source order), VertexA/B/C (original local indices), WeightA/B/C, Height, and a double-valued normalized TerrainPatchSurfaceVector Normal. It does not contain a geometric face normal, collision material, object identity or physics contact.

`QueryBatch(ReadOnlySpan<TerrainPatchSurfaceLocation>)` checks count, copies locations, validates every copied location, then builds an immutable result list. Empty batches are valid. Late interpolation failure throws without returning any partial batch. Caller location buffers must not be mutated during their copy; subsequent mutation cannot alter published results. Scalar/batch operations have no mutable query state and failed calls preserve old results.

## Eligibility and bounds

TerrainPatchSurfaceQueryLimits defaults: MaximumCoordinateComponent 1,000,000; MinimumProjectedDoubleArea 1e-12; MinimumInterpolatedNormalLength 1e-6; MaximumQueriesPerBatch 4096; RequireCoherentWinding true. Coordinate and normal-length caps must be finite, positive, and at most 1e9. Area threshold must be finite, positive, and at most 1e18. Batch cap must be 1..65536. These are configurable modern policy, not recovered client rejection rules.

All supplied position components must fit the coordinate cap. Accepted geometry already validates finite eligible raw normals. Each active triangle must have absolute computed projected double area strictly greater than the threshold; collapsed and vertical-only projections reject construction. By default its 3D cross product must have a positive finite dot product with the double-summed supplied vertex normals. Both projected winding signs can be eligible. An explicit RequireCoherentWinding=false skips only that coherence check, preserving supplied normal direction; it does not permit projected degeneracy or imply original malformed-input acceptance.

Selected computed weights must be finite and individually within [0,1]. Height must be finite and within the coordinate cap. Interpolated normal length must be finite and strictly exceed its threshold; cancellation rejects the chosen hit without trying a later overlapping triangle. Published normal components must be finite. Normalization is in double with ordinary rounding, so unit length is approximate rather than a bit-exact invariant.

Storage and construction are fixed by nine vertices and at most eight triangles. LogicalOwnedBytes counts only copied array payload plus cached double areas: 216 + 2*activeIndexCount + 8*triangleCount, at most 328 bytes. Scalar bounds/metadata, policy, arrays/object headers, temporary inspection copies and caller-held results are excluded; this is not CLR heap measurement. A scalar query tests at most eight triangles and allocates no query arrays. Batch temporary location payload is 16*count logical bytes, plus a capped nullable-hit array/result wrapper; arithmetic work is at most eight triangle tests per point. No spatial index, dynamic mesh rebuild, owner thread or engine allocation is hidden here.

## Arithmetic, edge and overlap policy

Position/normal inputs are binary32 supplied values promoted to double. Query coordinates, determinants, weights, anchored affine interpolation and normal normalization use ordinary C# double operators in the written order and Math.Sqrt. There is no legacy x87 control-word/software precision policy, snapping or epsilon expansion. The [source](../poc/Stardust.Core/Geometry/TerrainPatchSurfaceQuery.cs) is the operation-order specification.

First compare X/Z against the exact supplied minimum/maximum bounds. For each source triangle A/B/C, compute the three oriented edge numerators at the query point and divide by its cached signed area. A candidate includes an edge when its computed numerator is zero; all three numerators must agree in sign with the area. Both winding signs use the same containment rule. Closed shared edges, shared vertices, duplicate coverage and overlapping projections choose the lowest triangle ordinal in the supplied index vector. Bounds and edge tests are in computed binary64, not exact predicates over arbitrary real coordinates; near internal edges, floating rounding can affect classification. No tolerance-dependent winner is claimed.

Height is `A.Y + wB*(B.Y-A.Y) + wC*(C.Y-A.Y)`. Raw normal components use the same anchored affine formula, then divide once by the computed Euclidean length. Per-vertex normals are not normalized first. This preserves constant supplied heights/normals and deliberately reports the interpolated supplied shading direction, which can differ from a nonplanar triangle's face direction. WeightA is the separately divided oriented numerator, so the three reported weights sum to approximately one under floating arithmetic.

## Godot boundary

Locations must use the same native coordinate space as the owned geometry. The accepted TerrainPatchVisual adapter reflects Z while preserving source index order, converting native CCW to Godot CW, and normalizes normals at its engine boundary. For that reflection alone, a Godot-local `(x,z)` location maps to query `(x,-z)`; returned height is unchanged and returned normal maps to `(nx,ny,-nz)`. Further parent/world transforms require explicit caller conversion and are outside this API. The query normal does not claim GPU lighting parity: the existing adapter normalizes each uploaded vertex normal, while this query weights the raw supplied normals before its single normalization. Do not treat reflected engine triangles as native input with the native coherence rule unchanged. No Godot adapter or movement/world code changes in this round.

## Evidence and verification

Observation: [native scenarios](../poc/Stardust.Core.SmokeTests/TerrainPatchSurfaceQueryScenarios.cs) and the actual [separate-assembly runner](../poc/round37-tests/Runtime/Runtime.csproj) pass 10,131 checks including 44 rejection checks over 270 records. All nine patterns are tested against flat, sloped, nonplanar, reversed and translated/scaled surfaces; overlapping coverage tests source-order priority. Seam cases cover all sixteen masks at every cell in counts 1..3, including coinciding boundaries at count one. Confidence: Confirmed for these supplied modern fixtures.

The [independent oracle](../poc/round37-tests/Runtime/peer.py) uses literal topology, exact Fraction containment/barycentrics/height and independently normalized double reference normals. It regenerates fixture bytes, independently selects assembly seams, and compares source triangle/vertices, weights, heights, normals, fixed charges and cardinality: 46 geometry cases, 224 seam assemblies, 4,678 hits and 4,364 outside points. Numeric comparisons use relative/absolute 2e-13 tolerance; identity/outside/triangle selection are exact in this corpus. The result does not prove exact-real classification for every ill-conditioned supplied triangle.

Negative cases include nonfinite/over-cap source and locations, zero/vertical projection, incoherent winding, exact/lower caps, empty/excess/late-invalid batches, interpolated normal cancellation/threshold, aliases, old-result retention and cross-thread reads. Representable neighbors of outer edges verify strict bounding rejection. Core and separate runner build with zero warnings/errors.
