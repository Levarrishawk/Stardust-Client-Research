# Paired supplied current-speed snapshots

`SceneWorldSuppliedCurrentSpeedInputs` is an owner-thread adapter over an existing borrowed `SceneWorldCreatureMovementCurrentInputs`. Construct it with that reader, mandatory `CreatureSuppliedCurrentSpeedPolicy.SuppliedLocalOnly`, explicit nearest-even24/53/64 precision and optional `SceneWorldSuppliedCurrentSpeedLimits`. The adapter neither creates a world nor owns/disposes the borrowed reader. The caller must construct/use it on that reader's owner thread and keep the reader alive.

## Actual source and arithmetic receipts

`Read(requestedGeneration, cancellationToken)` calls the [frozen current-input reader](SCENE_WORLD_CREATURE_MOVEMENT_CURRENT_INPUT_CONTRACT.md). It requires its actual finalized operational receipt, including current typed state. From that exact view it retains the actual fields7 (run base),11 (walk base),4 (first modifier snapshot) and5 (second local modifier). All four must have `FiniteCurrent` eligibility and present raw bits before either arithmetic call. Unknown or nonfinite supplied values never fall back to constructor, authored, zero or other fields.

Both frozen [supplied reader](CREATURE_SUPPLIED_CURRENT_SPEED_READER_CONTRACT.md) reservations are checked before either evaluation. Run and walk independently call `CreatureSuppliedCurrentSpeedReader.Evaluate` with their respective base and the actual supplied modifier words. The result retains both actual immutable reader receipts, not reconstructed projections. Each invocation retains two products and returns its actual caller F32 word. Per pair the counts are two reader calls, six supplied argument-word uses, four multiplications and two caller stores. There are four distinct validated current fields; the common modifier argument uses are deliberately counted separately for each reader.

`SceneWorldSuppliedCurrentSpeedReceipt` owns an immutable identity-bearing header and retains `View`, `RunBase`, `WalkBase`, `FirstModifier`, `SecondModifier`, `Run` and `Walk`. `Generation`, `Incarnation`, `RootSha256`, precision, named policy and finite supplied provenance are derived from those actual receipts. The actual authored root remains available through `View.AuthoredRoot`. Source fields and returned reader results are get-only immutable objects/values. The adapter stores no last result, so it can release all borrowed references without erasing caller-owned historical receipts.

Observation: the implementation directly obtains the accepted current view and its field objects, invokes the two frozen supplied readers and rechecks the view before publication. Interpretation: the pair is a consistent historical snapshot under the explicit local-only context. Confidence: Confirmed by inspected calls and deterministic identity/provenance/arithmetic/lifecycle fixtures. Consequence: a host may consume actual `Run.ReturnBits` and `Walk.ReturnBits` together while checking pair freshness; it must not infer original branch predicates, getter recursion, global/vehicle substitutions, units, original control state or full locomotion parity.

## Currency and failure policy

`IsCurrent(receipt)` first requires this adapter's issuing identity, then delegates actual view currency to the borrowed reader. Receipt data remain historical after invalidation. A foreign adapter receipt returns false, even when both adapters borrow the same reader. Adapter disposal is idempotent on the owner thread, clears its borrowed reference and makes freshness false; Read afterward throws. It never disposes the borrowed reader. Borrowed-reader disposal makes pair freshness false; Read then propagates the borrowed reader's disposal exception.

Missing/stale generation, absent/replaced incarnation, closed/reset world, pending phase or missing current typed state returns null. These are unavailable operational contexts, not guessed finite inputs. A current operational view with unknown/nonfinite fields, insufficient per-reader work, or final arithmetic overflow throws without publishing a pair. Invalid policy, precision or configuration throws at construction. Owner-thread misuse and reentry throw; every entered operation clears its own busy guard in finally. Pre-cancellation throws before the borrowed Read; cancellation is also checked after it, through the frozen producers and before publication. Timed mid-arithmetic cancellation and mid-read source mutation are inspection-only; no test callback was added.

The exact current view is rechecked after both evaluations and before paired publication. Registry object/phase changes, typed-source changes, received revision changes, late first received publication (including listen-only), destroy/recreate and generation/reset/close stale the pair as the frozen reader dictates. A motion-only `SceneWorldObjectMotionStore` publication does not replace the frozen current inputs and therefore preserves pair freshness; this adapter does not add a broader motion currency rule.

## Fixed preflight and accounting

Fixed reservations are checked at construction and before every borrowed Read or output candidate: output2,080 units = existing view1,632 + two reader values at128 + paired header192; copy256 units; work16,384 units (two frozen hard work bounds); exactly two readers. Output option range is0..65,536; copy/work/reader-count ranges are0..256/0..16,384/0..2. Each must permit the full fixed charge. Individual reader copy/work ranges are0..128 and0..8,192. Reader copy must permit128 at construction; individual work is checked against the actual words at Read, before either evaluation.

These are conservative logical accounting units, not CLR heap measurements, instruction counts or original limits. Full paired work is reserved even when actual work is lower or a view is unavailable. The two actual reader work/copy reservations are preserved in the results, and `ActualWork` is their work sum. Fixed reservation occurs before any borrowed source access. The adapter has no driver, getter, engine, I/O or user callback and never writes received/world state.

Six exact/six one-below cap pairs pass. The207 accepted pairs retain414 actual reader receipts,828 multiplications and414 caller stores.
