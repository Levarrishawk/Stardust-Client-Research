# Caller-driven replacement application run

Round88 assembles the existing [session](REPLACEMENT_CLIENT_SESSION_CONTRACT.md), [pinned datagram pump](REPLACEMENT_DATAGRAM_PUMP_CONTRACT.md), [selected ingress](REPLACEMENT_SELECTED_PLAYER_INGRESS_CONTRACT.md), [scene barrier bridge](REPLACEMENT_SCENE_BRIDGE_CONTRACT.md), [movement seam](REPLACEMENT_PLAYER_MOTION_SESSION_CONTRACT.md) and [disconnect](REPLACEMENT_CLIENT_DISCONNECT_CONTRACT.md). It adds orchestration, not a codec, socket, engine resource loader, movement calculation or credential/character-selection policy.

## API and admission

`ReplacementClientRun(session, pump, world, motions, minimumResources, rootPolicy, zeroPolicy)` borrows those four owners and owns ingress, motion and bridge adapters. Before acquiring them, it checks exact session/pump binding with an internal owner-checked pump helper, exact open motion-store/world binding, session Offline and world Idle. Invalid construction preserves borrowed owners. Existing owner affinity is enforced by pump/world/store admission and subsequent session operations. Minimum callback and policies are explicit caller inputs; original timing/cadence assumptions are not introduced.

StartLogin, Authenticate and SelectCharacter forward caller choices to the actual pump. Credentials are never retained by the run. SelectCharacter admits the explicit zone port/peer using existing session/pump policy, then binds the bridge once. Caller owns an unadmitted port; the pump owns an admitted port. Duplicate selection rejects before acquiring a second port. Generation and SelectedObjectId are historical run values, including after session disconnect clears its live selection.

All mutating methods require the creating thread and no reentry. Clock arguments must be nonnegative and monotonic; equal clocks remain legal. Getters and ToString are owner-thread observations and remain readable after Dispose. ToString includes ready/failure state without raw messages, credentials or identifiers. Constructor rejects a foreign/disposed pump, foreign/disposed store and nonfresh session/world. Caught callback reentry cannot advance the run.

## Tick and transfer

`ReplacementClientRunTick(IReadOnlyList<byte[]> UnhandledApplications, string? FailureType = null)` returns only owned application remainder and a failure type. It returns no wire datagrams. Tick before StartLogin does no protocol work. Normal Tick calls the actual pump, routes its exchanges through the bound bridge and, when Selected, submits the bridge's Poll output immediately to the pump. Existing pump/bridge both poll the session at the same caller time; this is reused behavior, not a new retry scheduler. A barrier-generated ready queued after pump Tick becomes eligible for the next Tick. No automatic minimum-success or server-ready transition is inferred.

Before bound selection, applications reject. After selection, generation and session identity must remain current. Existing ingress owns selected lifecycle acceptance and unsupported/nearby deferral; motion owns correction decode/status; world owns typed state and barrier publication. Unknown copies transfer to the caller on successful return and survive later run disposal or failure. Source applications always clear. If a later routing/provider failure prevents successful Tick, all still-owned remainder copies and unprocessed exchange application suffixes clear and no remainder transfers from that failed Tick. Already transferred copies from earlier Ticks stay caller-owned. Decoder/body/private zeroing details remain the existing component contracts.

TryQueueLocal delegates exact current selected LOCAL row admission and encoding to the existing motion seam, immediately submits owned datagrams to the pump, and returns true on transfer. Existing whole-zone pending-message backpressure returns false before pose construction and creates no deferred run queue. Flags, counter, timestamp bits and caller time remain explicit. Wire/native axis conversions and counter ordering are not duplicated.

## Disconnect, failure and disposal

BeginDisconnect uses the accepted87 pump and then disposes the owned bridge to cancel/observe minimum work. During disconnect, Tick calls only the pump's disconnect branch until send completion/failure; it never invokes bridge Poll or application routing. Historical ready/correction counters remain available. A duplicate request or invalid pump preflight rejects while preserving the in-progress prefix. Preparation failure already faulting the pump/session is recorded and retires the failed run. Send-completion flags retain the actual pump observation; no server receipt/release is implied.

DrainCompletion observes current bridge, pump and world drains plus recorded cleanup errors. It is not an outcome signal by itself: pump drain can already be complete while a send is pending. After actual final send outcome, Tick observes a completed faulted aggregate and reports failure instead of treating completion as success. Asynchronous I/O re-observation and a new disposal failure after successful send remain distinct accepted87 outcomes. A later completed faulted drain requires another owner-thread Tick or an explicit await to observe it; no background continuation mutates run/session/world.

Runtime routing/provider/delegated-operation failure records the original failure type, releases owned adapters, retires the borrowed pump, closes session if not already Closed, and closes world. Cleanup failures are retained as redacted faulted tasks without replacing the first runtime failure. This is an explicit failed-flow policy. Clock/thread guards, duplicate selection and admission preflight errors reject before that failure policy where documented.

Normal Dispose releases only owned adapters and cancels the minimum task; session, pump, world and motion store remain caller-owned and active. A cancellation callback can throw: owned cleanup still attempts every adapter, Dispose reports the exception, and the run's failure/drain observations retain that cleanup failure without closing borrowed owners. Caller must stop presentation, explicitly close world/pump/session as appropriate and await current drains before disposing the borrowed motion source. Dispose is idempotent. It is an abort of owned orchestration, not automatic protocol disconnect or server release.

## Evidence and reproduction

Synthetic metadata uses the independent normalized path checksum required by the real template catalog.

Tests exercise asynchronous minimum success/failure/cancellation, disconnect before readiness, unknown-before-malformed failure suffix, stale generation, queue backpressure, foreign/disposed/nonfresh owners, invalid port ownership, thread/clock/duplicate/reentry guards, caller-copy lifetime, borrowed normal cleanup, throwing cancellation callback and both asynchronous send and post-send cleanup drain faults. No original resource factory runs; no socket/DNS/server or executable execution occurs. Confidence is Confirmed for exercised modern orchestration and authored fixtures; original gameplay timing, general avatar/zone readiness, server release and live interoperability remain Unknown.
