# Supplied terrain point targeting

SceneWorldTerrainPointTargetDriver (external historical reference) implements bounded modern straight-line planar targeting using an actual [retained ray query](TERRAIN_MODERN_PATCH_SET_RAY_QUERY_CONTRACT.md) and an owned actual [terrain motion driver](SCENE_WORLD_TERRAIN_MOTION_CONTRACT.md). It borrows a fixed exact world, motion store and ray query/surface. It does not build terrain, resolve markers, teleport, pathfind, avoid obstacles or establish original movement units/gameplay/collision/physics parity.

## API and construction

Construct `new SceneWorldTerrainPointTargetDriver(world, motions, objectId, rayQuery, speed, arrivalRadius, initialTimestampMicroseconds, stepMicroseconds, footOffset = 0, maximumUpdates = 128, maximumTargets = 16, terrainLimits = null, cancellationToken = default)` on the world/store owner thread. Speed is finite, strictly positive and at most10. Radius is a supplied binary32 value in1e-4..1. Step is1,000..100,000 microseconds. Updates are1..128 and successful targets1..16. The complete configured end clock must fit signed64 bits before driver construction; initial clock is nonnegative.

Exact open world/store binding, active finalized typed current incarnation, generation and existing motion speed0..10 are checked before constructing the owned driver. The actual frozen driver validates terrain options, incoming pose and initial grounding before its initial publication. Cancellation is checked before construction and after the driver returns. Initial publication can survive a later cancellation/allocation/inspection failure; returned owned driver cleanup does not undo that row. An unreturned partially constructed driver cannot be explicitly disposed. Store reads may prune obsolete rows according to the frozen store contract; no new local publication is performed to prove binding.

`Driver`, `Query`, `Target` and `State` expose actual references/state with owner/reentry guards. `SubmitTarget(hit, exactCurrentClock, token)` returns an immutable receipt containing the actual supplied hit, the controller's actual query, admitted float X/Z, clock and successful target revision. `AdvanceNext(submitClock, advanceClock, token)` returns wrapper diagnostics containing the actual driver result. `IsCurrent(receipt)` checks exact target receipt ownership and current world/incarnation, not controller health or whether a historical motion row is latest. Callers must use this controller as the serialized sole local writer and must not independently advance/reset/dispose its exposed owned driver.

## Hit admission and provenance boundary

Target submission requires the exact retained surface Source and exact Membership reference present in the controller's query.Source.Children. It checks bounded finite native hit position, actual geometry pattern/triangle/vertex indices, finite nonnegative T, finite barycentric weights in0..1 with sum tolerance1e-12, and reconstructed triangle position within absolute1e-9 plus relative1e-12. Bounded X/Z cast once to float; actual surface Query at those cast coordinates must be eligible and its height plus supplied foot offset must remain finite within the driver's position cap. Only then does target revision/ownership change. Clock/token/target-cap checks precede copies and queries. Source geometry exports are bounded copied arrays; no geometry or query is rebuilt.

**Frozen identity limitation:** the public frozen ray-hit record stores exact surface/member identities but no producing ray-query instance or unforgeable hit ownership. Two queries over the same exact source produce indistinguishable hit provenance; record copying is also public. This controller proves source/member/topology/position eligibility and records its exact query identity, but cannot prove the supplied hit was originally emitted by that particular query. Callers must supply the actual result from that query. This issue was reported to the lead; no unauthorized frozen API amendment or fictitious emitter identity is introduced. Foreign surface/member hits and inconsistent copied hit metadata are rejected. Original emitter provenance remains unproved.

## Consecutive movement and numerical policy

Each update admits exact submit=current result clock and advance=submit+step, cancellation, update budget and world/store/incarnation currentness before submitting new movement. It reads the actual current selected motion row. A newer authoritative revision differing from the exact last local publication supplies steering pose, matching the frozen driver's correction-adoption rule. Finite bounded corrected position/speed is validated before Submit. The actual driver then adopts that same correction during its one consecutive Advance, before Tick; there is no zero-time extra Advance. A correction off the original movement line therefore changes direction immediately. Another local writer's row is ignored by the frozen driver and is unsupported; the controller does not silently adopt it or arbitrate writers.

Direction uses double X/Z differences and Euclidean distance from that actual owned/prospective-authoritative pose to the admitted float target. If distance is within radius, velocity is exactly zero. Otherwise, with binary32 step seconds, choose double travel `min(speed * seconds, distance - radius / 2) * (1 - 2^-20)`, divide the normalized double direction by seconds, and cast X/Z velocity once to float. This explicit conservative policy leaves rounding margin and approaches within the radius without teleporting.

Before Submit, evaluate the actual binary32 candidate position and its displacement projected onto the current target difference. Require projection in0..distance-squared. If it rounds beyond the target plane, halve the float velocity up to eight times; otherwise use zero. This bounds work and prevents a rounded candidate from crossing the target plane. Large-coordinate float granularity may stall progress; arrival is not guaranteed in all admitted geometry. Update exhaustion rejects before further driver calls. Grounding, float displacement/yaw/speed and publication use the actual frozen driver with no alternate height calculation in production.

Every successful call performs one Submit and one real consecutive Advance with one fixed tick, no dropped/suspended time. Healthy result increments CompletedUpdates and recomputes Moving/Arrived from actual grounded pose. **Entering Arrived does not retroactively zero the final approach speed.** The next consecutive update submits zero and publishes zero stored speed; the host must perform that stop update before disposing if it needs stopped borrowed motion. The target remains retained and zero is submitted thereafter. A later authoritative correction outside the radius resumes steering toward it; retargeting explicitly replaces receipt currency.

## Failure and lifetime

AttemptedUpdates increments immediately before first driver operation and is bounded even if that attempt later fails. Invalid clocks, pre-cancellation, caps, hit admission and invalid authoritative pose reject before new Submit/publication. Stale world/store/generation/incarnation returns Unavailable before operations. Errors or cancellation after an attempted Submit latch terminal Faulted; there is no retry/reset or rollback. A late hole/outside grounding failure preserves exact prior successful pose/publication, reports the actual faulted driver clock/state, and leaves CompletedUpdates at its successful prefix. External authoritative rows are never reversed.

`Retire`/`Dispose` dispose only the owned driver, release borrowed references and current target, and are idempotent. Borrowed world/store/query/surface and caller-held receipts survive. Disposed wrapper diagnostics retain the historical driver result while Mode is Disposed; they do not claim it is the driver's latest disposal state. Immutable queries have no independent selection-retirement signal: the host explicitly retires the controller when replacing that selection. Reentry guards and post-effect cancellation cleanup are source-inspected because production dependencies provide no callback hook.
