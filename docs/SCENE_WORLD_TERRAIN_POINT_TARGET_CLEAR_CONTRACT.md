# Point-target clear intent

The [point controller](../../SWG-Godot-Client/poc/Stardust.Core/Session/SceneWorldTerrainPointTargetDriver.cs) adds `public void ClearTarget(long exactCurrentClock, CancellationToken token = default)` to its accepted [point-target](SCENE_WORLD_TERRAIN_POINT_TARGET_CONTRACT.md) and [active-pause](SCENE_WORLD_TERRAIN_POINT_TARGET_ACTIVITY_CONTRACT.md) APIs. The only existing-source change is this new method; default targeting, pause/admission, driver ownership and numerical behavior remain unchanged.

Clear requires owner thread/non-reentry, an open healthy current world/store/incarnation, exact cached driver-result clock, pre-cancellation and remaining update capacity. It does not require remaining target capacity: clearing an admitted target is permitted even at the successful-target cap. Tokens and inherited operation-local reentry poison are checked before intent publication. A fresh/no-target clear is idempotent after the same live/current clock admission. Invalid clock, negative clock, token, stale/faulted/Unavailable/disposed state, closed store and exhausted updates reject without intent/motion mutation.

The method releases the owned target/receipt reference and updates owned Mode to Idle or Paused. It preserves IsPaused, SuccessfulTargets, attempted/completed update counts, actual driver result/clock, last motion publication, query/world/store references and the owned actual driver. It performs no geometry query, driver call, input submission, clock advance, motion publication, teleport or external cleanup. An old caller-held receipt remains a historical object but becomes non-current through the existing exact-reference currency check. Clearing does not refund target budget; later submission uses the next successful revision and the same remaining cap.

Clear intent alone does not stop the last published speed. The next ordinary consecutive active tick submits zero, adopts an eligible current authoritative correction, grounds the actual pose and publishes zero stored speed. Unpaused/no-target stays Idle; paused/no-target stays Paused and still consumes normal clocks/update budget. Resume with no target stays Idle. A later target steers normally from actual pose. Clearing Arrived preserves its potentially nonzero final approach speed until that next zero tick, just as the accepted arrival policy requires.

Setter admission failures have no new publication prefix. Allocation of the cleared state is prepared before committing target/state references; cancellation is rechecked before commit. The method cannot undo prior external authoritative publication or inherited constructor/tick effects. A faulted or stale controller is not recovered by clear. Dispose still owns only the actual driver and releases borrowed references according to the accepted lifecycle. Sole local writer, immutable selection retirement, unproved historical ray-emitter provenance, and Unknown original gameplay/units/collision/physics parity remain unchanged.
