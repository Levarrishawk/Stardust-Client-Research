## Preparation and lifecycle

Raw typed baselines/deltas resolve the current registry object and require creature family/recipe agreement. Baselines seed the complete store; deltas require finalized seeded targets. World change capacity and next mutation revision are reserved before store preparation. The accepted store PrepareSeed/PrepareApply builds the complete candidate, variable historical journal and exact snapshot. CheckPrepared precedes callback-free store/world assignments; ReleasePrepared runs in finally. Failed aggregate capacity, malformed input or stale preparation exposes no scalar/collection prefix. Typed decode failure in an active scene retains prior presentation/resources/state; other lifecycle failure keeps existing generation failure semantics.

Full4 state is included in ingress snapshot revision comparisons. Close closes its owned store; generation reset retires old incarnations and drains its journal. Destroy/lifecycle replay retires stale state while retaining historical journal records. Event batches bind world owner/generation and store revision/epoch. Delivery requires the exact current batch, current incarnation and finalized registry phase; old-incarnation historical records remain inspectable but not deliverable. Exact acknowledgement clears the journal and invalidates the batch. A later write/reseed supersedes batch identity without discarding historical pending records.

RetainedCreatureView4FullBytes sums store RetainedStateBytes and PendingEventBytes. It never multiplies event count by a fixed48: scalar/vector summaries48, skill64+key bytes, mission64. Global store output includes all other actors and existing historical journal before the full kernel's intermediate and mapped/child summary peaks. World snapshots/change delivery remain separate from journal acknowledgement. No original owner/subscriber callbacks or gameplay effects are introduced.

## Router and callbacks

Router constructor mirrors accepted full6 naming: world, optional Func<ReplicationEnvelope,CreatureView4FullDelta> decoder, optional downstream and maximumPayloadBytes=65536. Accept owns/clears message bytes and recognizes exact CREO/view4 delta framing. It validates native grammar before decoder callback, captures world generation/state/mutation/callback stamps and snapshots, then rejects callback changes to world/journal, swallowed router reentry, close, recipient/declared metadata mismatch or stale exact target before preparing its own candidate. Callback-produced plans are remeasured under world/store policy. Noncandidate messages delegate downstream. Stale generation returns false; failures close the router. World/downstream are borrowed, router owns only its ingress lifetime.
