# Current speed-plan playback

`SceneWorldCurrentSpeedPlanPlayback` is a bounded owner-thread consumer of an actual [current paired-speed plan](SCENE_WORLD_SUPPLIED_CURRENT_SPEED_PLAN_CONTRACT.md) and borrowed `ISceneWorldLocalMotionDriver`. Construction requires the issuing composition, its actual receipt, driver, named `SuppliedLocalOnlyStoredSpeedOnWorldZ` policy, nonnegative initial timestamp and explicit step interval1,000..100,000 microseconds. The host integration uses10,000. It never constructs a driver, reloads a reader, copies a plan, recomputes targets/transitions or writes world/source state directly.

## One stored step and one explicit driver quantum

`AdvanceNext(submitTime, advanceTime, token)` consumes the next actual retained `CreatureNominalSpeedPlanReceipt`. Submit time must equal the playback's last successful clock; advance time must equal that clock plus exactly one configured interval, without signed64 overflow. Planning seconds are not reinterpreted as playback time. The driver must already be configured/aligned to that interval/clock and have no other consumer; this is a caller binding contract.

Input is a modern world-axis velocity `(0,0,storedSpeed)`, where storedSpeed is the exact F32 word from `Step.Transition.StoredBits`. The signed value is preserved; negative speed moves along negative Z. No absolute-value velocity substitution or target/transition recomputation occurs. The existing local driver requires finite axis components bounded to±10, so stored words outside that range reject before even reading driver State. This is a modern planar policy, not original movement or physical unit evidence.

Before any driver operation, playback checks source currency, completion/count, exact timestamps, stored-speed eligibility, token and remaining operation budget. It then reads actual driver State, requiring matching objectId, timestamp==submit time, active/no fault, finite bounded speed and finite transform rows/translation. It checks token and source again after this external getter and before Submit. A matching objectId does **not** prove same-world or same-incarnation ownership for an arbitrary interface implementation; the caller must bind the actual driver correctly. The interface exposes no stronger identity proof.

After Submit it rechecks cancellation and source before Advance. Advance is explicitly active and must return one healthy step: matching objectId and timestamp, exactly one completed tick, active/no fault, no dropped/suspended time, finite bounded speed and finite transform. The actual returned state object is retained by identity. Source and token are checked again before publishing a successful playback receipt or incrementing the next index. Only successful one-step results consume an index.

Each successful `SceneWorldCurrentSpeedPlaybackReceipt` retains the exact `Source`, actual `Step`, index, raw stored word, explicit timestamps, named policy and actual `DriverResult`. It contains no reconstructed driver result. Driver Speed may be float vector Length, including square underflow for tiny input; universal exact equality to the absolute stored speed is not required. `IsCurrent` checks the issuing playback identity and current source receipt, not whether a historical driver result is the newest motion publication.

Observation: the implementation consumes actual frozen step/result identities and uses the existing driver interface only after preflight. Interpretation: engine-host input submission and one-step consumption now have a reusable compatibility-side gate. Confidence: Confirmed source and deterministic native/fake/oracle tests. Consequence: a host can use the actual `DriverResult`, while effective original movement, gameplay/getter recursion/global substitutions, units, controls, lifetime and full locomotion parity remain Unknown.

## State machine and fault semantics

States are Ready, Complete, Unavailable, Faulted and Disposed. Empty plans start Complete; repeated advancement after completion returns null without driver calls. Source currency is still checked before the complete branch, so a stale/foreign source becomes Unavailable. Ready preflight errors or pre-cancellation throw without Submit/Advance or index consumption. Stale/foreign/disposed composition returns Unavailable before any driver call. State properties enforce owner thread/reentry and do not call the driver.

State-read exceptions or ineligible binding/clock become terminal Unavailable, with a separate `UnavailableReason`, without a Submit attempt. External getters may contain arbitrary implementation effects; the guarantee is the absence of playback Submit/Advance, not rollback of getter behavior. Source changes inside State are caught by the subsequent currency check. A caller must not treat a bare interface getter as a same-world proof.

Once Submit is attempted, errors, unhealthy outcomes or source changes latch terminal Faulted. Driver exceptions return null with FaultType. Cancellation after that attempt also latches, then propagates OperationCanceledException. No retry, implicit reset, driver disposal or index replay follows. Submitted/advanced work may already have occurred: the adapter does not undo queues, motion or partial driver work. `SubmitAttempts`/`AdvanceAttempts` count attempted calls, not proven effects. `LastAttemptedDriverResult` records an actual returned state for the latest motion attempt, or null when none returned. `LastSuccessful` remains the exact prior successful receipt after later faults; the next index remains its success prefix.

Complete/Unavailable/Faulted subsequent calls make no further driver calls (pre-cancellation still throws). A new instance is an explicit caller action, not an internal recovery mechanism; serialized one-writer ownership and avoidance of deliberate plan replay remain caller responsibilities.

## Bounds and borrowed lifetime

Hard plan count is128. Limits allow maximum steps0..128, driver operations0..384 and output0..65,536. The source plan count must fit, operation capacity must permit three operations per source step (State/Submit/Advance), and fixed logical output must permit512 units before borrowing. Before each attempted quantum, at least three operation units must remain. All State reads, including a getter failure, count toward the operation budget. Invalid timestamp/speed/source/pre-cancel gates consume no driver operation units. Charges are modern logical policy, not CLR allocation measurements or original limits.

The playback does not own the composition, its paired reader/world, motion source or driver. Dispose is idempotent on the owner thread, clears borrowed references and internal success/attempt references, and marks Disposed. It never invokes driver Reset/Dispose or source disposal. Caller-held immutable historical receipts remain usable; playback IsCurrent returns false after disposal. Host-owned final inactive/stop submission after all planned steps remains outside this adapter.

There is no public callback parameter or production reflection. Owner affinity and reentry guard every operation. Controlled test interface implementations can invoke reentry/source mutations through their own getters/methods; those tests do not add a product callback API.
