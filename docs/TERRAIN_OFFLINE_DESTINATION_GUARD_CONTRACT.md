# Modern offline destination hold

The [actual point driver](../poc/Stardust.Core/Session/SceneWorldTerrainPointTargetDriver.cs) appends `bool holdMissingTerrainDestination = false` after the existing optional `TerrainOfflineSessionBudget? budget`. Existing calls preserve their strict missing-terrain fault behavior and perform no additional surface query. This opt-in policy is modern offline behavior; it establishes no original collision, physics, movement, input or terrain parity.

When enabled, construction retains the exact `rayQuery.Source` surface query, checks its complete patch/triangle counts against the frozen terrain driver's per-candidate caps and reserves one query before initial driver publication. It builds no new surface, geometry or normals. Frozen driver admission still validates terrain options, foot offset, incoming position and initial grounding before publication. The constructor's existing post-publication cancellation/cleanup limitations remain unchanged.

Each admitted `AdvanceNext` computes steering/manual velocity through the existing rules, then computes `poseBefore + velocity * (stepMicroseconds / 1_000_000f)` using binary32 vector multiplication and addition. Proposed XYZ must remain finite and within the configured frozen position cap. One bounded actual retained-surface query tests that candidate XZ. A missing destination replaces the velocity with zero; a present destination preserves it. Query rejection, cancellation, wrong clocks or position caps reject before attempt/input/row/receipt mutation. This is destination sampling: it does not test the segment, slide along edges, avoid obstacles or find paths. A sufficiently large step may cross a narrow gap if its destination has ground.

The ordinary frozen driver still receives Submit and performs exactly one step, grounding and publishing through its actual surface. A hold consumes an attempted/completed update and advances the actual clock. Manual mode retains its raw direction and may report zero speed at an edge; reverse input can resume on a later ordinary tick. Point mode retains the target and may remain Moving with zero speed across a gap until retargeted. Pause still submits zero and retains intent; clear and the [session controller](TERRAIN_OFFLINE_SESSION_CONTROLLER_CONTRACT.md) final zero tick keep their existing semantics. There is no extra tick, budget refund or invented completion.

A newly eligible authoritative correction receives a separate bounded current-position surface query before steering. If its current XZ has no ground, `InvalidDataException` rejects before Submit, leaving the authoritative motion row untouched. This check prevents a next destination inside coverage from masking an invalid current ground position. It does not roll back or silently replace authoritative data. Valid current ground still lets the frozen driver adopt and ground the correction in its next actual step. Thus correction ticks can make two guard queries; ordinary ticks make one, in addition to frozen grounding.

Owner-guarded `LastDestinationReceipt` starts null and remains null for the default policy. An opt-in attempted tick retains an immutable [TerrainOfflineDestinationReceipt](../poc/Stardust.Core/Session/TerrainOfflineDestinationReceipt.cs) with `Vector3 ProposedPosition`, `Vector3 AcceptedVelocity` and `bool HeldAtMissingDestination`. The proposed Y is the incoming pose's Y before actual grounding; it can be an authoritative correction's admitted Y. The receipt records the decision before Submit, not proof of a successful publication. A subsequent frozen fault/cancellation preserves its honest attempted prefix and receipt. It contains value fields only, with no world/query/geometry references. Dispose releases the added retained surface reference, preserves the historical receipt, and retains inherited borrowed-world/store/query ownership. Setter changes do not rewrite historical decisions.
